## 作者寄语

我曾经是个爱玩的孩子。儿时和小伙伴围在一起玩经典地产类桌游：大家去买地、收租金，最后按照资产的高低分出输赢，简单又热闹。从那以后，便一直念念不忘。

后来在亚马逊云科技的生态里，我也玩过不少有趣的作品，比如 BuildCards，但玩过之后总觉得少了点什么：作为专业的云从业者，我们需要更有深度的玩法，也需要更好、更复杂的规则。

二十年后的某个夜晚，我忽然有了这样的灵感：参考一部分经典地产类桌游的规则，再做一些延伸，把自己对亚马逊云科技的了解和架构知识，通过游戏的方式传播出去，让大家在玩的同时，轻松学到云架构知识；而且要本土化，做一款我们自己的游戏。于是便有了「云上大亨」。

云上大亨借鉴了经典地产类桌游的那份轻松；我又用自己所学的知识和积累，加进了云服务、架构、账单和故障这些真实的元素，做了很多技术方面的升级和创新，让它不只是一个游戏，更是一个能在玩中学的地方。在游戏里，你可以尽快熟悉、学习云服务的能力边界和典型用法，也可以把服务组成亚马逊云科技的架构，联合收取租金；如果想和 BuildCards 联动，还可以用 BuildCards 的卡片，把手上服务组成的架构摆出来。

也许在每一次和小伙伴的交锋中，在缅怀童年玩乐的同时，我们就不知不觉掌握了使用亚马逊云科技的能力。

一路走来，要感谢 UG 的各位小伙伴帮忙测试、做美工设计和修 bug：很多个夜晚，虫虫在线陪我一起测试游戏功能，找出里面的 bug、提需求，还承担了一部分美工；辣条提交了一大堆修复代码的 PR；Damo 架设了国内的服务器，降低了访问延迟；还有 Yuki，在开发前期就提出了很多优化建议。没有你们的帮助，这款游戏不可能这么快地上线和大家见面。

希望 User Group 能帮助更多的小伙伴快速上手亚马逊云科技，也希望你在这里，能找回小时候和小伙伴围在一起掷骰子的那份快乐。我的水平有限，难免有不周之处，还请多多包涵。

—— User Group 云上大亨小组


## 简介

在亚马逊云科技上创业的地产类桌游：买服务、做高可用、扛住 Health 事件、控制账单、把服务组成有效架构。每个服务都按它的真实特性计费和升级，比如实例要自己做多 AZ，Serverless 没人用就不花钱，Bedrock 按 token 收费。玩法灵感来自经典的地产类桌游。

- 2–4 人，约 20 分钟一局（默认打满 15 轮按估值排名）；不设轮数上限时最多 50 轮（学习模式不限），电脑对打模拟里 4 人局不限轮数时中位约 32 轮分出胜负（完整局约 30 轮，地狱模式约 21 轮）
- 48 格棋盘：35 个服务 + 3 个按用量收费的格子
- 30 张 Health 事件卡（机会）、38 张 re:Invent 卡（命运），4 个玩法 DLC 和代理商模式全开时一共 42 张、53 张；其中有现场社交卡（踩坑大会、Office Hours、白板画架构、技术分享会等）和指向别人的卡（这次事故谁背锅、根因在上游）；要你停一轮的卡都能交钱立刻处理、照常走；15 个角色（12 个客户 + 3 个代理商）、48 种有效架构（很多格子可以二选一，几个架构能串联收费）、114 道题（4 个玩法 DLC 另带 18 道，共 132 道）
- 每个角色一个起死回生的专属技能：总资产低于开局资金一半时发动，一局一次；发动时先结算角色自己的技能，再「战略并购」：按卖回价买下全场总资产最高的对手的一块服务。模拟里快不行的人翻盘率约 12%（不开技能 0–1%）
- 6 个模式：娱乐、入门、标准、完整、学习、地狱（全部加压项拉满、必须答题、每个角色多一条地狱限制）
- 4 个玩法 DLC（GenAI 浪潮、安全攻防、FinOps 账单大战、全球出海），各带规则、卡牌和题目
- 2 个开关（默认关）：高速部署（部署点数 0–12，1–12 点各一个技能，12 点 DDoS 让对手服务下线 2 回合）、代理商模式（座位可以当代理商，不超过一半：落在空地上按进货价 5 折占地，自己的地只在组成有效架构时收过路费、架构 ×2；客户落在代理商的地上可以从他手里买，在用的不卖；开局资金是客户的总和，勾了轮数上限时是角色卡加每位客户 $300（娱乐、地狱模式只按角色卡）；还多 3 张 Health 卡、6 张 re:Invent 卡）
- 3 个认证题库 DLC（CLF-C02 40 道、SAA-C03 40 道、AIF-C01 30 道，原创练习题，题目在 `tools/qbank/*.json`，改完跑 `python3 tools/inject_qbank.py` 写回网页），带错题本和刷题模式

## 怎么玩

**网页版**：用 Chrome 或 Safari 打开 `code/index.html`，选好人数、难度、胜利条件，点「开始游戏」。

- **办线下活动**：开局页最上面点「UG 活动局 · 一键开局」（娱乐模式 + 边玩边答题，12 轮或 30 分钟先到为准，4 人一桌），或者网址加 `?ug=1`。流程和要讲的规则见 `手册/0-组织者/组织者包.pdf`。
- 外观默认跟随系统，可在开局页或对局菜单选择浅色、深色；选择保存在本机，切换外观不影响对局进度或其他联机玩家。
- 进度自动存在浏览器里（localStorage），关掉再打开可以「继续上一局」。同一个浏览器只存一局，存档旁边记了版本号：两个标签页开着同一局时，后接着打的那边算数，另一边停止存档并提示；开新局前有没打完的局会先确认。浏览器禁止网站保存数据、或者存储满了时存不上，局里会提示。
- 开局页默认选的是标准局，第一次玩建议改选入门局，胜利条件保持默认（经典 + 15 轮上限）。Well-Architected 胜利的门槛随难度提高：入门局每条支柱 1 分，标准局每条 1 分且六条共 12 分，完整局每条 2 分，地狱模式每条 2 分且共 18 分。
- 地狱模式：完整局 + 4 个玩法 DLC + 高速部署 + 全部题库，必须边玩边答题，卡牌 ×2，过路费涨得最快，没有新账户保护期；每个角色多一条地狱限制。
- 缺钱时可以把服务按实付（买价 + 升级 + 容量）8 折卖回亚马逊云科技；全卖了也不够还才破产，服务按欠款比例分给各个债主；主动认输时资产交回亚马逊云科技，不能指定送人。
- 3 人以上时右侧玩家卡默认收起，点名字那一行展开；右侧栏不跟着回合自动变化。屏幕 1800 宽以上时右侧栏加宽，玩家卡排两列。
- 中间右栏是「这回合还能做什么」：能升级的服务、能发动的技能、技术债、能不能抽卡、能不能出题考对手（同一回合只能发动一个：考一个人每局一次，花 $100，答对他拿走、答错他赔你 $200；考全场每 3 圈一次，至少两位对手，每人 $50，答对的拿走、答错的赔你 $100）、哪个架构只差一块，能直接操作的带按钮。技能留下的持续效果（过路费翻倍、监管沙盒、运行费减免、被 DDoS 打下线）挂在玩家卡上。
- 网页里点「玩法」先看三分钟的简版，可以切到完整版。
- 语言：开局页「新建一局」右边、对局顶栏里的「语言」按钮，点开选简体中文、English 或日本語，当场换字，不换页面、不回开局页，进行中的这一局接着玩（之前的日志还是原来的语言）。
- 老板键：按 `（Esc 下面那个键）整页换成一张表格，标签页标题和图标也换掉；再按一次回来，也可以双击表格最上面的文件名。不在输入框里时输入 `:version` 回车，弹出版本号、构建号和内容规模。
- 开了高速部署时，中间带进度条的「部署 x/12」按钮打开 12 张技能卡片，亮着的点一下就发动，灰的写着为什么现在不能用。
- 电脑在玩时主按钮旁边有「暂停 / 继续」；电脑的弹窗只能看，真人点按钮、按键都不会替它选。
- 点棋盘上的服务格，弹窗顶部写着谁拥有、在第几级、现在的过路费（含架构串联收费）、每圈运行费、关联的有效架构和还差哪块。
- 一局结束先出「最终架构总览」，再出战报：估值排名、本局之最、估值走势和关键时刻，每人一份复盘档案（钱花在哪、钱从哪来、最赚和最烧钱的服务、凑成和差一块的架构、想赢可以怎么改）。
- 打开开局页第 02 步「难度」下面的「边玩边答题」后，付过路费、买服务时会出亚马逊云科技的题目。难度里的「学习模式」是另一回事：标准局 + 必答题 + 错题本 + 不限轮数，会自动打开边玩边答题。
- **联机**：开局页第 04 步，房主「创建房间」设密码，其他人在自己的设备上打开同一个 `index.html`「加入房间」。游戏在房主那台跑，轮到谁谁在自己的设备上操作；房主刷新后重新建房间、点「继续上一局」，其他人按局里的名字和原浏览器钥匙重新加入；无钥匙时由房主确认身份后回到原座位。连接用 WebRTC，配对用 PeerJS 公共信令服务器（库已内嵌在 `index.html` 里，不从 CDN 加载）；公司网络连不上时可以用 `?peerhost=` 指定自建 PeerServer。开局页「联机设置和测试」能逐项检测信令、点对点、STUN、中继，也能填自己的中继服务器（TURN）：PeerJS 原来自带的免费中继已经下线。
- **受邀观战（测试中）**：房主在联机大厅或对局菜单打开「受邀观战」，开启后把房间号和独立的观战邀请码发给解说；对方在「加入房间」选择「受邀观战」。最多 4 位观众，不占玩家座位，可中途加入、查看棋盘/资料和只读决策弹窗。关闭或更新邀请会断开观众，旧邀请失效；单独移出仅断开当前连接。邀请码不等于玩家房间密码，请只交给受信任的解说。首版沿用完整客户端状态，不是经过隐藏信息裁剪的公开直播。
- **联机身份**：昵称用于寻找座位，座位钥匙证明原浏览器身份。同一浏览器重连会自动带钥匙；换设备、清除存储或房主刷新丢失钥匙后，请联系房主，在大厅或对局菜单点击「确认入座」核实本人。已有在线玩家不能仅凭同名顶替，离线座位也需要钥匙或房主确认。

**实体版**：`docs/手册/6-打印/棋盘与配件.pdf` 第 1 页用 A3 纸打印（拼两张 A4 也行），其余页和 `卡牌.pdf` 用 A4 纸打印；`卡牌.pdf`选「实际大小 / 100%」、双面、长边翻转，沿虚线裁开。单张卡 63 × 88 mm，可以直接套标准卡套。棋盘可以用网页截图打印，规则查 `手册/2-主持人/主持人规则书.pdf`。

**Docker**：

```bash
docker build -f deploy/docker/Dockerfile -t aws-ug-tycoon .
docker run --rm -p 127.0.0.1:8080:8080 aws-ug-tycoon   # 然后打开 http://127.0.0.1:8080/
# 本机 8080 已经被别的程序占了（报 port is already allocated）就换一个本机端口，比如：
docker run --rm -p 127.0.0.1:18080:8080 aws-ug-tycoon  # 打开 http://127.0.0.1:18080/
```

- 镜像里只有网页和讲解音频：`code/`（游戏、架构讲解、服务知识点，放在网站根上，不含对照表 `code/i18n/`）和 `docs/更新说明.html`；手册 PDF、`.md`、`tools/`、`.claude/` 都不放。nginx 以普通用户运行、监听容器里的 8080。
- 端口只发布到本机 `127.0.0.1`，别的电脑访问不到。别写成 `-p 8080:8080`：那样会发布到所有网卡，同一网络里的人都能打开。
- 用 8080 不用 443：443 是 HTTPS 端口，要配 TLS 证书；本机玩用 HTTP 就够了。要给别人通过网络访问，得先决定开放给谁并配好证书。
- 别的电脑想玩，直接把 `code/` 文件夹拷过去，用浏览器打开 `code/index.html` 就行，联机走浏览器之间的 WebRTC，不经过这个服务器。

## 开发检查

开发检查使用 Node.js 24 或更新版本；游戏本身仍可直接打开 HTML，无需安装依赖。

```bash
cd tests
npm ci
npx playwright install chromium
npm run check
```

- `npm run lint`：检查自有内联 JavaScript 和 CSS 的语法、重复分支、未知属性等错误，跳过内嵌第三方库。
- 国际化继续复用 `_t/_tf/_tr`、`__I18N` 和内嵌手册 `__MAN`；lint 拦截新增的 en/ja 平行字典及常见翻译框架依赖/动态加载。现有语言切换确认提示例外。这是可自动检查的约束，不能代替对任意自制实现或手工内嵌库的审阅。
- `npm run lint:size -- <基线commit或ref>`：比较发布 HTML、gzip 和固定四人中盘/终局的代表性存档 JSON。CI 自动与 PR 目标提交或 push 前提交比较，新分支与默认分支比较；所有指标写入检查摘要。增长超过 5%，且 HTML 增加超过 50 KiB、gzip 超过 20 KiB、任一代表性存档超过 2 KiB 时告警，均不阻断。缺少基线或存档未能测量时也提醒；代表性存档不是最长对局/满历史存档的上限。
- `npm run test:layout`：用 Chromium 检查 15 种窗口尺寸的棋盘，确认没有页面横向溢出、棋盘格出屏或操作区被裁切，并验证按钮能滚动到可视区域且可点击。另以中文、英文、日文检查 19 种窗口尺寸下棋盘、玩家卡、日志、操作区的内部文字裁切，以及标题与工具栏重叠；覆盖最长玩家名、满级及容量徽章，并抽查开局页、服务详情、事件卡、玩法、图鉴和战报。包含浏览器工具栏占高及缩放对应的视口；正常滚动和明确省略不算错误，手机和平板遵循各自的文字显示规则。
- `npm run test:content`：仅运行内部裁切专项（先 `cd tests`），复用页面遍历尺寸，弹窗采用代表组合，供本地快速检查；已随 `npm run check` 自动进入 CI，无需新增工作流或依赖。
- `npm run test:movement`：走棋路径、动画隔离、有界模型与弱网指标；`npm run test:auth`：实际房主协议的观众权限和座位鉴权回归。
- 浏览器检查还覆盖深浅主题、真实 WebRTC 走棋及受邀观战；生产 PeerJS 建房/自动重连使用本机官方 PeerServer 测试。详细范围与未覆盖条件见 [受邀观战验证说明](tests/verification/spectator.md)。
- GitHub Actions 在 push 和 PR 时执行以上检查；失败时保留截图和 trace，可用 `npx playwright show-trace <trace.zip>` 查看。

布局约定：棋盘格保持在左右边界内；矮窗口中央操作区可滚动，手机页面允许纵向滚动。不要用整页 `overflow:hidden` 掩盖溢出。增加布局或内容时，边界及操作可达性场景放在 `tests/layout.spec.mjs`，内部裁切与重叠场景放在 `tests/content-layout.spec.mjs`。

## 改了规则之后

（这一节说的是开发目录里的路径和脚本：开发目录里文档在根目录，同步到仓库时放进 `docs/`；`tools/` 不进仓库。）

规则和数据只有一个来源：`code/index.html` 里的数据表，包括 `SVC`、`UPGRADES`、`INC`、`REI`、`COMBOS`、`ROLES`、`QUIZ`、`BAL`。改完按下面的顺序同步：

1. **跑机器人自测**，确认改动没有引入错误：

   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
     --virtual-time-budget=1800000 --dump-dom "file://$PWD/code/index.html?bot=1&games=12" | grep -o 'BOTRESULT {.*' | head -c 600
   ```

   结果里 `"errors":[]` 表示没出错。12 局大约要 4–5 分钟（加了起死回生技能后对局变长了，时限给小了会被截断、看不到结果）。

2. **改两份 md**：`规则书.md`、`玩法手册.md`。大表（棋盘、服务详情、卡牌、角色、架构、题库）不用手改：`node tools/gen_rules.mjs && python3 tools/sync_docs.py` 会从网页数据重新生成并写回去；手写的规则文字要自己改。
3. **把玩法手册写回网页**：`python3 tools/build_manual.py`，会更新 `code/index.html` 里的 `MANUAL_HTML`（完整版）和 `MANUAL_LITE_HTML`（简版，来自 `玩法速览.md`）。
4. **出 PDF**：`python3 tools/build_pdfs.py`，一次生成 `手册/` 下全部 PDF 和根目录的 `更新说明.pdf`：两本手册、卡牌、棋盘与配件、速查卡，再调 `tools/build_mode_manuals.py` 出 8 本模式和专题手册、10 本简版手册、分级规则手册、三本图鉴、术语对照、组织者包和 UG 活动流程单、更新说明，最后给所有 PDF 补书签分隔符。改了模式规则的数字记得同步 `build_mode_manuals.py`（专题手册里的角色表和技能表会自动从网页数据取）。流程是先截棋盘图当封面，再把 md 套上 `tools/pdf.css` 打成两本手册，最后用 `tools/build_cards.mjs` 和 `tools/cards.css` 生成卡牌。

## 测试和调试用的网址参数

| 参数 | 作用 |
|---|---|
| `?bot=1&games=N` | 机器人自对弈 N 局，检查状态是否合法，结果写在页面里的 `BOTRESULT` |
| `?sim=N&players=4&diff=std&reserve=150` | 经济模拟（不渲染），看破产率、轮数、钱的流向，结果是 `SIMRESULT` |
| `?sim=N&act=ai&players=4&diff=std` | 同上，但弹窗交给电脑玩家（开局能勾的那种 AI）来答，测对局长度最接近真人；结果里还有第 10/15/20/30 轮的六大支柱得分 `pil`、每局的角色 `roles` 和赢家 `win`。模拟里电脑答题默认全对（`bal={"aiQuiz":0.6}` 可改）；买服务、付过路费的题都答，手上的 MAP 卡也会用 |
| `…&diff=hell` / `&dlc=speed,reseller` / `&rs=1` / `&learn=1` / `&rl=15` | 模拟地狱模式 / 开 DLC 和开关 / 0 号座位当代理商 / 开边玩边答题 / 打满 15 轮按估值排名（开局页默认；不加就打到分出胜负） |
| `…&acc=1,0.75,0.5,0.25` | 每局把这几个答题正确率随机分给各座位，看正确率和胜率的关系（结果里的 `acc`、`winId`） |
| `?bal={"rentBase":0.2}` | 临时覆盖平衡参数 `BAL`（工资、运行费、请求费、过路费基数、`growth` 流量增长、`sell` 卖回折扣、`cardGrow` 卡牌金额跟涨、`quizRent` 答对后付几成过路费、`noSkill` 关掉角色技能等）；地狱模式另有 `HELL_BAL` |
| `?demo=board` | 摆好一个对局中盘，用来截图。还有 `inc`、`rei`、`deed`、`deed2`、`gallery`、`manual`、`cw`、`land`、`flip`、`es`、`pay` |

## 分享给别人之前

- 不含个人信息：没有邮箱（唯一一处 `team@peerjs.com` 是内嵌的 PeerJS 开源库自带的）、手机号、账户 ID、密钥、本机路径或用户名；链接都是公开的 `docs.aws.amazon.com` 和 `aws.amazon.com`；PDF 元数据只有标题和生成时间。示例玩家名用的是昵称（韩叔、虫虫、Damo、Yuki）。
- 打包时删掉 `.claude/`（本机的编辑器设置，跟游戏无关）和 `.DS_Store`（macOS 自动生成）。
- 只给玩家的话，带上 `code/` 文件夹和需要的 PDF 就够了；要改规则才需要 `tools/`、`*.md` 和 `tools/qbank/`。`tools/out/` 是生成 PDF 的中间文件，可以不带。

## 内容约定

- 只用亚马逊云科技对外公开的说法，不用内部术语。品牌写「亚马逊云科技」，服务保留官方名称（如 Amazon S3、Amazon Cognito）。
