# 受邀观战与座位身份验证

关联上游 issue：https://github.com/cloudsmithy/aws_game/issues/10 。功能处于测试阶段，暂不提 PR。

## 权限与数据边界

- 房主默认关闭观战；显式开启生成 128 位随机邀请码，最多 4 个观众连接。邀请只存在页面内存中，不进入游戏存档、普通状态、玩家弹窗或浏览器 URL。
- 观众注册在 `MP.viewers`，与 `MP.seats` 分开，不领取座位号、座位钥匙，不获得玩家入房凭证。昵称只是显示文字，不是账号身份。
- 房主接收观众消息时只处理 `resync`；操作、答题、暂停、改名、结算、作弊和举报均不能进入玩家分支。客户端另外阻止发送这些消息，但权限成立不依赖客户端保护。
- 所有玩家操作都必须来自该座位**当前、在线且未撤销**的连接。一个连接完成入房后不能通过重复 hello 新增座位或改变身份。
- 观众完整状态、增量与动画沿用现有协议；动画不得写 `S`。补发只作用于请求者的同步基线，不改变其他客户端的同步基线和重画方式。
- 更新或关闭邀请撤销全部现有观众连接；单独移出只断开当前连接，持有有效邀请的人仍能再次加入。邀请码是可转交的持有者凭证，不是实名账号。
- 受邀解说沿用现有完整客户端状态（只排除原协议已排除的 `diceQ`），包含牌堆等客户端已有数据；不能宣称隐藏了未来抽牌、其他玩家资料或具有比赛防窥屏能力。公开观战需另行定义数据投影与延迟。

## 玩家身份修正

旧逻辑允许知道房间密码的人，使用离线玩家的名字直接接管座位。新逻辑要求原浏览器的座位钥匙，或房主通过语音等已知渠道核实后显式批准：

1. 原钥匙正确：允许在线/离线重连，撤销旧连接并换发新钥匙；旧钥匙不能再次接管。
2. 无钥匙且原座位在线：拒绝。
3. 无钥匙且原座位离线，或大厅名字对应已保存的座位：进入待确认队列；不发送游戏状态、不分配座位。最多 4 个请求，60 秒超时。
4. 审批前后检查同一游戏对象、同一座位对象、座位仍离线、连接仍有效；不能批准过期请求或让审批复活已关闭的连接。
5. 重连失败保留锁定客户端身份，防止远端快照被当作本机单机局写入存档。

房主刷新后内存中的座位钥匙不保留，按上述人工核实路径恢复。旧版本客户端依然能首次入房，但没有钥匙的重连需要房主审批；旧房主不支持受邀观战，不能使用新观众功能。

## 自动检查

在 `tests/` 执行：

```bash
npm run check
# 仅协议权限：
npm run test:auth
# 仅观战浏览器回归：
npx playwright test spectator.spec.mjs
```

`auth.check.mjs` 从发布 HTML 提取并执行实际 `MP`，不是测试另一份鉴权实现：

- 邀请默认关闭、错误凭证、人数上限、关闭/轮换、单独移出、禁止身份升级和重复 hello。
- 绕过所有客户端 UI，发送全部游戏操作类型；验证权威状态、玩家座位和控制副作用不变。
- 三类无权连接（观众、未认证、旧连接）× 7 类消息 × 任意两个消息顺序，共 147 条有界序列，输出 `AUTH_METRICS`。
- 整份状态补发、增量基线隔离、不发送骰点/邀请/座位钥匙。
- 同名抢座、正确钥匙重连/轮换、房主审批/拒绝、审批中换局/换座/断线/超时、读档前抢先入座。
- 用传输桩执行生产 `host/join/rejoin` 生命周期，检查观众不读取或发送玩家钥匙/密码、旧连接回调隔离、旧 Peer 连接拒绝、被拒后保留只读身份。

`spectator.spec.mjs` 用独立浏览器上下文模拟独立设备，实际 Chromium 与真实有序 WebRTC DataChannel：

- 房主 + 玩家 + 两位观众，中途加入、经过 UG 的移动、逐端比较完整同步状态、只读弹窗与玩家正常作答。
- 观众绕过客户端发送过滤，直接向数据通道注入伪造操作；用随后收到的整份补发作为有序处理屏障，再比较状态与未提交的玩家选择。
- 增量缺口自动补发、观众断线后重新入房、邀请失效与新邀请、原玩家不受影响。
- 真实房主审批 UI、换发钥匙、在线接管、旧连接和重复 hello 隔离。
- 手机 390×844，只读菜单、深色外观、资料查询、本机已有存档不被覆盖。
- 观众留在大厅等待下一局，开局按钮始终禁用；下一局保持观战身份。
- `file://` 直接打开单 HTML、移动中加入、存储被禁用、动画不写状态。
- 决策进行中加入、观众名字按文本转义、邀请/审批等房主本地窗口不广播。

## 进一步贴近真实联机的测试

`peerjs.spec.mjs` 把原先的手工 SDP / PeerJS 传输桩换成 [官方 PeerServer 1.0.2](https://github.com/peers/peerjs-server)，不替换发布 HTML 内的 `Peer`、`MP.host/join/rejoin`。每个参与者使用独立 Chromium BrowserContext，隔离 cookie、localStorage 和 sessionStorage；这仍是同一台电脑上的多个浏览器环境。

- HTTP 测试服务和信令均只监听 `127.0.0.1`。通过真实控件建房、输入玩家密码、开局、展示角色、开启观战和输入邀请码；服务器记录实际 OFFER / ANSWER 以确认走过真实信令。
- 测试唯一的连接配置替换是本机信令地址、HTTP 和空 ICE 列表；不依赖公共 PeerJS / STUN / TURN，也不修改业务鉴权。测试继续禁用本机 mDNS 地址隐藏。
- 正常轮转走界面和真实远端操作消息。骰点固定为 `[1,2]`，首张 re:Invent 固定为 1 号卡，避免随机传送/多方投票把网络回归变成随机规则测试；结算仍执行生产规则。
- 关闭真实 PeerJS DataConnection，观察生产重连定时器创建新 Peer、完成 hello/welcome、恢复原身份与完整状态，没有手工调用 `MP.rejoin` 或注入新状态。
- 通过本机信令服务的控制接口关闭并阻止房主的真实 WebSocket：确认已有 P2P 仍可正常走棋，解除后房主自行恢复信令，新观众能够加入。该接口只属于测试服务，不打包到游戏。
- 在发送边界暂存指定观众的消息，其他玩家正常传输；之后每 80ms 按 FIFO 释放，消息仍经真实 PeerJS 编解码和 DataChannel。这是**应用层延迟模拟**，不等于底层丢包或带宽限速。
- 通过 CDP `Debugger.pause/resume` 实际暂停观众 JavaScript，验证定时器没有推进，房主继续走棋；恢复后状态一致、动画队列及占位清空。这是**JS 无法执行**的模拟，不等于真实手机锁屏。
- 真实刷新房主页面、保留本机存档、创建新房间、继续上一局；玩家刷新后无新房间钥匙，必须由房主审批。验证业务状态不丢失、新旧邀请隔离、观众凭新邀请恢复观看。读档新增的三个零值默认字段先归一化，再比较所有玩家业务字段、资产、回合及阶段。
- 玩家通过真实改名窗口改名后，关闭通道仍能自动回原座位并轮换钥匙；房主通过界面撤销邀请后，观众不自动重连。
- `file://` 打开发布单 HTML，真实建房、入房、开局和观众刷新重入，仍使用本机官方信令；游戏页面不依赖 HTTP 服务。
- 四观众持续同步和周期性真实断线，最后逐端比较完整状态并检查 `4 观众 + 1 远端玩家 = 5 条有效连接`、无待审批请求；记录更新次数、断线次数、时长和 JS 堆大小。堆大小仅作观测，不用一次前后差值断言没有内存泄漏。

默认持续测试 30 秒，CI 可以运行；本机可独立延长：

```bash
npm run test:layout -- peerjs.spec.mjs
PEERJS_SOAK_MS=180000 npm run test:layout -- peerjs.spec.mjs --grep 四观众
# 端口被其他任务占用时可单独选择，默认仍为 8878 / 8879：
AWS_GAME_TEST_PORT=8888 AWS_GAME_SIGNAL_PORT=8889 npm run check
```

持续测试输出 `PEERJS_SOAK`，同时附加 `peerjs-soak.json` 到 Playwright 结果。失败保留截图和 trace。延长测试不代表已完成小时级/整场活动的稳定性验收。

### 无效故障模拟的排除

在本机 Chromium 上，旧的 `Network.emulateNetworkConditions` 及新的全局 `emulateNetworkConditionsByRule` 设置 `packetLoss:100` 后，测试标记仍通过 WebRTC 到达；因此**没有计为丢包测试通过**。`Page.setWebLifecycleState(frozen)` 也没有停止当前 WebRTC 页面的定时器，不能当作锁屏验证。测试改用能观测到效果的实际通道关闭、WebSocket 中断、应用消息排队和 JS 暂停。CDP 参数的说明参见 [官方协议定义](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/browser_protocol.json)，实际效果必须另行断言。

### 更真实流程发现并修复的问题

真实建房后开局，再让无钥匙玩家重新入座时，房主看不到新审批按钮：隐藏大厅和对局菜单重复使用 `id=mpmembers`，更新命中了隐藏大厅。已改为 `data-mp-members` 并更新全部成员区；真实刷新/读档/审批测试明确断言审批按钮在可见的 `#game` 中出现。权限本身没有绕过，但操作流程会卡住；先前直接摆中盘的测试没覆盖这一点。

## 证据限度与人工验收

这些是有界实现验证与浏览器集成测试，不是对无限执行或任意网络的数学证明。第一组 movement/spectator 浏览器测试由测试代码交换 SDP；新增 PeerJS 流程由官方本地信令交换。两组均不覆盖公网 PeerJS/STUN/TURN，仅在测试中禁用本机 mDNS 隐藏。生产 PeerJS 生命周期已由本地官方信令的完整流程补充验证，但仍不能当作公网端到端结果。

提 PR 前仍应人工确认：

- 两台以上真实设备，用正式 PeerJS 信令建房；玩家及观众都分别从本地 HTML 和网页加入。
- iOS Safari / Android Chrome 的真实锁屏、切换网络及后台恢复。房主刷新重建/读档/审批已有 Chromium 自动回归，仍需手机端人工复核。
- 真实网络抖动、TURN 中继、四位观众长期观看对房主 CPU/上传带宽的影响；本次未给出容量或延迟保证。
- 邀请窗口、玩家审批和手机画面的文案、布局及全局主题切换，尤其长昵称和长局日志。

房主仍是可信权威，能看到并控制整个游戏；本功能未增加账号服务或公网抗攻击设施。

## 追加并发边界与输入校验

新增四项真实 PeerJS 浏览器回归：

- 原玩家 JS 暂停、房主关闭其连接后，无钥匙请求进入审批；原玩家恢复并凭钥匙自动认回座位，再批准旧请求也不能覆盖新连接。
- 请求者关页、房主确认连接已失效后，旧审批不能复活连接、生成新钥匙或占座；玩家业务状态保持不变。
- 观众 JS 暂停期间收到决策关闭和邀请撤销，恢复后保持锁定客户端、没有旧决策窗口复活、没有占用玩家座位。
- 通过真实未鉴权通道发送对象类型的名字，以及通过已认证玩家通道发送畸形操作名、作弊参数和答案输入；均不得触发房主异常或提交选择，正常答案和后续观众加入仍然有效。

复现并修复了输入转换问题：旧入房逻辑对任意 `name` 调用 `String`，对象 `{toString:null}` 会抛异常；操作名的属性查询和参数转换存在同类边界。现在入房名字及操作名要求文字，作弊参数/弹窗输入只接受原始值，拒绝对象转换。协议测试增至 17 项，含合法答案的正向验证；这些检查不代替消息大小限制或公网抗攻击设计。

本机直接关页时，WebRTC 识别玩家断线约 16 秒、清除已关闭请求约 17 秒；这是一次实测，不是保证时限。测试给识别过程最多 30 秒，等待实际失效后再验证审批隔离。主动点击「离开房间」会显式关闭通道；直接关页、断网或进程消失需要等待浏览器识别，不能承诺即时离线。


## 建房时开启与赛前入场

房主在创建房间表单勾选「开启受邀观战」（默认不勾），成功建房后才生成独立邀请码，大厅直接显示邀请码、复制邀请按钮和已到场观众。复制内容只包含房间号、观战邀请码和加入说明，不含玩家密码；系统剪贴板不可用时提示手动选择。建房完成后该选项只显示状态，后续开关和轮换仍在观战管理中操作。

新增真实流程覆盖：观众先加入大厅，未收到对局状态时保持只读身份、不占玩家座位、不能点开始；信令断开重连不换邀请码，也不让观众重复入场；玩家随后正常入座，房主开始后观众自动收到状态并进入只读对局。另验证未勾选时不生成邀请码、不能用玩家密码观战。剪贴板测试只替换系统写入接口，验证复制内容及失败提示，不改写测试机个人剪贴板。

协议回归另验证建房成功前没有有效邀请、默认关闭、重复 open 不轮换邀请。
