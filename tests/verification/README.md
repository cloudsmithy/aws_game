# 联机分段走棋：契约、形式化检查与指标

## 状态契约

房主的 `moveSteps` 是唯一执行移动与结算的逻辑。新版 `walk` 消息只携带展示路径；客户端 `MPFX` 不写 `S`，只维护展示占位 `MOVE_TO` 和 3D 对象。动画位置可以暂时领先或落后于最近收到的权威位置，不能拿来结算、存档或发起下一回合。

- **权威隔离**：对任意动画转换 `A`，`S_after = S_before`。玩家位置、余额、资产、日志、回合不能因动画改变。
- **路径等价**：把 `walkSegment` 的各段连接起来，必须等于旧版逐格路径；每段内部不得越过起点 / UG 结算边界，反向绕起点也分段。只有房主处理完边界后才发下一段。
- **幂等**：连接内只接受递增的 `seq`，重复或过期路径不重播。能力 `walk:1` 在 hello 中协商；未声明的旧客户端继续接收 ws / wh，新版继续兼容旧房主。
- **取消隔离**：断线、welcome、下一局、切后台、增量接不上、回放超时或积压时递增展示 epoch。旧异步任务与延迟弹窗不得继续执行；旧连接的 data 事件不再进入处理器。
- **最终收敛**：可靠有序的 DataChannel 最终交付收尾和权威状态后，客户端的同步状态等于房主，展示占位解除。断线期间不声称实时一致；重连使用房主全量状态。

## 可复现检查

在 `tests/` 执行 `npm ci`、`npx playwright install chromium`、`npm run check`。`npm run test:movement` 可单独运行无网络的验证；`npm run test:layout -- movement.spec.mjs` 运行浏览器集成检查。

`movement.check.mjs` 直接提取发布 HTML 的规划器、房主移动函数、协议发送函数和实际回放器，避免测试另一份实现。

1. **路径有界穷举**：48 个起点 × 0..96 步 × 正反方向 = 9,312 例。逐项检查旧路径等价、分段上限、结算边界。
2. **具体实现交错**：90 例，覆盖每跳附近的取消、权威状态先到 / 后到、断线、后台、补发、重启、重复及过期序号；另检查畸形消息、关闭动态效果、超时、队列积压、旧弹窗失效、新旧能力协商及房主收支。
3. **显式状态模型检查**：单客户端、一段三步的有限协议模型，状态为 `(host, client, lastState, wire, left, seen, cancelled, duplicated, endRx, rx, ghost)`。枚举房主推进、FIFO 投递、本地播放、一次取消、一次重复和收尾转换的所有可达交错：120 个状态、362 条转换，4 个完成状态，无不变量违例。动画 / 取消转换保持权威状态与传输队列不变；完成状态断言 `client = host` 且没有展示占位。
4. **真实浏览器集成**：一个房主、两个客户端，真实 Chromium WebGL 动画及 WebRTC DataChannel。只发动画时对比完整 `S` 不变；普通六步、经过 UG、反向绕起点后比较完整同步状态（不包含原协议本来就不发送的 diceQ）；制造增量序号缺口，检查真实 resync 请求与全量恢复。关闭所有自有浏览器上下文。仅此测试禁用 mDNS 隐藏以便本机直连，不测试公网信令 / STUN / TURN。

这是有界形式化模型检查与实现回归验证，不是任意网络、无限执行或完整游戏规则的数学证明。模型是抽象契约，具体实现测试和浏览器测试分别校验对应行为。收敛依赖恢复连接后最终收到房主状态，不能用动画来替代丢失的权威数据。

## 弱网 A/B 指标

同一回放器、同一路径（1→7，6 步）、每步 150ms，首包延迟 200ms，后续包因拥塞额外延后 600ms，保持可靠有序。使用虚拟时钟隔离设备帧率，比较旧逐格消息与新版一次路径 + 收尾：

| 指标 | 逐格 | 分段 |
|---|---:|---:|
| 动画协议消息 | 8 | 2 |
| 首跳至最后一跳结束 | 1500ms | 900ms |
| 段内跳间累计空闲 | 600ms | 0ms |
| 段内最大跳间空闲 | 600ms | 0ms |

运行时输出 `MOVEMENT_METRICS` 和 `MOVEMENT_MODEL`，断言不满足即失败。75% 的消息减少仅针对这段动画协议，不包括仍然保留的权威状态同步、信令或其他特效；不等于总体带宽减少 75%。首包等待、结算边界等待和房主操作确认仍依赖网络。真实设备帧率、跨公网尾延迟和长期掉线率未在本次测量。

## 回退

按客户端能力协商，不要求各设备同时升级。回退本次功能提交即可恢复逐格协议；没有存档结构或规则变更。
