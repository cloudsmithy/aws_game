4 Backup 主要用来做什么？（选项：集中管理多个服务的备份策略 / 把本地服务器整机迁到亚马逊云科技 / 缓存静态内容，加速网站访问 / 扫描实例和镜像里的软件漏洞） 集中管理多个服务的备份策略 能统一管 EBS、RDS、DynamoDB、EFS 等的备份

6 S3、EFS 这类服务要不要自己做多 AZ？（选项：不用，默认就跨多个 AZ 存数据 / 要自己在两个 AZ 各建一个桶互相复制 / 要买 Multi-AZ 附加功能 / 只有付费版才跨 AZ） 不用，默认就跨多个 AZ 存数据 S3 标准存储类至少在 3 个 AZ 里存数据；单区类型如 S3 One Zone-IA、EFS One Zone 例外

# 考点 题目 答案 解析
1 设计安全的架构 某公司在 Amazon EC2 上运行的应用需要读取同一账户中某个 Amazon S3 存储桶的对象。安全团队禁止在实例或代码中保存长期访问密钥。最安全的做法是什么？（选项：创建只读该存储桶的 IAM 角色，通过实例配置文件附加 / 创建 IAM 用户，把访问密钥写进实例的环境变量 / 把访问密钥加密后打包进 AMI，实例启动时解密使用 / 将存储桶策略设为允许所有主体读取，再用安全组限制访问） 创建只读该存储桶的 IAM 角色，通过实例配置文件附加 实例配置文件让应用获取 IAM 角色的临时凭证，不需要保存长期密钥，还能按最小权限授权。环境变量或 AMI 中的访问密钥仍是长期凭证；安全组无法控制 S3 API 授权，公开存储桶会造成数据暴露。 官方文档
2 设计安全的架构 某应用使用 Amazon RDS for MySQL，数据库密码目前硬编码在配置文件中。公司要求集中存储凭证并定期自动轮换，同时尽量减少自研代码。应采用哪种方案？（选项：将凭证存入 Secrets Manager 并启用自动轮换，应用在运行时通过 API 读取 / 将密码以 SecureString 存入 Systems Manager Parameter Store，再编写 cron 脚本每月改密码 / 把密码加密后保存在 S3 中，由 Lambda 每天下载校验 / 在 KMS 中开启密钥自动轮换，由 KMS 自动更换数据库密码） 将凭证存入 Secrets Manager 并启用自动轮换，应用在运行时通过 API 读取 Secrets Manager 可集中存储凭证并内置自动轮换（托管轮换或 Lambda 轮换函数），应用按需读取最新值。Parameter Store 方案需要自写轮换脚本；KMS 密钥轮换只更换加密密钥材料，不会修改数据库密码。 官方文档
3 设计安全的架构 一家金融公司要求 S3 中的敏感数据静态加密，并且必须能自行决定哪些 IAM 主体可以使用加密密钥、自行管理密钥轮换，并通过 CloudTrail 审计密钥使用。哪种方案满足全部要求？（选项：使用 SSE-KMS 并采用客户托管的 KMS 密钥，通过密钥策略控制访问 / 使用 SSE-S3（Amazon S3 托管密钥） / 使用 SSE-KMS 并采用亚马逊云科技托管密钥 aws/s3，再修改其密钥策略 / 在客户端使用硬编码在应用中的对称密钥加密后上传） 使用 SSE-KMS 并采用客户托管的 KMS 密钥，通过密钥策略控制访问 客户托管密钥的密钥策略由客户管理，可自行开启自动或按需轮换，密钥使用会记录到 CloudTrail。SSE-S3 无法单独控制密钥权限；亚马逊云科技托管密钥的属性和密钥策略都不能修改；硬编码密钥既不安全也无法集中审计。 官方文档
4 设计安全的架构 一个面向公众的网站部署在 Application Load Balancer 之后。最近发现个别 IP 地址在短时间内发送大量 HTTP 请求刷接口。如何以最少的运维工作量自动限制这些 IP？（选项：为 ALB 关联 WAF Web ACL，并添加基于速率的规则 / 在 ALB 的安全组中逐条添加针对这些 IP 的拒绝规则 / 把 ALB 换成 Network Load Balancer 以提升吞吐量 / 启用 VPC 流日志，由运维人员定期把可疑 IP 加入网络 ACL） 为 ALB 关联 WAF Web ACL，并添加基于速率的规则 WAF 基于速率的规则按 IP 等维度统计请求，超过阈值时自动限流，无需人工维护名单。安全组只支持允许规则；NLB 工作在第 4 层，识别不了 HTTP 层的滥用；人工分析流日志再改网络 ACL 反应慢且运维开销大。 官方文档
