一 有效架构是什么

把几块服务组成一套真实能跑的架构（比如 ELB → EC2 → RDS），就是「有效架构」。凑齐以后：

  • 联合收费：别人落在其中任意一块上，按整套架构所有服务的过路费加起来收；被打成 Impaired 的那块这次不算。
  • 串联收费：一块服务同时在几个生效架构里时，几个架构串在一起收，共用的服务只算一次。
  • 估值：每个生效的架构 +$200（打满轮数时排名用）。
  • 六大支柱：每个生效的架构给「性能效率」支柱加 1 分。
  • 有些架构还有额外加成（下表最后一列），比如容器组升级费减半、免疫某张 Health 卡。
  • 架构里的服务要都在手上、而且在运行：下线的、被 DDoS 打下线的服务不算持有，架构会暂时失效。
  • 写着「A 或 B」的格子，有其中一个就能凑成；几块都在手上，联合收费时都算进去。标着「可选」的那块不用也能凑成，有的话一起收。
  • 万能服务：CloudWatch、CloudTrail、Config 什么架构都能绑；KMS 只能绑有存储或数据库的架构；VPC 只要架构里有一块能接进 VPC 的服务就能绑。每块万能服务绑一个架构：缺一块就顶上，已经凑齐的就并进去一起收；绑了不能换。

三 每个架构的组成

Serverless API

可选 CloudFront → 可选 S3 + 可选 Cognito ⇄ API Gateway → Lambda → DynamoDB 或 Aurora

  • 怎么搭：（可选）CloudFront 分发前端页面 +（可选）页面放在 S3 里 +（可选）用户用 Cognito 登录，API Gateway 先验令牌（⇄）→ API Gateway 接请求 → Lambda 处理 → DynamoDB 或 Aurora（Serverless v2）存数据；前后端都配上就是一个没有服务器要管的完整网站
  • 至少要花：$680（每一格取最便宜的那个）
  • 额外加成：没有，只有联合收费

经典三层 Web

可选 Route 53 → 可选 CloudFront → ELB ⇄ 可选 Cognito → EC2 或 ECS → RDS 或 Aurora + 可选 OpenSearch

  • 怎么搭：（可选）Route 53 解析域名 →（可选）CloudFront 就近缓存静态内容、在边缘挡掉一部分攻击 → ELB 把请求分到多个 AZ →（可选）ALB 先让没登录的用户去 Cognito 登录（⇄）→ EC2 或 ECS 跑应用 → RDS 或 Aurora 存数据 +（可选）应用写库的同时把要搜的内容也写进 OpenSearch，站内搜索走它，不压数据库
  • 至少要花：$520（每一格取最便宜的那个）
  • 额外加成：没有，只有联合收费

容器平台

ECR → ECS 或 EKS ← ELB

  • 怎么搭：镜像放 ECR，ECS 或 EKS 拉镜像跑起来 ← ELB 把外面的请求分给这些容器
  • 至少要花：$500（每一格取最便宜的那个）
  • 额外加成：容器组升级费减半

事件驱动

EventBridge → Step Functions → Lambda

  • 怎么搭：EventBridge 收事件 → Step Functions 编排 → Lambda 执行每一步
  • 至少要花：$720（每一格取最便宜的那个）
  • 额外加成：没有，只有联合收费

订单削峰

  • 怎么搭：EC2 或 ECS 上的网站收订单 → SQS 排队削峰 → Lambda 按自己的节奏处理 →（可选）订单写进 DynamoDB、RDS 或 Aurora；大促时网站不被压垮
  • 至少要花：$560（每一格取最便宜的那个）
  • 额外加成：免疫「流量暴增」，扛住了还能领钱

  • 至少要花：$680（每一格取最便宜的那个）

  • 先看自己手上已经有的服务能凑哪几个：网页里玩家卡会列出「还缺 xx」，鼠标停在架构名上（手机上点一下）能看组成。
