每一块干什么5 块服务

01Kinesis必须

分析组 · 托管服务 · 按小时 · 售价 $300
在这里
Kinesis 收用户的点击、浏览行为
为什么用它
数据一条条持续进来、要实时处理时用它：扛得住突发流量，多个消费者能同时读
它是什么
实时数据流：Kinesis Data Streams 接住每秒大量的事件，多个程序同时读；Data Firehose 能把数据直接送进 S3、Redshift、OpenSearch。
常见用法
点击流和日志实时分析、实时大屏、IoT 数据

02Lambda必须

计算组 · Serverless · 按用量 · 售价 $220
在这里
Lambda 读流
为什么用它
代码不多、按事件触发的活交给它：不用管服务器和扩容，没请求就不花钱
它是什么
无服务器函数：上传代码，有事件来才运行，按请求次数和运行时长（毫秒）收费，没请求不收钱；单次最长运行 15 分钟。
常见用法
API 后端、处理 S3 上传的文件、定时任务

AI组 · PaaS · 按小时 · 售价 $460
在这里
调 SageMaker AI 的推理端点算推荐

常见用法
训练自己的模型、部署推理服务

04DynamoDB必须几选一

数据库组 · Serverless · 按用量 · 售价 $240
在这里
推荐结果写进 DynamoDB 或 ElastiCache
为什么用它
访问方式固定、并发特别高时用它：没有数据库服务器要管，读写延迟稳定在毫秒级
它是什么
Serverless 的键值和文档数据库：毫秒级读写，按需模式按请求收费，数据自动存在多个 AZ；全局表可以多区域同时读写。
常见用法
用户会话、购物车、游戏数据、高并发场景
DynamoDB 的知识点 →

04ElastiCache必须几选一

数据库组 · PaaS · 按小时 · 售价 $300
在这里
推荐结果写进 DynamoDB 或 ElastiCache
为什么用它
同样的数据被反复读时放一层内存缓存：亚毫秒返回，数据库压力小很多
它是什么
托管的内存缓存：Valkey、Redis OSS、Memcached，读写在微秒到毫秒级，挡在数据库前面扛热点读。
常见用法
缓存热点数据、会话、排行榜
ElastiCache 的知识点 →
这一环怎么选

推荐结果要持久保存、按用户查，选 DynamoDB；要亚毫秒延迟、丢了能重算，选 ElastiCache
