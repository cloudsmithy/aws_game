每一块干什么8 块服务

01Cognito可选

安全组 · 托管服务 · 按用量 · 售价 $80
在这里
ALB 先让没登录的用户去 Cognito 登录
为什么用它
登录这件事不用自己写：密码存储、MFA、找回密码、社交登录都是现成的，还能直接给 API Gateway 和 ALB 做鉴权
它是什么
给你的 App 和网站管用户登录：用户池存账号，负责注册、登录、MFA，登录后发 JWT 令牌；身份池把登录的用户换成临时的亚马逊云科技凭证，App 可以直接访问 S3 这类服务。按月活跃用户（MAU）计费。
常见用法
App 和网站的注册登录、给 API 加登录校验（API Gateway、ALB 都能直接认 Cognito 的令牌）、手机 App 直传文件到 S3

02ELB必须

网络组 · 托管服务 · 按小时 · 售价 $140
在这里
ELB 分发流量
为什么用它
多台后端前面放一个统一入口：自动分流量、绕开坏掉的实例，天生跨 AZ
它是什么
负载均衡：把流量分给后面多台 EC2、容器或 Lambda，自动绕开不健康的；ALB 处理 HTTP/HTTPS，NLB 处理 TCP/UDP。
常见用法
网站和 API 的统一入口、多 AZ 高可用
ELB 的知识点 →

03EC2必须几选一

计算组 · IaaS · 按小时 · 售价 $100
在这里
EC2 或 ECS 跑应用
为什么用它
要完全掌控操作系统、装特殊软件、跑老应用时用它，机型最全
它是什么
云上的虚拟服务器：自己选 CPU、内存和操作系统，按秒计费，可以用按需、Savings Plans、Spot 等方式买。每台实例在一个 AZ 里，要高可用得在多个 AZ 各放几台，配合 ELB 和 Auto Scaling。
常见用法
跑各种应用、需要完全控制操作系统的场景
EC2 的知识点 →

03ECS必须几选一

容器组 · 容器 · 按小时 · 售价 $180
在这里
EC2 或 ECS 跑应用
为什么用它
想跑容器又不想学 Kubernetes 时选它，配 Fargate 连机器都不用管
它是什么
亚马逊云科技自己的容器编排服务：告诉它要跑几个任务，它负责调度、替换坏掉的；底层可以用 EC2，也可以用 Fargate（不用管服务器）。
常见用法
微服务、批处理任务
ECS 的知识点 →
这一环怎么选

要完全掌控操作系统、跑老应用，用 EC2；已经容器化、想省心，用 ECS（配 Fargate 连机器都不用管）

04ElastiCache必须

数据库组 · PaaS · 按小时 · 售价 $300
在这里
先查 ElastiCache 里的热点数据
为什么用它
同样的数据被反复读时放一层内存缓存：亚毫秒返回，数据库压力小很多
它是什么
托管的内存缓存：Valkey、Redis OSS、Memcached，读写在微秒到毫秒级，挡在数据库前面扛热点读。
常见用法
缓存热点数据、会话、排行榜

05RDS必须几选一

数据库组 · PaaS · 按小时 · 售价 $280
在这里
没命中再去查 RDS、Aurora 或 DynamoDB
为什么用它
要关系库又不想自己运维时用它：备份、补丁、多 AZ 故障切换都托管，引擎选择最多
它是什么
托管的关系数据库：支持 MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2，帮你做备份、打补丁和故障切换。多 AZ 部署会在另一个 AZ 放一台备用实例。
常见用法
传统业务系统、电商订单库
RDS 的知识点 →

05Aurora必须几选一

数据库组 · PaaS · 按小时 · 售价 $280
在这里
没命中再去查 RDS、Aurora 或 DynamoDB
为什么用它
要更高性能和可用性的 MySQL、PostgreSQL 时选它：存储自动跨 3 个 AZ，只读副本延迟低
它是什么
亚马逊云科技自研的云原生关系数据库，兼容 MySQL 和 PostgreSQL：数据在 3 个 AZ 里存 6 份，最多 15 个只读副本；Aurora Serverless v2 按负载自动伸缩，Global Database 能跨区域。
常见用法
高并发的核心业务数据库

05DynamoDB必须几选一

数据库组 · Serverless · 按用量 · 售价 $240
在这里
没命中再去查 RDS、Aurora 或 DynamoDB
为什么用它
访问方式固定、并发特别高时用它：没有数据库服务器要管，读写延迟稳定在毫秒级
它是什么
Serverless 的键值和文档数据库：毫秒级读写，按需模式按请求收费，数据自动存在多个 AZ；全局表可以多区域同时读写。
常见用法
用户会话、购物车、游戏数据、高并发场景
DynamoDB 的知识点 →
这一环怎么选

按键读写、超高并发选 DynamoDB；要 SQL 和事务选 Aurora（性能、高可用更好）或 RDS（引擎更多、更便宜）
