每一块干什么5 块服务

01API Gateway必须

网络组 · Serverless · 按用量 · 售价 $220
在这里
API Gateway 接下单请求
为什么用它
不用自己搭网关：鉴权、限流、缓存、版本管理开箱就有，后面直接接 Lambda
它是什么
托管的 API 入口：创建 REST、HTTP、WebSocket API，负责鉴权、限流和缓存，后面接 Lambda 或其他服务，按调用次数收费。
常见用法
Serverless API、移动应用和小程序后端
API Gateway 的知识点 →

02Step Functions必须

应用集成组 · Serverless · 按用量 · 售价 $260
在这里
Step Functions 按步骤编排：扣库存、扣款、建发货单
为什么用它
多步骤的流程不用自己写状态机：每一步的重试、超时、失败回滚都能配，执行到哪一步看得见
它是什么
可视化的工作流编排：把 Lambda、容器任务和各种服务的 API 调用串成状态机，自带重试、分支、并行，还能停下来等人工审批。
常见用法
订单处理流程、数据处理流水线、编排 AI Agent 的步骤
Step Functions 的知识点 →

03Lambda必须

计算组 · Serverless · 按用量 · 售价 $220
在这里
每一步由 Lambda 执行
为什么用它
代码不多、按事件触发的活交给它：不用管服务器和扩容，没请求就不花钱
它是什么
无服务器函数：上传代码，有事件来才运行，按请求次数和运行时长（毫秒）收费，没请求不收钱；单次最长运行 15 分钟。
常见用法
API 后端、处理 S3 上传的文件、定时任务
Lambda 的知识点 →

04DynamoDB必须

数据库组 · Serverless · 按用量 · 售价 $240
在这里
订单状态记在 DynamoDB
为什么用它
访问方式固定、并发特别高时用它：没有数据库服务器要管，读写延迟稳定在毫秒级
它是什么
Serverless 的键值和文档数据库：毫秒级读写，按需模式按请求收费，数据自动存在多个 AZ；全局表可以多区域同时读写。
常见用法
用户会话、购物车、游戏数据、高并发场景
DynamoDB 的知识点 →

05SQS可选

应用集成组 · Serverless · 按用量 · 售价 $240
在这里
发货任务放进 SQS
为什么用它
前后两段处理速度不一样时放一个队列：峰值先排队，后端按自己的节奏取，失败的还能重试
它是什么
托管的消息队列：生产者把消息放进队列，消费者按自己的速度取。标准队列至少送达一次，FIFO 队列保证顺序。
常见用法
订单削峰填谷、把系统拆开互不拖累、异步任务
