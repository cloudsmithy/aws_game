服务知识点/存储组/EFS

SERVICE存储组 · Serverless

EFS

存储组Serverless按用量自带跨 AZ 高可用

托管的共享文件系统（NFS）：多台 EC2、容器、Lambda 能同时挂载同一个目录，容量随写随涨，按用了多少收费。

常见用法

多台服务器共用的文件、内容管理、机器学习训练数据

为什么用它

多台机器要读写同一批文件时，不用自己搭 NFS 服务器，容量随用随长

核心知识点5 条

  1. 托管的 NFS 文件系统，EC2、ECS、EKS、Lambda 都能挂载，多台同时读写同一批文件
  2. 区域型文件系统的数据跨多个 AZ 存储，每个 AZ 放一个挂载目标；也有只在一个 AZ 的单区版，更便宜
  3. 存储类别有 Standard、Infrequent Access、Archive，生命周期管理自动把不常用的文件转冷
  4. 吞吐模式：弹性（按实际用量自动伸缩）、预置、突增
  5. 按实际存的量付费，不用预先分配容量；Windows 共享盘用 FSx for Windows File Server

1.EFS 和 EBS 最大的区别是？
答案EFS 能被多台实例同时挂载，EBS 卷一般只挂一台
EBS 有多重挂载，但只限部分卷类型和同一个 AZ
2.EFS 是什么类型的存储？
答案共享文件系统，多台实例能同时挂载
EFS 用 NFS 协议，按用量自动伸缩
3.S3、EFS 这类服务要不要自己做多 AZ？
答案不用，默认就跨多个 AZ 存数据
S3 标准存储类至少在 3 个 AZ 里存数据；单区类型如 S3 One Zone-IA、EFS One Zone 例外
4.同一区域里分布在多个可用区的多台 EC2 实例需要同时通过 NFS 访问同一个共享文件系统。应选择哪项服务？CLF-C02
答案Amazon Elastic File System（Amazon EFS）
EFS 支持多个 NFS 客户端并发访问，同一区域多个可用区的计算实例都能访问，适合共享数据。EBS 快照是卷的时间点备份，不能直接作为共享文件系统挂载。　官方文档 ↗
5.某内容管理系统运行在跨三个可用区的 Linux EC2 Auto Scaling 组上，所有实例都要同时读写同一组文件，存储容量需要随文件增减自动伸缩。应选择哪种存储？SAA-C03
答案Amazon EFS 区域文件系统，并在每个可用区创建挂载目标
EFS 是基于 NFS 的托管共享文件系统，区域文件系统跨多个可用区冗余存储，可被大量实例并发访问，容量随文件增减自动伸缩。各自的 EBS 卷彼此不共享，同步脚本复杂易错；FSx for Windows 面向 SMB 和 Windows 工作负载；实例存储是临时存储。　官方文档 ↗
