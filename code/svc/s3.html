服务知识点/存储组/S3

SERVICE存储组 · Serverless

S3

存储组Serverless按用量自带跨 AZ 高可用

对象存储：文件当成「对象」放进桶里，按存的数据量和请求次数收费，容量不用提前规划。标准存储类会把数据存到一个区域里至少 3 个 AZ。

常见用法

网站图片和静态资源、数据湖、备份归档、日志

为什么用它

不用规划容量，存多少付多少，数据持久性 11 个 9；越放越冷的数据还能自动转到更便宜的存储类别

核心知识点6 条

  1. 对象存储：数据按「桶 + 键」存取，不是文件系统，也不是挂在机器上的磁盘
  2. 存储类别从热到冷：S3 Standard、Intelligent-Tiering、Standard-IA、One Zone-IA、Glacier Instant Retrieval、Glacier Flexible Retrieval、Glacier Deep Archive，越冷越便宜，取回越慢或要另付取回费
  3. 2020 年 12 月起读写都是强一致的：写完马上读，读到的就是新数据
  4. 新建的桶默认开启 Block Public Access、禁用 ACL，新对象默认用 SSE-S3 加密
  5. 版本控制、生命周期规则、对象锁定（一次写入多次读取）配合起来，防误删、防勒索
  6. 事件通知能直接触发 Lambda，或者发到 SQS、SNS、EventBridge

和谁比、怎么选

EFS 还是 S3

训练数据量大、按文件整块读，放 S3（便宜）；多台机器要像本地磁盘一样共享读写，用 EFS

OpenSearch 还是 Redshift 还是 S3

便宜地长期存、离线分析，放 S3 数据湖；要秒级 SQL 报表，进 Redshift；要实时检索，进 OpenSearch

答对 0 / 8，已答 0

1.私有子网里的实例访问 S3，怎么做不走 NAT 网关、不付流量处理费？
答案建 S3 网关终端节点
S3 和 DynamoDB 的网关终端节点不收费
2.S3 里很少访问、但要保留多年的归档数据，放哪个存储类最便宜？
答案S3 Glacier Deep Archive
标准取回 12 小时内、批量 48 小时内，比 Flexible Retrieval 慢得多；最少存 180 天
3.S3、EFS 这类服务要不要自己做多 AZ？
答案不用，默认就跨多个 AZ 存数据
S3 标准存储类至少在 3 个 AZ 里存数据；单区类型如 S3 One Zone-IA、EFS One Zone 例外
4.S3 标准存储的设计耐久性是多少？
答案99.999999999%（11 个 9）
耐久性 11 个 9；可用性是另一回事
5.单个 S3 对象最大可以多大？
答案50 TB
2025 年 12 月从 5 TB 提到 50 TB；单次 PUT 最大 5 GB，更大要用分段上传
6.2023 年 4 月起，新建的 S3 桶默认是什么状态？
答案开启 Block Public Access、禁用 ACL
想公开要自己显式关掉 Block Public Access
7.S3 智能分层（Intelligent-Tiering）的特点是？
答案按访问频率自动换存储层，不收取回费
适合访问规律说不准的数据，按对象收一点监控费
8.用 Athena 查询 S3 上的数据，怎么最省钱？
答案用 Parquet 这类列式格式并分区
Athena 按扫描的数据量收费，扫得越少越便宜
