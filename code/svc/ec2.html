服务知识点/计算组/EC2

SERVICE计算组 · IaaS

EC2

计算组IaaS按小时要自己做多 AZ

云上的虚拟服务器：自己选 CPU、内存和操作系统，按秒计费，可以用按需、Savings Plans、Spot 等方式买。每台实例在一个 AZ 里，要高可用得在多个 AZ 各放几台，配合 ELB 和 Auto Scaling。

常见用法

跑各种应用、需要完全控制操作系统的场景

为什么用它

要完全掌控操作系统、装特殊软件、跑老应用时用它，机型最全

核心知识点5 条

  1. 虚拟服务器，按实例类型选 CPU、内存、网络：通用型 M、计算优化 C、内存优化 R、GPU 实例 P 和 G 等
  2. 买法：按需、Savings Plans、预留实例、Spot（用闲置算力，最多省九成，回收前两分钟通知）、专用主机
  3. 一台实例只在一个 AZ 里；高可用靠跨多个 AZ 的 Auto Scaling 组加负载均衡
  4. 安全组是实例级、有状态的防火墙；访问云上服务用 IAM 角色（实例配置文件），别把访问密钥写进机器
  5. 实例存储（instance store）停机数据就没了，要留的数据放 EBS

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

自动 AMI

用 Data Lifecycle Manager 按计划给实例做 AMI（连同挂着的 EBS 卷），实例坏了、被误删了，直接用镜像再起一台

游戏里：免疫误删数据

LV.2 · 第 2 级

跨 AZ Auto Scaling

Auto Scaling 组跨几个 AZ 放实例，按 CPU 或请求数自动加减；一个 AZ 出问题，别的 AZ 里的实例顶上

游戏里：免疫「EC2 实例硬件退役」；扛住 AZ 断电和单点故障；扛住流量暴增

LV.3 · 第 3 级

Graviton

换成 Arm 架构实例，同样性能更便宜

游戏里：运行费或请求费减半

和谁比、怎么选

EC2 还是 ECS

要完全掌控操作系统、跑老应用，用 EC2；已经容器化、想省心，用 ECS（配 Fargate 连机器都不用管）

EC2 还是 ECS 还是 EKS

要完全掌控操作系统用 EC2；容器化了想省心用 ECS；团队熟 Kubernetes 选 EKS

1.EC2 Spot 实例被中断前会提前多久通知？
答案2 分钟
可以通过实例元数据或 EventBridge 收到中断通知
2.Linux EC2 按秒计费，最低按多久算？
答案60 秒
按秒计费，最低 60 秒
3.EC2 实例 Stop 之后还收什么钱？
答案EBS 卷存储费和弹性 IP 费
停机只停算力费用，存储照收
4.EC2 Auto Scaling 组想跨 AZ 高可用，要怎么配？
答案选多个 AZ 的子网
实例会自动在这些 AZ 之间平衡
5.OpenSearch Service 的域能像 EC2 一样 Stop 吗？
答案不能，只能删除
不用了就删域，删之前先拍快照
6.同一个 AZ 内的 EC2 用私有 IP 互传数据，收费吗？
答案免费
跨 AZ 才开始收数据传输费；走公网 IP 或弹性 IP 互传也要收费
7.责任共担模型里，客户负责什么？
答案自己的数据和权限，用 EC2 时的系统补丁
服务越托管，客户要管的越少
8.根据责任共担模型，客户在 Amazon EC2 上运行应用时，以下哪项是客户的责任？CLF-C02
答案给客户机操作系统打更新和安全补丁
使用 EC2 时，客户负责客户机操作系统（含更新和安全补丁）、应用软件以及安全组配置。物理设施、硬件和网络属于亚马逊云科技负责的「云本身的安全」。　官方文档 ↗
