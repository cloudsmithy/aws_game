核心知识点5 条

  1. 兼容 MySQL 和 PostgreSQL 的云原生数据库：存储层在 3 个 AZ 里存 6 份，按用量自动增长
  2. 最多 15 个低延迟只读副本，主实例出问题时副本自动提升成主库
  3. Aurora Serverless v2 按负载自动扩缩容量（ACU）
  4. Global Database 跨区域复制，延迟通常不到 1 秒，可以做区域级灾备
  5. Zero-ETL 集成能把数据近实时同步进 Redshift 做分析

三个关键功能游戏里的三级升级，就是现实里的这三个功能

和谁比、怎么选

Aurora 还是 DynamoDB

按键读写、并发特别高、访问方式固定，选 DynamoDB；要 SQL、事务、多表关联，选 Aurora（Serverless v2 会自动扩缩）

Aurora 还是 RDS

Aurora 兼容 MySQL 和 PostgreSQL，性能和高可用更好（存储跨 3 个 AZ）；要 SQL Server、Oracle，或者想省钱，用 RDS

Aurora 还是 DynamoDB 还是 RDS

按键读写、超高并发选 DynamoDB；要 SQL 和事务选 Aurora（性能、高可用更好）或 RDS（引擎更多、更便宜）

Aurora 还是 OpenSearch

向量多、要关键词加向量的混合检索，选 OpenSearch；已经在用 PostgreSQL、数据量不大，选 Aurora（pgvector）

答对 0 / 6，已答 0

1.Aurora 的存储默认怎么保存数据？
答案跨 3 个 AZ 存 6 份
存储层自动复制，和计算分离
2.Aurora Serverless v2 的特点是？
答案按负载自动增减容量（ACU）
适合负载波动大的业务
3.把 Oracle 迁到 Aurora PostgreSQL，表结构和存储过程用什么转换？
答案DMS Schema Conversion（以前是 SCT）
异构迁移先用 DMS Schema Conversion 或 SCT 转换表结构和代码对象，数据再由 DMS 复制任务搬过去
4.Aurora 全球数据库跨 Region 复制的延迟通常是？
答案1 秒以内
主 Region 出问题时，可以把备用 Region 提升为主
5.一家全球化 SaaS 公司使用 Amazon Aurora MySQL，需要在第二个区域提供低延迟读取，并且在主区域故障时只丢失极少的数据（约 1 秒级）即可在该区域恢复写入。哪种方案最合适？SAA-C03
答案Aurora 全球数据库，在第二个区域加辅助集群
Aurora 全球数据库使用专用基础设施跨区域复制，延迟通常低于 1 秒，辅助区域可提供本地读取，并支持跨区域切换或故障转移。同区域副本无法抵御区域故障；每小时快照和每日 DMS 迁移的 RPO 远大于要求。　官方文档 ↗
6.某应用使用 Amazon Aurora PostgreSQL，报表查询占用了写入实例的大量资源。公司希望把只读查询分流出去，而且以后增减副本时不必修改应用的连接配置。应如何做？SAA-C03
答案添加 Aurora 副本，让报表查询连接集群的读取器终端节点
读取器终端节点会在所有 Aurora 副本之间均衡只读连接，增减副本无需修改应用配置。集群终端节点指向写入实例；频繁从快照恢复的集群数据不实时且运维复杂；只纵向扩展写入实例无法隔离报表负载。　官方文档 ↗
