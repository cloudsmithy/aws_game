RDS

数据库组PaaS按小时要自己做多 AZ

托管的关系数据库：支持 MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2，帮你做备份、打补丁和故障切换。多 AZ 部署会在另一个 AZ 放一台备用实例。

常见用法

传统业务系统、电商订单库

为什么用它

要关系库又不想自己运维时用它：备份、补丁、多 AZ 故障切换都托管，引擎选择最多

核心知识点5 条

  1. 托管关系数据库，引擎有 MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2
  2. 多 AZ 部署：同步复制到另一个 AZ 的备用实例，主库出问题自动切换（备用实例平时不接读请求）
  3. 只读副本：异步复制，分担读流量，可以放到别的区域
  4. 自动备份加时间点恢复，备份最长保留 35 天；手动快照能长期留
  5. RDS Proxy 复用数据库连接，适合 Lambda 这种连接多、时间短的调用方

和谁比、怎么选

Aurora 还是 RDS

Aurora 兼容 MySQL 和 PostgreSQL，性能和高可用更好（存储跨 3 个 AZ）；要 SQL Server、Oracle，或者想省钱，用 RDS

Aurora 还是 DynamoDB 还是 RDS

按键读写、超高并发选 DynamoDB；要 SQL 和事务选 Aurora（性能、高可用更好）或 RDS（引擎更多、更便宜）

4.某公司的生产数据库运行在 Amazon RDS for MySQL 上，全天候运行，未来 3 年内实例类型和区域都不会变。如何降低数据库成本？SAA-C03
答案为该数据库购买 3 年期 RDS 预留数据库实例
RDS 预留数据库实例以 1 年或 3 年期限换取相对按需价格的显著折扣，适合长期稳定运行的实例。在 Spot 上运行生产数据库有中断风险且运维更重；全天候运行的生产库不能夜间停机；RDS 的存储不能使用 S3 存储类。　官方文档 ↗
5.为 Amazon RDS 启用只带一个备用实例的 Multi-AZ 数据库实例部署，主要好处是什么？CLF-C02
答案备用实例在另一个可用区，故障时自动切换
带一个备用实例的 Multi-AZ 部署提供故障转移支持，但备用实例不承担读流量。想扩展读性能应考虑只读副本等其他方案。　官方文档 ↗
6.某应用使用 Amazon RDS for MySQL，数据库密码目前硬编码在配置文件中。公司要求集中存储凭证并定期自动轮换，同时尽量减少自研代码。应采用哪种方案？SAA-C03
答案将凭证存入 Secrets Manager 并启用自动轮换，应用在运行时通过 API 读取
Secrets Manager 可集中存储凭证并内置自动轮换（托管轮换或 Lambda 轮换函数），应用按需读取最新值。Parameter Store 方案需要自写轮换脚本；KMS 密钥轮换只更换加密密钥材料，不会修改数据库密码。　官方文档 ↗
7.某电商公司的订单数据库运行在单个 Amazon RDS for PostgreSQL 实例上。公司要求可用区故障时能自动故障转移，并尽量不丢失已提交的数据，不需要额外的读取扩展能力。应如何改造？SAA-C03
答案将该数据库实例转换为多可用区（Multi-AZ）部署
多可用区部署会在另一个可用区维护同步复制的备用实例，主实例故障时自动故障转移。只读副本是异步复制，需手动提升且可能丢失最新数据；每小时快照的 RPO 长达一小时，恢复也需要人工操作。　官方文档 ↗
8.某新闻网站的 Amazon RDS 数据库因大量重复执行相同的热门查询而 CPU 居高不下，这些查询结果几分钟内几乎不变。如何在尽量不改动数据库的前提下提升读取性能？SAA-C03
答案用 ElastiCache 缓存热门查询结果
ElastiCache 提供托管的内存缓存，缓存重复的热门查询结果可以显著降低数据库负载和读取延迟。多可用区数据库实例的备用实例不处理读取；多可用区数据库集群的读取器实例虽能分担读取，但得迁移成新集群，热门查询也还是每次都要重新执行；st1 是 HDD，不适合数据库随机 I/O；换成 T 系列只是改变 CPU 的计费和突增方式，重复执行的热门查询负载依然存在。　官方文档 ↗
