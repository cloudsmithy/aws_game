SERVICE数据库组 · PaaS

DMS

数据库组PaaS按小时要自己做多 AZ

数据库迁移服务：把机房或别的云上的数据库搬到亚马逊云科技，同构（MySQL 到 RDS for MySQL）、异构（Oracle 到 Aurora PostgreSQL）都行；全量搬完以后还能持续抓源库的变更（CDC），新旧库一直对得上，割接时停机很短。按复制实例的小时计费，也有按用量的 DMS Serverless。

常见用法

数据库上云、把业务库的改动实时同步到数据湖、搜索或数仓（CDC）

为什么用它

源库不用改代码：先全量复制，再持续抓变更（CDC），迁移割接停机短；平时也能把改动实时同步到搜索、数据湖或数仓

核心知识点5 条

  1. 数据库迁移服务：先全量复制，再持续复制变更（CDC），迁移期间源库照常对外服务
  2. 同构迁移（MySQL 到 RDS for MySQL）直接搬；异构迁移（Oracle 到 Aurora PostgreSQL）先用 Schema Conversion 转表结构和存储过程
  3. 复制实例跑在你的 VPC 里；也可以用 DMS Serverless 按用量自动扩缩
  4. 目标不只是数据库，还能是 S3、Kinesis、OpenSearch、Redshift，用来同步数据湖、搜索和数仓
  5. 能做数据校验，核对源库和目标库的数据是否一致

三个关键功能游戏里的三级升级，就是现实里的这三个功能

1.用 DMS 迁数据库，想让新旧库在割接前一直对得上，要开什么？
答案全量加载完以后接着做 CDC 持续复制
DMS 全量搬完以后持续抓源库的变更（CDC）应用到新库，割接时只要停很短的时间
2.把 Oracle 迁到 Aurora PostgreSQL，表结构和存储过程用什么转换？
答案DMS Schema Conversion（以前是 SCT）
异构迁移先用 DMS Schema Conversion 或 SCT 转换表结构和代码对象，数据再由 DMS 复制任务搬过去
