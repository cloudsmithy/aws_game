Athena

分析组Serverless按用量自带跨 AZ 高可用

Serverless 交互式查询：直接用 SQL 查 S3 里的数据，不用建集群，按扫描的数据量收费。数据存成列式格式、按日期分区，能少扫很多、省钱。

常见用法

日志分析、数据湖临时查询

为什么用它

偶尔查一查 S3 里的数据时最省事：不用建库、不用管服务器，按扫描的数据量付费

核心知识点5 条

  1. 用标准 SQL 直接查 S3 里的数据，不用建集群，按扫描的数据量计费
  2. 表结构存在 Glue 数据目录；支持 CSV、JSON、Parquet、ORC、Apache Iceberg 等格式
  3. 省钱又提速：转成 Parquet 这类列式格式、压缩、按日期分区，少扫数据
  4. 联合查询能顺带查 DynamoDB、RDS 等别的数据源
  5. 常用来分析 ALB、CloudFront、CloudTrail 的日志

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

分区投影

按规则直接算出分区位置，不用查数据目录；配合分区只扫需要的数据，扫得少花得少

游戏里：运行费或请求费减半

LV.2 · 第 2 级

查询结果复用

同样的查询直接用上次的结果

游戏里：这块过路费再 +20%

LV.3 · 第 3 级

联合查询

一条 SQL 同时查 S3、数据库、日志等多个数据源

游戏里：过路费提高

1.用 Athena 查询 S3 上的数据，怎么最省钱？
答案用 Parquet 这类列式格式并分区
Athena 按扫描的数据量收费，扫得越少越便宜
2.Athena 默认（按需）模式下按什么收费？
答案按每次查询扫描的数据量
用列式格式和分区能大幅减少扫描量
3.某公司每天通过 Amazon Data Firehose 把数 TB 的 JSON 点击日志写入 S3，分析师用 Amazon Athena 查询。大多数查询只涉及最近几天和少数几个字段，但费用很高。如何最有效地降低查询成本？SAA-C03
答案用 Glue 作业把数据转换为 Apache Parquet 列式格式，并按日期分区
Athena 按扫描的数据量计费：列式格式让查询只读取需要的列，按日期分区让查询只扫描相关分区，两者都能大幅减少扫描量。改存储类会增加取回费用且不减少扫描量；自建数据库增加常驻成本和运维；跨区域复制只会增加存储和传输费用。　官方文档 ↗
