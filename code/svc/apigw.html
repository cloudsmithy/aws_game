API Gateway

网络组Serverless按用量自带跨 AZ 高可用

托管的 API 入口：创建 REST、HTTP、WebSocket API，负责鉴权、限流和缓存，后面接 Lambda 或其他服务，按调用次数收费。

常见用法

Serverless API、移动应用和小程序后端

为什么用它

不用自己搭网关：鉴权、限流、缓存、版本管理开箱就有，后面直接接 Lambda

核心知识点5 条

  1. 三种 API：REST API（功能最全：用量计划、API 密钥、请求校验、缓存）、HTTP API（更便宜、更快、功能少一些）、WebSocket API
  2. 鉴权：IAM、Cognito 用户池、Lambda 授权方，HTTP API 还能直接验 JWT
  3. 节流限流和用量计划防刷；REST API 能开响应缓存
  4. 端点类型：边缘优化、区域、私有（只能在 VPC 里通过接口终端节点访问）
  5. 集成超时默认 29 秒，跑得久的活改成异步处理

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

使用计划限流

按阶段和 API 密钥限制请求速率，突发请求不会全压到后端；官方说明这是尽力而为，防 DDoS 要靠 WAF

游戏里：免疫「接口被恶意刷爆」（安全攻防 DLC）；性能效率支柱 +1 分

运行费：收到过路费时交 15% 请求费

LV.2 · 第 2 级

接入认证

用 Cognito 用户池、Lambda 授权方或 IAM 校验调用方：没登录、没权限的请求在网关就被挡掉，到不了后端

游戏里：免疫「安全审计没过」

运行费：收到过路费时交 15% 请求费

LV.3 · 第 3 级

缓存

把响应缓存起来，少调后端，响应更快；缓存按小时收费

游戏里：这块过路费再 +20%

运行费：每圈 $10，收到过路费时交 15% 请求费

1.想让 API Gateway 只放行登录过的用户，最省事的做法是？
答案给 API 配 Cognito 用户池授权方，请求带上登录拿到的令牌
API Gateway 的 Cognito 授权方（HTTP API 用 JWT 授权方）先验令牌，没登录或令牌过期的请求在网关就被挡回去，Lambda 里不用写验证逻辑
2.API Gateway 支持哪几类 API？
答案REST、HTTP、WebSocket
HTTP API 更便宜、更轻量；GraphQL 要用 AppSync
3.WAF 可以挂在哪些服务前面？
答案CloudFront、ALB、API Gateway
WAF 管第 7 层；API Gateway 只能挂 REST API，另外还能挂 AppSync、Cognito 用户池等
