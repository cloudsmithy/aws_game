SERVICE应用集成组 · Serverless

EventBridge

应用集成组Serverless按用量自带跨 AZ 高可用

Serverless 事件总线：把亚马逊云科技服务、自己的应用和 SaaS 发出的事件按规则转给 Lambda、Step Functions 等，也能定时触发。

常见用法

事件驱动架构、跨账户分发事件、定时任务

为什么用它

发事件的和处理事件的互不认识：多加一个处理方不用改发送方，还能按时间表触发

核心知识点5 条

  1. Serverless 事件总线：亚马逊云科技服务的事件、自己应用的事件、SaaS 合作伙伴的事件都能进来
  2. 规则按事件内容（事件模式）过滤，再转给 Lambda、SQS、Step Functions 等目标
  3. EventBridge Scheduler：按 cron 表达式或固定频率定时触发，能直接调很多服务的 API，不用写 Lambda
  4. Pipes：把 SQS、Kinesis、DynamoDB Streams 这类源点对点接到目标，中间能过滤、转换
  5. 能归档事件、事后重放；Schema Registry 自动发现事件结构

三个关键功能游戏里的三级升级，就是现实里的这三个功能

1.EventBridge 主要用来做什么？
答案接收事件并按规则路由给目标
能接亚马逊云科技服务、SaaS 和自己应用发出的事件
2.EventBridge 全局端点（Global Endpoints）用来做什么？
答案主 Region 故障时，事件切到备用 Region
配合 Route 53 健康检查自动故障转移
3.GuardDuty 发现异常后，想自动隔离实例，常见做法是？
答案EventBridge 规则触发 Lambda 处置
也可以触发 Step Functions 编排多步处置，这就是「威胁自动响应」架构
4.某公司的多个微服务会发布订单状态变更事件。要求按事件内容（例如 status 字段为 CANCELLED）把事件路由到不同目标（如 Lambda、Step Functions），新增消费者时不修改发布方代码，并尽量少写路由代码。应使用哪项服务？SAA-C03
答案Amazon EventBridge 事件总线，为每类消费者创建带事件模式的规则
EventBridge 规则用事件模式按内容匹配事件并路由到目标，新增消费者只需增加规则。发布方硬编码路由会造成耦合；Kinesis 需要各消费者自行读取和过滤；自建代理运维开销大。　官方文档 ↗
