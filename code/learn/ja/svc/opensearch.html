OpenSearch

分析グループPaaS時間課金マルチ AZ は自前で構成

マネージドな OpenSearch（Elasticsearch から派生したオープンソースプロジェクト）：全文検索、ログ分析、可視化を行い、ベクトルデータベースとしても使えます。

主な用途

サイト内検索、ログ検索、RAG のベクトル検索

使う理由

全文検索、あいまい検索、ログのリアルタイム検索が必要なときに使います。これらをリレーショナルデータベースで行うと遅いうえ、データベースに負荷がかかります

重要ポイント5 件

  1. マネージドな OpenSearch（Elasticsearch 7.10 から派生したオープンソースプロジェクト）：全文検索やログ分析に使い、OpenSearch Dashboards で可視化します
  2. 形態は 2 種類：マネージドドメイン（ノードタイプを自分で選ぶ）と OpenSearch Serverless（コレクション単位、自動スケーリング）
  3. ベクトルエンジンで k-NN ベクトル検索ができ、RAG のベクトルデータベースとしてよく使われます
  4. 本番環境では、マルチ AZ 配置と専用のクラスターマネージャーノードが推奨されます。アクセスの少ないデータは UltraWarm やコールドストレージに置いてコストを抑えます
  5. OpenSearch Ingestion はマネージドなデータパイプラインで、S3 や DynamoDB（Zero-ETL）などからデータを取り込めます

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

比較と選び方

OpenSearch と Redshift

全文検索やログのリアルタイム検索なら OpenSearch、大規模な SQL 分析やレポートなら Redshift を選びます

Aurora と OpenSearch

ベクトルが多く、キーワードとベクトルを組み合わせたハイブリッド検索が必要なら OpenSearch を選びます。すでに PostgreSQL を使っていて、データ量が多くないなら Aurora（pgvector）を選びます

OpenSearch と Redshift と S3

安く長期保存してオフラインで分析するなら S3 のデータレイクに置きます。秒単位で結果が返る SQL レポートが必要なら Redshift に、リアルタイムの検索が必要なら OpenSearch に入れます
