WAF

セキュリティ系マネージド従量課金マルチ AZ 標準対応

ウェブアプリケーションファイアウォール：CloudFront、ALB、API Gateway の前に配置し、ルールに従って SQL インジェクション、クロスサイトスクリプティング、悪意のあるボットをブロックします。IP 単位のレート制限もできます。

主な用途

一般的なウェブ攻撃の防御、API の不正な大量呼び出しの防止

使う理由

入口でルールに従って、SQL インジェクション、XSS、悪意のあるクローラー、API の不正な大量呼び出しをブロックします。アプリケーションのコードを変更する必要はありません

重要ポイント5 件

  1. ウェブアプリケーションファイアウォール：CloudFront、ALB、API Gateway、AppSync、Cognito ユーザープールなどの前段に配置します
  2. Web ACL でルールを設定します：IP セット、地理的位置、レート制限（レートベース）、マネージドルールグループ（一般的な脆弱性、既知の不正な入力、SQL インジェクションなど）
  3. Bot Control でクローラーを識別・管理し、Fraud Control でリスト型攻撃や不正なアカウント作成を防ぎます
  4. Web ACL の数、ルール数、リクエスト数に応じて課金されます
  5. 新しいルールはまずカウント（Count）モードで様子を見て、正常なリクエストをブロックしないことを確認してからブロックに切り替えられます

Bot Control

クローラー、スキャナー、ステータスモニター、検索エンジンなどのボットトラフィックを識別し、カウントして観察するだけ、レート制限、ブロックのいずれかを選べます。ターゲット検査レベルなら、身元を名乗らないボットにチャレンジすることもできます

ゲーム内：このマスの通行料がさらに +20%

運用コスト：1 周ごとに $5、通行料を受け取るたびに 15% のリクエスト料金

正解Amazon Web Services またはパートナーが管理する既製のルール

正解ALB に WAF ウェブ ACL を関連付け、レートベースのルールを追加する
WAF のレートベースのルールは IP などの単位でリクエストを集計し、しきい値を超えると自動的にレート制限をかけるため、リストを手作業で管理する必要はありません。セキュリティグループは許可ルールしかサポートしていません。NLB はレイヤー 4 で動作するため、HTTP レイヤーの悪用を識別できません。フローログを手作業で分析してからネットワーク ACL を変更する方法は対応が遅く、運用上のオーバーヘッドも大きくなります。　公式ドキュメント ↗
