DMS

データベース系PaaS時間課金マルチ AZ は自前で構成

データベース移行サービス：オンプレミスや他のクラウドのデータベースを Amazon Web Services に移行します。同種（MySQL から RDS for MySQL）でも異種（Oracle から Aurora PostgreSQL）でも移行できます。全ロードの後もソースデータベースの変更を継続的にキャプチャ（CDC）するので、新旧のデータベースを同期させたまま、切り替え時のダウンタイムを短くできます。レプリケーションインスタンスの時間単位で課金され、従量課金の DMS Serverless もあります。

主な用途

データベースのクラウド移行、業務データベースの変更をデータレイク、検索、データウェアハウスにリアルタイムで同期（CDC）

使う理由

ソースデータベース側のコードを変更する必要はありません：まず全ロードで既存のデータをコピーし、その後は変更を継続的に取り込む（CDC）ので、移行の切り替え時のダウンタイムは短くて済みます。移行時以外にも、変更を検索、データレイク、データウェアハウスにリアルタイムで同期できます

重要ポイント5 件

  1. データベース移行サービス：まず全ロードでデータをコピーし、その後は変更を継続的にレプリケーション（CDC）します。移行中もソースデータベースは通常どおりサービスを提供できます
  2. 同種間移行（MySQL から RDS for MySQL）はそのまま移せます。異種間移行（Oracle から Aurora PostgreSQL）では、先に Schema Conversion でテーブル構造とストアドプロシージャを変換します
  3. レプリケーションインスタンスは自分の VPC 内で実行されます。DMS Serverless を使って、使用量に応じて自動でスケールさせることもできます
  4. ターゲットはデータベースだけでなく、S3、Kinesis、OpenSearch、Redshift にもでき、データレイク、検索、データウェアハウスへの同期に使えます
  5. データ検証で、ソースとターゲットのデータが一致しているかを確認できます

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

LV.1 · レベル 1

マルチ AZ レプリケーションインスタンス

レプリケーションインスタンスが別の AZ に同期スタンバイを置き、プライマリのある AZ で問題が起きると自動で切り替わるので、移行と継続的なレプリケーションが止まりません

ゲーム内：AZ の停電と単一障害点に耐える

運用コスト：1 周ごとに $20

LV.2 · レベル 2

DMS Serverless

レプリケーションインスタンスのサイズを自分で選ぶ必要がなく、実際に使ったキャパシティユニット（DCU）に応じて自動でスケールし、使用量に応じて課金されます

ゲーム内：運用コストまたはリクエスト料金が半額

運用コスト：1 周ごとに $15

LV.3 · レベル 3

Schema Conversion

Oracle や SQL Server のスキーマ、ストアドプロシージャ、関数を Aurora PostgreSQL や MySQL で使える形に自動変換するので、データベースエンジンを変えても手作業で書き直す必要がありません

ゲーム内：このマスの通行料がさらに +20%

運用コスト：1 周ごとに $20

1.DMS でデータベースを移行するとき、切り替えまで新旧のデータベースを同期させ続けるには何を有効にしますか？
正解全ロードの完了後に続けて CDC による継続的なレプリケーションを行う
DMS は全ロードの完了後もソースデータベースの変更（CDC）をキャプチャし続けて新しいデータベースに適用するため、切り替え時のダウンタイムはごく短く済みます
2.Oracle を Aurora PostgreSQL に移行するとき、テーブルスキーマとストアドプロシージャは何で変換しますか？
正解DMS Schema Conversion（以前の SCT）
異種間の移行では、まず DMS Schema Conversion または SCT でテーブルスキーマとコードオブジェクトを変換し、データはその後 DMS のレプリケーションタスクで移します

使われるアーキテクチャ3 個

API クエリサービス必須

DMS がデータベースの変更を継続的に OpenSearch へ同期（CDC、RDS 自体は OpenSearch にデータをプッシュできないので、同期は DMS が担う）

データベースの変更をデータレイクへ必須

DMS が RDS または Aurora の変更ログ（CDC：MySQL の binlog、PostgreSQL の WAL）を継続的にキャプチャ。DMS タスクのステータス変化を EventBridge に送り、同期が止まったらすぐにアラート

データベースのクラウド移行必須

DMS がオンプレミスのデータベースを RDS または Aurora に全ロードで移行（エンジンを変える場合は先に Schema Conversion でテーブル構造とストアドプロシージャを変換）し、その後も変更を継続的に同期して新旧データベースを一致させる
