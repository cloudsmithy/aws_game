EFS

ストレージ系サーバーレス従量課金マルチ AZ 標準対応

マネージドな共有ファイルシステム（NFS）：複数の EC2、コンテナ、Lambda から同じディレクトリを同時にマウントできます。容量は書き込みに応じて自動で増え、使った分だけ課金されます。

主な用途

複数のサーバーで共有するファイル、コンテンツ管理、機械学習のトレーニングデータ

使う理由

複数のマシンで同じファイルを読み書きするとき、NFS サーバーを自分で構築する必要がありません。容量は使った分だけ自動で増えます

重要ポイント5 件

  1. マネージドな NFS ファイルシステムで、EC2、ECS、EKS、Lambda のどれからでもマウントでき、複数台から同じファイルを同時に読み書きできます
  2. リージョンファイルシステムのデータは複数の AZ にまたがって保存され、AZ ごとにマウントターゲットを 1 つ置きます。1 つの AZ だけに置く 1 ゾーン版もあり、こちらはより安価です
  3. ストレージクラスには Standard、Infrequent Access、Archive があり、ライフサイクル管理によって、あまり使わないファイルは自動でよりコールドなクラスへ移されます
  4. スループットモード：エラスティック（実際の使用量に応じて自動で拡張・縮小）、プロビジョンド、バースト
  5. 実際に保存した量に応じて支払い、容量を事前に割り当てる必要はありません。Windows の共有ドライブには FSx for Windows File Server を使います

比較と選び方

EFS か S3

トレーニングデータが大量で、ファイル単位でまとめて読むなら S3 に置きます（安価です）。複数のマシンでローカルディスクのように共有して読み書きしたいなら EFS を使います

1.EFS と EBS の最大の違いはどれですか？
正解EFS は複数のインスタンスから同時にマウントでき、EBS ボリュームは通常 1 台にしかアタッチしない

2.EFS はどのタイプのストレージですか？
正解共有ファイルシステムで、複数のインスタンスから同時にマウントできる
EFS は NFS プロトコルを使い、使用量に応じて自動的に拡張・縮小します
3.S3 や EFS のようなサービスでは、マルチ AZ を自前で構成する必要がありますか？
正解いいえ、デフォルトで複数の AZ にデータが保存される
S3 標準ストレージクラスは少なくとも 3 つの AZ にデータを保存します。S3 One Zone-IA や EFS One Zone のような単一 AZ のクラスは例外です

正解Amazon Elastic File System（Amazon EFS）
EFS は複数の NFS クライアントからの同時アクセスをサポートし、同じリージョンの複数のアベイラビリティーゾーンにあるコンピューティングインスタンスからアクセスできるため、データの共有に適しています。EBS スナップショットはボリュームのある時点のバックアップで、共有ファイルシステムとして直接マウントすることはできません。　公式ドキュメント ↗

正解Amazon EFS のリージョンファイルシステムを使用し、各アベイラビリティーゾーンにマウントターゲットを作成する
