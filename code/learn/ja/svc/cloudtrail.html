CloudTrail

モニタリンググループ従量課金従量課金ワイルドカードサービス

アカウント内の API コールを記録します：誰が、いつ、どこから、どんな操作をしたか。コンソールではデフォルトで直近 90 日間の管理イベントを確認でき、証跡を作成すると S3 に長期保存できます。

主な用途

セキュリティ監査、誰がリソースを削除したかの調査

使う理由

誰が、いつ、どの API を呼び出したかを記録するので、何か起きたときに追跡できます

重要ポイント5 件

  1. アカウント内の API 呼び出しを記録します：誰が、いつ、どこから、何をしたかを残し、監査やトラブルシューティングに使います
  2. イベント履歴では、デフォルトで過去 90 日間の管理イベントを確認できます。長期間保存するには、証跡（Trail）を作成して S3 に配信します
  3. データイベント（S3 オブジェクトの読み書き、Lambda の呼び出しなど）は個別に有効化する必要があり、別料金です
  4. ログファイルの整合性検証で、ログが改ざんされていないことを証明できます。組織の証跡を使えば、1 つですべてのアカウントをカバーできます
  5. CloudTrail Lake では SQL でイベントをクエリできます

4.ある金融会社は、S3 の機密データを保管時に暗号化することに加え、暗号化キーを使用できる IAM プリンシパルを自社で決定し、キーのローテーションを自社で管理し、CloudTrail でキーの使用状況を監査できることを求めています。すべての要件を満たす方法はどれですか？SAA-C03
正解SSE-KMS でカスタマーマネージド KMS キーを使用し、キーポリシーでアクセスを制御する
カスタマーマネージドキーのキーポリシーは顧客が管理し、自動ローテーションやオンデマンドローテーションを自分で有効にでき、キーの使用は CloudTrail に記録されます。SSE-S3 ではキーの権限を個別に制御できません。Amazon Web Services マネージドキーは、プロパティもキーポリシーも変更できません。ハードコードしたキーは安全でないうえ、一元的な監査もできません。　公式ドキュメント ↗
5.昨夜、ある EC2 インスタンスが何者かによって終了されました。チームは、どのユーザーまたはロールがいつ API を呼び出したのかを突き止めたいと考えています。どのサービスの記録を確認すべきですか？CLF-C02
正解CloudTrail
CloudTrail は、ユーザー、ロール、または Amazon Web Services のサービスが実行した操作を、コンソール、CLI、SDK、API の呼び出しを含めてイベントとして記録するため、「誰が何をしたか」の監査に適しています。CloudWatch メトリクスはリソースのパフォーマンスデータを示すもので、誰が API を呼び出したかは記録しません。　公式ドキュメント ↗
