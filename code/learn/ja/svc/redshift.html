Redshift

分析系PaaS時間課金マルチ AZ は自前で構成

クラウドデータウェアハウス：列指向ストレージと超並列処理で、大量のデータを SQL で分析します。プロビジョニングされたクラスターと Redshift Serverless の 2 つの使い方があります。

主な用途

BI レポート、経営分析

使う理由

データ量が多く、レポートや複雑な SQL が多いときに使います：列指向ストレージと超並列処理で、数十億行でもクエリできます

重要ポイント5 件

  1. クラウドデータウェアハウス：列指向ストレージと超並列処理（MPP）で、複雑な SQL 分析やレポートに向いています
  2. 使い方は 2 種類：プロビジョニングされたクラスター（RA3 ノード、コンピューティングとストレージを別々にスケール）と Redshift Serverless（使用量に応じて課金）
  3. Redshift Spectrum で S3 のデータを直接クエリできます。Zero-ETL 統合で、Aurora、RDS、DynamoDB からほぼリアルタイムに同期できます
  4. ストリーミング取り込みで、Kinesis や MSK から直接データを読み込めます
  5. データ共有を使うと、データをコピーし合わずに、複数のクラスターで同じデータを使えます

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

LV.2 · レベル 2

同時実行スケーリング

クエリが多いときは一時的なクラスターを自動で追加します

ゲーム内：トラフィックの急増に耐える

運用コスト：1 周ごとに $30

LV.3 · レベル 3

Zero-ETL 統合

Aurora、RDS for MySQL、DynamoDB のデータをほぼリアルタイムで Redshift に同期し、ETL パイプラインを自前で構築する必要がありません。同期の方向は Redshift への取り込みで、Redshift のデータをほかで使うにはデータ共有か S3 への UNLOAD を使います

ゲーム内：このマスの通行料がさらに +20%

運用コスト：1 周ごとに $40

比較と選び方

OpenSearch か Redshift

全文検索やログのリアルタイム検索なら OpenSearch、大規模な SQL 分析やレポートなら Redshift を選びます

OpenSearch か Redshift か S3

安く長期保存してオフラインで分析するなら S3 のデータレイクに置きます。秒単位で結果が返る SQL レポートが必要なら Redshift に、リアルタイムの検索が必要なら OpenSearch に入れます
