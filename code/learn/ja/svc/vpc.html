VPC

ネットワーク系マネージド無料マルチ AZ 標準対応ワイルドカードサービス

クラウド上のプライベートネットワーク：IP アドレス範囲、サブネット、ルートテーブル、セキュリティグループを自分で設定し、どのリソースがインターネットにアクセスできるかを決めます。VPC 自体は無料です。

主な用途

外部向けのロードバランサーはパブリックサブネットに、アプリケーションとデータベースはプライベートサブネットに配置

使う理由

リソースを自分のプライベートネットワークに置き、サブネットとセキュリティグループで誰がアクセスできるかを決めます。データベースをインターネットに公開する必要はありません

重要ポイント5 件

  1. 自分専用のプライベートネットワーク：CIDR ブロックを選び、AZ ごとにサブネットを分けます。パブリックサブネットのルートテーブルはインターネットゲートウェイを指します
  2. プライベートサブネットからインターネットに出るには NAT ゲートウェイを経由します（パブリックサブネットに配置し、時間とデータ処理量に応じて課金）
  3. セキュリティグループ：インスタンス単位、ステートフル、許可ルールのみ。ネットワーク ACL：サブネット単位、ステートレス、許可ルールと拒否ルールの両方
  4. VPC エンドポイントを使うと、トラフィックがインターネットに出ません：ゲートウェイエンドポイント（S3、DynamoDB 向け、無料）とインターフェイスエンドポイント（PrivateLink、ほとんどのサービスに対応）
  5. VPC 同士は VPC ピアリング接続か Transit Gateway でつなぎます。VPC フローログで、出入りするトラフィックを記録します

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

LV.1 · レベル 1

プライベートサブネット + NAT

インスタンスをインターネットに直接公開せず、パブリック IPv4 アドレスの料金（2024 年から時間単位で課金）もかかりません。外向きの通信は NAT ゲートウェイを通ります

ゲーム内：インスタンスをプライベートサブネットに配置（NAT ゲートウェイが必要で、費用が増える）

運用コスト：1 周ごとに $20

LV.2 · レベル 2

Session Manager

22 番ポートを開けず、踏み台サーバーも使わずにプライベートサブネットのインスタンスにログインでき、操作はすべて記録されます

ゲーム内：プライベートサブネットと組み合わせて 22 番ポートを閉じ、SSH ブルートフォース攻撃を無効化

運用コスト：1 周ごとに $20

LV.3 · レベル 3

Transit Gateway

複数の VPC と自社のデータセンターを 1 つのネットワークにつなぎます

ゲーム内：このマスの通行料がさらに +20%

運用コスト：1 周ごとに $20

正解Secrets Manager 用のインターフェイス VPC エンドポイントを作成する
Secrets Manager はインターフェイスエンドポイント（PrivateLink）を介した VPC 内からのプライベートなアクセスをサポートしており、インターネットゲートウェイや NAT は不要です。ゲートウェイエンドポイントがサポートするのは S3 と DynamoDB のみです。NAT ゲートウェイではトラフィックがインターネットに出てしまいます。VPC ピアリング接続は推移的なルーティングをサポートしないため、相手側の出口を借りることはできません。　公式ドキュメント ↗
4.ある企業には 40 の VPC と、オンプレミスのデータセンターへの VPN 接続が 1 つあります。すべての VPC がオンプレミスのネットワークにアクセスできるよう一元的に相互接続する必要がありますが、開発用 VPC と本番用 VPC の間はネットワーク的に分離しなければなりません。運用上のオーバーヘッドが最も少ない方法はどれですか？SAA-C03
正解Transit Gateway を使用し、開発用と本番用の VPC を別々のルートテーブルに関連付ける
Transit Gateway は VPC と VPN を接続する中央のハブとして機能し、複数のルートテーブルを使ってネットワークを互いに分離されたルーティングドメインに分割できます。フルメッシュのピアリングは接続数が膨大になり、管理が困難です。VPC ピアリングは推移的なルーティングをサポートしないため、中継用の VPC を経由してオンプレミスにアクセスすることはできません。インターネット経由のアクセスは、プライベートな相互接続という要件を満たしません。　公式ドキュメント ↗
5.ある会社は 1 本の Direct Connect 接続で VPC にアクセスしています。ビジネス上、Direct Connect が中断しても接続を維持する必要がありますが、予算が限られているため、バックアップ回線の信頼性とパフォーマンスが低くても許容できます。最も費用対効果の高い方法はどれですか？SAA-C03
正解バックアップ接続として Site-to-Site VPN を設定する
Site-to-Site VPN はインターネット経由で IPsec トンネルを確立し、信頼性とパフォーマンスが低くなる代わりに、Direct Connect の低コストなバックアップとして利用できます。複数のロケーションで複数の専用接続を用意すると回復力は最も高くなりますが、コストも最も高くなります。VPC ピアリングは VPC 同士を接続するだけで、オンプレミスのデータセンターは接続できません。NAT ゲートウェイはアドレス変換を行うだけで、それ自体は回線ではないため、オンプレミスへのトラフィックは結局 VPN か Direct Connect を通る必要があります。　公式ドキュメント ↗
6.VPC のセキュリティグループとネットワーク ACL について、正しい説明はどれですか？CLF-C02
正解セキュリティグループはステートフルで戻りトラフィックが自動的に許可され、ネットワーク ACL はステートレス
セキュリティグループはステートフルなので戻りトラフィックは自動的に許可され、ネットワーク ACL はステートレスなので戻りトラフィックを明示的に許可する必要があります。公式には、セキュリティグループを主要な制御手段とし、ネットワーク ACL はサブネットレベルの補助的な制御として使うことが推奨されています。　公式ドキュメント ↗
7.プライベートサブネット内の EC2 インスタンスが、NAT ゲートウェイ経由で同じリージョンの Amazon S3 に毎月数十 TB のデータを転送しており、NAT ゲートウェイのデータ処理料金が高額になっています。インスタンスをプライベートに保ったまま、コストを最も効果的に削減するにはどうすればよいですか？SAA-C03
正解S3 用のゲートウェイ VPC エンドポイントを作成し、プライベートサブネットのルートテーブルに追加する
S3 のゲートウェイエンドポイントは、ルートテーブルによってトラフィックを NAT ゲートウェイを経由せずに S3 へ直接送ります。ゲートウェイエンドポイントの利用に追加料金はかかりません。NAT インスタンスは自分で運用する必要があり、単一障害点にもなります。パブリックサブネットへの移動は、プライベートに保つという要件に反します。Transfer Acceleration は長距離の転送を高速化するもので、NAT の料金は削減できません。　公式ドキュメント ↗
