Glue

分析グループServerless従量課金マルチ AZ 標準対応

サーバーレスのデータ統合（ETL）サービス：データソースをクロールしてデータカタログを作成し、Spark ジョブでデータをクレンジング・変換します。実行時間で課金されます。

主な用途

データレイクへのデータ取り込み、Athena や Redshift 向けのデータ準備

使う理由

データのクレンジング、フォーマットの変換、データカタログの作成のために、自分でクラスターを構築する必要はありません。実行時間に応じて支払います

重要ポイント5 件

  1. サーバーレスのデータ統合（ETL）サービス：Spark や Python のジョブでデータをクレンジング・変換します
  2. Glue データカタログはテーブルのスキーマ（メタデータ）を一元的に保存し、Athena、Redshift Spectrum、EMR がいずれもこれを使います
  3. クローラー（Crawler）が S3 などのデータソースを自動でスキャンし、テーブルのスキーマを推論してデータカタログに書き込みます
  4. Glue Studio ではビジュアルにジョブを組み立てられます。Glue DataBrew では画面操作でデータをクレンジングできます
  5. DPU（データ処理ユニット）の稼働時間に応じて課金されます

3.ある企業は毎日 Amazon Data Firehose を使用して数 TB の JSON 形式のクリックログを S3 に書き込み、アナリストが Amazon Athena でクエリしています。ほとんどのクエリは直近数日分の少数のフィールドしか対象にしていませんが、料金が高くなっています。クエリのコストを最も効果的に削減するにはどうすればよいですか？SAA-C03
正解Glue ジョブでデータを列指向形式の Apache Parquet に変換し、日付でパーティション分割する
Athena はスキャンしたデータ量に応じて課金されます：列指向形式ではクエリが必要な列だけを読み取り、日付でパーティション分割するとクエリが関連するパーティションだけをスキャンするため、どちらもスキャン量を大幅に減らせます。ストレージクラスを変更すると取り出し料金が増えるうえ、スキャン量は減りません。自前のデータベースは常時稼働のコストと運用の手間が増えます。クロスリージョンレプリケーションはストレージ料金と転送料金が増えるだけです。　公式ドキュメント ↗
