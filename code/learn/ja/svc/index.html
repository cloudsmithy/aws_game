ストレージ系

3 個

ファイル、オブジェクト、ディスクの保存：データの置き場所とバックアップの方法

S3ストレージ · サーバーレス

オブジェクトストレージ：ファイルを「オブジェクト」としてバケットに保存し、保存したデータ量とリクエスト数に応じて課金されます。容量を事前に計画する必要はありません。S3 Standard ストレージクラスは、1 つのリージョン内の 3 つ以上の AZ にデータを保存します。

EFSストレージ · サーバーレス

マネージドな共有ファイルシステム（NFS）：複数の EC2、コンテナ、Lambda から同じディレクトリを同時にマウントできます。容量は書き込みに応じて自動で増え、使った分だけ課金されます。

EBSストレージ · IaaS

EC2 用のブロックストレージ（クラウドディスク）：ボリュームを同じ AZ のインスタンスにアタッチしてシステムディスクやデータディスクとして使い、スナップショットでバックアップできます。ボリュームは 1 つの AZ 内にのみ存在します。

コンピューティング系

2 個

コードを実行する場所：仮想マシン、またはイベントで動く関数

Lambdaコンピューティング · サーバーレス

サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。

重要ポイント 9問題 8アーキテクチャ 26
EC2コンピューティング · IaaS

クラウド上の仮想サーバー：CPU、メモリ、OS を自分で選び、秒単位で課金されます。オンデマンド、Savings Plans、スポットなどの方法で購入できます。各インスタンスは 1 つの AZ にあるため、高可用性には複数の AZ にそれぞれ数台ずつ配置し、ELB と Auto Scaling を組み合わせます。

ネットワーク系

5 個

トラフィックの入口と経路：プライベートネットワーク、ロードバランシング、ドメイン、CDN、API の入口

VPCネットワーク · マネージド

クラウド上のプライベートネットワーク：IP アドレス範囲、サブネット、ルートテーブル、セキュリティグループを自分で設定し、どのリソースがインターネットにアクセスできるかを決めます。VPC 自体は無料です。

CloudFrontネットワーク · グローバルサービス

CDN：ウェブサイト、動画、API を世界中のエッジロケーションにキャッシュし、ユーザーは最寄りの拠点からアクセスするので、オリジンの負荷が軽くなります。Shield Standard が標準で付属し、一般的な DDoS 攻撃を防ぎます。

重要ポイント 5問題 8アーキテクチャ 9
ELBネットワーク · マネージド

ロードバランシング：トラフィックを背後の複数の EC2、コンテナ、Lambda に分散し、異常なターゲットを自動的に避けます。ALB は HTTP/HTTPS、NLB は TCP/UDP を処理します。

API Gatewayネットワーク · サーバーレス

マネージドな API の入口：REST、HTTP、WebSocket API を作成し、認可、スロットリング、キャッシュを担当します。背後に Lambda などのサービスを接続し、呼び出し回数で課金されます。

Route 53ネットワーク · グローバルサービス

マネージド DNS：ドメイン名の登録と名前解決を行い、ヘルスチェックに基づいてフェイルオーバーしたり、レイテンシーや地理的位置に基づいてユーザーを異なるリージョンに誘導したりできます。グローバルサービスで、可用性の SLA は 100% です。

データベース系

5 個

業務データの保存：リレーショナルデータベース、キーバリューストア、キャッシュ、データベース移行用の DMS

RDSデータベース · PaaS

マネージドなリレーショナルデータベース：MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2 に対応し、バックアップ、パッチ適用、フェイルオーバーを代行します。マルチ AZ 配置では別の AZ にスタンバイインスタンスを置きます。

重要ポイント 5問題 8アーキテクチャ 7
Auroraデータベース · PaaS

Amazon Web Services が独自に開発したクラウドネイティブなリレーショナルデータベースで、MySQL および PostgreSQL と互換性があります：データは 3 つの AZ に 6 つのコピーとして保存され、リードレプリカは最大 15 個。Aurora Serverless v2 は負荷に応じて自動でスケールし、Global Database はリージョンをまたいで使えます。

重要ポイント 5問題 6アーキテクチャ 10
DMSデータベース · PaaS

データベース移行サービス：オンプレミスや他のクラウドのデータベースを Amazon Web Services に移行します。同種（MySQL から RDS for MySQL）でも異種（Oracle から Aurora PostgreSQL）でも移行できます。全ロードの後もソースデータベースの変更を継続的にキャプチャ（CDC）するので、新旧のデータベースを同期させたまま、切り替え時のダウンタイムを短くできます。レプリケーションインスタンスの時間単位で課金され、従量課金の DMS Serverless もあります。

重要ポイント 5問題 2アーキテクチャ 3
DynamoDBデータベース · サーバーレス

サーバーレスのキーバリュー型およびドキュメント型データベース：ミリ秒単位で読み書きでき、オンデマンドモードはリクエスト単位で課金、データは自動的に複数の AZ に保存されます。グローバルテーブルを使えば複数のリージョンで同時に読み書きできます。

重要ポイント 5問題 7アーキテクチャ 12
ElastiCacheデータベース · PaaS

マネージドなインメモリキャッシュ：Valkey、Redis OSS、Memcached に対応し、マイクロ秒からミリ秒単位で読み書きできます。データベースの前に置いて、アクセスが集中するデータの読み取りを受け止めます。

リアルタイムのデータストリーミング：Kinesis Data Streams は毎秒大量のイベントを受け止め、複数のアプリケーションが同時に読み取れます。Data Firehose はデータを S3、Redshift、OpenSearch に直接配信できます。
