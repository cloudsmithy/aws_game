DynamoDB

データベース系サーバーレス従量課金マルチ AZ 標準対応

サーバーレスのキーバリュー型およびドキュメント型データベース：ミリ秒単位で読み書きでき、オンデマンドモードはリクエスト単位で課金、データは自動的に複数の AZ に保存されます。グローバルテーブルを使えば複数のリージョンで同時に読み書きできます。

主な用途

ユーザーセッション、ショッピングカート、ゲームデータ、高い同時実行性が求められるワークロード

使う理由

アクセスパターンが決まっていて、同時アクセスが非常に多いときに使います：管理するデータベースサーバーがなく、読み書きのレイテンシーはミリ秒単位で安定しています

重要ポイント5 件

  1. サーバーレスのキーバリュー型・ドキュメント型データベースで、プライマリキー（パーティションキーと、オプションのソートキー）でアクセスします。レイテンシーは 1 桁ミリ秒で安定しています
  2. キャパシティモード：オンデマンド（リクエスト単位で支払い）とプロビジョンド（自動スケーリングを設定可能）
  3. グローバルセカンダリインデックス（GSI）とローカルセカンダリインデックス（LSI）で、別の条件でのクエリに対応できます。任意のテーブルを結合するクエリはできないので、テーブル設計はアクセスパターンに合わせて行います
  4. DynamoDB Streams はすべての変更を順番に記録し、Lambda をトリガーできます。グローバルテーブルでマルチリージョン・マルチアクティブを実現します
  5. ポイントインタイムリカバリ（PITR）に対応し、TTL で期限切れのデータを自動削除できます。DAX は専用のインメモリキャッシュです

比較と選び方

Aurora か DynamoDB

キーで読み書きし、同時アクセスが非常に多く、アクセスパターンが決まっているなら DynamoDB を選びます。SQL、トランザクション、複数テーブルの結合が必要なら Aurora を選びます（Serverless v2 は自動でスケールします）

Aurora か DynamoDB か RDS

キーでの読み書きで同時アクセスが非常に多いなら DynamoDB を選びます。SQL とトランザクションが必要なら Aurora（パフォーマンスと可用性がより高い）か RDS（エンジンが多く、より安い）を選びます

DynamoDB か ElastiCache

レコメンドの結果を永続的に保存し、ユーザーごとに参照するなら DynamoDB を選びます。ミリ秒未満のレイテンシーが必要で、失われても再計算できるなら ElastiCache を選びます
