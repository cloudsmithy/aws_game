EC2

コンピューティング系IaaS時間課金マルチ AZ は自前で構成

クラウド上の仮想サーバー：CPU、メモリ、OS を自分で選び、秒単位で課金されます。オンデマンド、Savings Plans、スポットなどの方法で購入できます。各インスタンスは 1 つの AZ にあるため、高可用性には複数の AZ にそれぞれ数台ずつ配置し、ELB と Auto Scaling を組み合わせます。

主な用途

さまざまなアプリケーションの実行、OS を完全に制御する必要があるケース

使う理由

OS を完全に制御したい、特殊なソフトウェアを入れたい、古いアプリケーションを動かしたいときに使います。インスタンスタイプの種類が最も豊富です

重要ポイント5 件

  1. 仮想サーバーです。インスタンスタイプで CPU、メモリ、ネットワークを選びます：汎用の M、コンピューティング最適化の C、メモリ最適化の R、GPU インスタンスの P と G など
  2. 購入オプション：オンデマンド、Savings Plans、リザーブドインスタンス、スポット（未使用のキャパシティを利用、最大 90% 節約、中断の 2 分前に通知）、専有ホスト
  3. 1 つのインスタンスは 1 つの AZ にしか存在しません。高可用性は、複数の AZ にまたがる Auto Scaling グループとロードバランサーで実現します
  4. セキュリティグループはインスタンス単位のステートフルなファイアウォールです。クラウド上のサービスへのアクセスには IAM ロール（インスタンスプロファイル）を使い、アクセスキーをマシンに書き込まないようにしましょう
  5. インスタンスストア（instance store）のデータはインスタンスを停止すると消えます。残したいデータは EBS に置きましょう

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

LV.1 · レベル 1

AMI 自動作成

Data Lifecycle Manager でスケジュールに従ってインスタンスの AMI を作成します（アタッチされた EBS ボリュームも含む）。インスタンスが壊れたり誤って削除されたりしても、そのイメージからすぐにもう 1 台起動できます

ゲーム内：データの誤削除を無効化

運用コスト：1 周ごとに $15

LV.2 · レベル 2

マルチ AZ Auto Scaling

Auto Scaling グループが複数の AZ にインスタンスを配置し、CPU やリクエスト数に応じて自動で増減させます。1 つの AZ で問題が起きても、ほかの AZ のインスタンスが引き継ぎます

ゲーム内：「EC2 インスタンスのハードウェア廃止」を無効化、AZ の停電と単一障害点に耐える、トラフィックの急増に耐える

運用コスト：1 周ごとに $25

LV.3 · レベル 3

Graviton

Arm ベースのインスタンスに切り替えます。同じ性能でより安くなります

ゲーム内：運用コストまたはリクエスト料金が半額

運用コスト：1 周ごとに $20

比較と選び方

EC2 か ECS

OS を完全に制御したい、古いアプリケーションを動かしたいなら EC2 を使います。すでにコンテナ化していて手間を減らしたいなら ECS を使います（Fargate と組み合わせればマシンの管理さえ不要です）

EC2 か ECS か EKS

OS を完全に制御したいなら EC2、コンテナ化していて手間を減らしたいなら ECS、チームが Kubernetes に慣れているなら EKS を選びます

正解60 秒
秒単位の課金で、最低 60 秒です
3.EC2 インスタンスを停止（Stop）した後も課金されるものはどれですか？
正解EBS ボリュームのストレージ料金と Elastic IP の料金
停止で止まるのはコンピューティング料金だけで、ストレージは引き続き課金されます
4.EC2 Auto Scaling グループで AZ をまたいだ高可用性を実現するには、どう設定しますか？
正解複数の AZ のサブネットを選択する
インスタンスはそれらの AZ 間で自動的にバランスよく配置されます
5.OpenSearch Service のドメインは、EC2 のように停止（Stop）できますか？
正解いいえ、削除するしかない
使わなくなったらドメインを削除します。削除する前にスナップショットを取っておきましょう
6.同じ AZ 内の EC2 どうしがプライベート IP でデータを転送する場合、料金はかかりますか？
正解無料
データ転送料金がかかるのは、AZ をまたぐ場合です。パブリック IP や Elastic IP 経由で転送する場合も料金がかかります
7.責任共有モデルで、お客様が責任を負うのはどれですか？
正解自社のデータと権限、および EC2 を使う場合の OS のパッチ
マネージドの度合いが高いサービスほど、お客様が管理する範囲は小さくなります
8.責任共有モデルによると、顧客が Amazon EC2 でアプリケーションを実行する場合、次のうち顧客の責任はどれですか？CLF-C02
正解ゲスト OS に更新プログラムとセキュリティパッチを適用する
EC2 を使用する場合、顧客はゲスト OS（更新プログラムとセキュリティパッチを含む）、アプリケーションソフトウェア、セキュリティグループの設定に責任を負います。物理的な設備、ハードウェア、ネットワークは、Amazon Web Services が責任を負う「クラウドのセキュリティ」に含まれます。　公式ドキュメント ↗
