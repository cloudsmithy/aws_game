Kinesis

分析系マネージド時間課金マルチ AZ 標準対応

リアルタイムのデータストリーミング：Kinesis Data Streams は毎秒大量のイベントを受け止め、複数のアプリケーションが同時に読み取れます。Data Firehose はデータを S3、Redshift、OpenSearch に直接配信できます。

主な用途

クリックストリームとログのリアルタイム分析、リアルタイムダッシュボード、IoT データ

使う理由

データが 1 件ずつ絶え間なく届き、リアルタイムで処理したいときに使います：突発的なトラフィックにも耐えられ、複数のコンシューマーが同時に読み取れます

重要ポイント5 件

  1. Kinesis Data Streams：リアルタイムのデータストリームで、シャード単位またはオンデマンドモードでスケールします。データの保持期間はデフォルトで 24 時間、最長 365 日です
  2. 複数のコンシューマーが同じストリームを同時に読み取れます。拡張ファンアウトを使うと、各コンシューマーが専用の読み取りスループットを持てます
  3. Amazon Data Firehose（旧称 Kinesis Data Firehose）を使えば、コードを書かずにデータを S3、Redshift、OpenSearch などへ継続的に配信できます
  4. 同じパーティションキーのレコードは同じシャードに入るので、順序が保たれます
  5. よくあるダウンストリーム：Lambda によるリアルタイム処理、または Managed Service for Apache Flink によるストリーム処理

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

データ変換

Data Firehose が配信前に Lambda を呼び出して各レコードをクレンジング・変換するか、Glue データカタログのテーブルスキーマに従って Parquet に変換してから S3 に書き込みます。保存コストが下がり、下流で Athena からクエリするときのスキャン量も減ります

ゲーム内：運用コストまたはリクエスト料金が半額

運用コスト：1 周ごとに $15

1.Kinesis Data Streams のデフォルトのデータ保持期間はどれですか？
正解24 時間
デフォルトは 24 時間で、最長 365 日まで延長できます
2.Kinesis Data Streams の 1 つのシャードの書き込み上限はどれですか？
正解毎秒 1 MB または 1000 レコード
毎秒 2 MB は読み取りの上限です。スループットが足りなければシャードを追加するか、オンデマンドモードを使います
3.Kinesis Data Streams は、データが流れていないときも料金がかかりますか？
正解はい、時間単位またはアカウントの最低料金で課金される
プロビジョンドモードはシャード時間、オンデマンドの Standard モードはストリーム時間で課金され、データがなくても料金がかかります。アカウントで On-demand Advantage を有効にするとストリームごとの時間料金はなくなりますが、そのリージョンのオンデマンドストリーム全体で、書き込みと読み取りそれぞれ毎秒 25 MiB 分が最低料金として課金されます。そのため「使われなければ料金ゼロ」のサーバーレスとは言えません
4.Kinesis Data Firehose（現在の名称は Amazon Data Firehose）の主な用途は何ですか？
正解ストリーミングデータを S3 などの送信先に自動で配信する
送信先は S3、Redshift、OpenSearch などです。コンシューマーのコードを書く必要はなく、自動でバッチにまとめて書き込みます
5.ある EC サイトでは、クリックストリームデータをリアルタイムで収集する必要があります。リアルタイムレコメンデーションや不正検出などの複数のアプリケーションが、同じデータをそれぞれ独立して順番どおりに読み取り、処理でエラーが発生した場合は保持期間内に再処理できる必要があります。データ取り込みレイヤーとしてどのサービスを使用すべきですか？SAA-C03
正解Amazon Kinesis Data Streams
Kinesis Data Streams はシャードごとにシーケンス番号の順でレコードを保存し、複数のコンシューマーがそれぞれ独立して読み取れるほか、保持期間内であればデータをリプレイできます。SQS 標準キューは順序を保証せず、メッセージは処理されて削除されるとリプレイできません。SNS はプッシュした後にメッセージを保持しません。リレーショナルデータベースは、高速なクリックストリームを受け止めるにはスケーラビリティが不足します。　公式ドキュメント ↗
