ElastiCache

データベース系PaaS時間課金マルチ AZ は自前で構成

マネージドなインメモリキャッシュ：Valkey、Redis OSS、Memcached に対応し、マイクロ秒からミリ秒単位で読み書きできます。データベースの前に置いて、アクセスが集中するデータの読み取りを受け止めます。

主な用途

ホットデータのキャッシュ、セッション、ランキング

使う理由

同じデータが繰り返し読まれるときに、インメモリキャッシュの層を置きます：ミリ秒未満で応答でき、データベースの負荷が大きく減ります

重要ポイント5 件

  1. マネージドなインメモリデータベースで、エンジンは Valkey、Redis OSS、Memcached から選べます
  2. 主な用途：ホットデータのキャッシュ（まずキャッシュを参照し、ヒットしなければデータベースを参照）、セッションストア、ランキング、カウンター
  3. Valkey と Redis OSS はレプリカ、マルチ AZ の自動フェイルオーバー、データの永続化に対応しています。Memcached はシンプルなキャッシュ専用で、永続化はしません
  4. ElastiCache Serverless ではノードタイプを選ぶ必要がなく、使用量に応じて課金されます
  5. キャッシュには有効期限を設定し、データベースを更新したら、対応するキャッシュを無効化しましょう

比較と選び方

DynamoDB か ElastiCache

レコメンドの結果を永続的に保存し、ユーザーごとに参照するなら DynamoDB を選びます。ミリ秒未満のレイテンシーが必要で、失われても再計算できるなら ElastiCache を選びます

正解ElastiCache で人気クエリの結果をキャッシュする
ElastiCache はマネージドのインメモリキャッシュを提供し、繰り返し実行される人気クエリの結果をキャッシュすることで、データベースの負荷と読み取りのレイテンシーを大幅に削減できます。マルチ AZ DB インスタンスのスタンバイインスタンスは読み取りを処理しません。マルチ AZ DB クラスターのリーダーインスタンスは読み取りを分担できますが、新しいクラスターへの移行が必要なうえ、人気クエリは毎回あらためて実行されます。st1 は HDD で、データベースのランダム I/O には適していません。T 系に変更しても CPU の課金とバーストの仕組みが変わるだけで、繰り返し実行される人気クエリの負荷は残ります。　公式ドキュメント ↗
