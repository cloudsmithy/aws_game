EBS

ストレージ系IaaS時間課金常にシングル AZ

EC2 用のブロックストレージ（クラウドディスク）：ボリュームを同じ AZ のインスタンスにアタッチしてシステムディスクやデータディスクとして使い、スナップショットでバックアップできます。ボリュームは 1 つの AZ 内にのみ存在します。

主な用途

システムディスク、自前で構築したデータベースのデータディスク

使う理由

低レイテンシーで、ローカルディスクのように使えるブロックストレージが必要なときに使います。スナップショットは増分でバックアップされます

重要ポイント5 件

  1. ブロックストレージで、同じ AZ 内の EC2 にアタッチしてローカルディスクのように使います。ボリュームは 1 つの AZ 内にしか存在しないため、別の AZ に移すにはスナップショットを使います
  2. スナップショットは増分で、S3 に保存されます（このバケットは見えません）。リージョン間でコピーでき、別の AZ やリージョンで復元できます
  3. ボリュームタイプ：gp3（汎用 SSD、パフォーマンスと容量を別々に設定）、io2 Block Express（高 IOPS のデータベース用ディスク）、st1 と sc1（スループット重視の HDD）
  4. ほとんどのボリュームは、同時に 1 つのインスタンスにしかアタッチできません。io1 と io2 はマルチアタッチ（Multi-Attach）に対応しており、同じ AZ 内の複数のインスタンスにアタッチできます
  5. KMS で暗号化でき、アカウント単位でデフォルトの暗号化を有効にすることもできます。スナップショットロックを使うと、ロックの期限が切れるまでスナップショットを削除できなくなります

1.EFS と EBS の最大の違いはどれですか？
正解EFS は複数のインスタンスから同時にマウントでき、EBS ボリュームは通常 1 台にしかアタッチしない
EBS にもマルチアタッチはありますが、一部のボリュームタイプと同じ AZ 内に限られます
2.EBS ボリュームが存在する範囲はどれですか？
正解単一の AZ
そのため、別の AZ で復元するにはスナップショットが必要です
3.EBS gp3 の gp2 に対する主な利点はどれですか？
正解IOPS とスループットを個別に設定でき、しかも安い
gp2 は性能が容量に連動し、バーストクレジットで一時的に高めます。gp3 はバーストクレジットを使いません
4.EC2 インスタンスを停止（Stop）した後も課金されるものはどれですか？
正解EBS ボリュームのストレージ料金と Elastic IP の料金
停止で止まるのはコンピューティング料金だけで、ストレージは引き続き課金されます
5.Nitro インスタンスで実行されている重要な OLTP データベースでは、1 つのボリュームで 200,000 IOPS とミリ秒未満のレイテンシーを継続的に提供する必要があります。どの Amazon EBS ボリュームタイプを選ぶべきですか？SAA-C03
正解プロビジョンド IOPS SSD（io2 Block Express）
io2 Block Express は Nitro インスタンスにアタッチした場合、1 ボリュームあたり最大 256,000 IOPS をプロビジョニングでき、安定したミリ秒未満のレイテンシーを提供します。gp3 は 1 ボリュームあたり最大 80,000 IOPS です。st1 と sc1 はシーケンシャルなスループット向けの HDD で、ランダム IOPS が集中するワークロードには適していません。　公式ドキュメント ↗
