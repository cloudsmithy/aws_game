KMS

セキュリティ系マネージド従量課金マルチ AZ 標準対応ワイルドカードサービス

マネージドなキー管理：暗号化キーを作成・管理し、S3、EBS、RDS などのサービスがそのキーでデータを暗号化します。キーが平文で KMS の外に出ることはなく、使用のたびに CloudTrail に記録されます。

主な用途

保管中のデータの暗号化、データを復号できるユーザーの制御

使う理由

キーを自分で保管する必要はありません：データを保存するサービスはどれもこれを使って直接暗号化でき、誰がキーを使ったかはすべて CloudTrail に記録されます

重要ポイント5 件

  1. マネージドな暗号化キー：S3、EBS、RDS、DynamoDB など、データを保存するサービスの多くと直接統合されています
  2. エンベロープ暗号化：KMS キーはデータキーだけを暗号化し、そのデータキーで大きなデータを暗号化します
  3. キーには Amazon Web Services マネージドキーとカスタマーマネージドキーがあります。カスタマーマネージドキーでは、キーポリシーを自分で書いたり、自動ローテーションを有効にしたり、キーを無効にしたりできます
  4. キーの使用はすべて CloudTrail に記録されるので、誰がいつ何を復号したかを監査できます
  5. キーマテリアルは、FIPS 140 で検証されたハードウェアセキュリティモジュール（HSM）の外に出ません

1.KMS は何に使いますか？
正解暗号化キーを作成・管理する
多くのサービスの保管時の暗号化は KMS キーで行われます。パスワードの保存には Secrets Manager、証明書には ACM を使います
2.KMS のカスタマーマネージドキーの自動ローテーション期間は、どの範囲で設定できますか？
正解90～2560 日、デフォルトは 1 年
ローテーション後も、古いデータはそのまま復号できます
3.開発チームは、データの暗号化に使うキーを作成・管理する必要があり、それらのキーを検証済みのハードウェアセキュリティモジュールで保護したいと考えています。どのサービスを使用すべきですか？CLF-C02
正解Key Management Service（KMS）
KMS は暗号化や署名に使うキーの作成と管理に使われ、KMS キーは FIPS 140-3 検証済みのハードウェアセキュリティモジュールで保護されます。Secrets Manager はパスワードなどのシークレットを保存し、ACM は TLS 証明書を管理し、IAM はアイデンティティと権限を管理するサービスで、いずれも暗号化キーの作成は担当しません。　公式ドキュメント ↗
4.コンプライアンスチームの要件：Amazon Bedrock でファインチューニングして作成したカスタムモデルは、自社で管理・制御するキーで暗号化しなければなりません。どうすればよいですか？AIF-C01
正解KMS のカスタマーマネージドキーでカスタムモデルを暗号化する
Bedrock はデフォルトで Amazon Web Services 所有のキーを使ってカスタムモデルを暗号化しますが、KMS で自分で管理するカスタマーマネージドキーで暗号化することも選択でき、キーポリシーでアクセス許可を制御できます。IAM のアクセスキーは認証に使用するもので、データの暗号化キーではありません。　公式ドキュメント ↗
5.ある金融会社は、S3 の機密データを保管時に暗号化することに加え、暗号化キーを使用できる IAM プリンシパルを自社で決定し、キーのローテーションを自社で管理し、CloudTrail でキーの使用状況を監査できることを求めています。すべての要件を満たす方法はどれですか？SAA-C03
正解SSE-KMS でカスタマーマネージド KMS キーを使用し、キーポリシーでアクセスを制御する
カスタマーマネージドキーのキーポリシーは顧客が管理し、自動ローテーションやオンデマンドローテーションを自分で有効にでき、キーの使用は CloudTrail に記録されます。SSE-S3 ではキーの権限を個別に制御できません。Amazon Web Services マネージドキーは、プロパティもキーポリシーも変更できません。ハードコードしたキーは安全でないうえ、一元的な監査もできません。　公式ドキュメント ↗
