Lambda

コンピューティング系サーバーレス従量課金マルチ AZ 標準対応

サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。

主な用途

API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク

使う理由

コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません

重要ポイント9 件

  1. イベント駆動型の関数：S3、SQS、DynamoDB Streams、EventBridge、API Gateway などがトリガーになります
  2. 通常の関数は 1 回の実行が最長 15 分です。メモリは 128 MB から 10 GB までで、CPU はメモリに比例して割り当てられます
  3. 耐久性のある関数（durable functions、2025 年 12 月リリース、複数ステップのアプリケーションや AI ワークフロー向け）：コード内でステップ（steps）と待機（waits）を使って進行状況を記録し、一時停止中は課金されず、実行全体で最長 1 年続けられます。1 回の呼び出しの上限は 15 分のままですが、タイムアウトしても最後に完了したステップの続きから実行されるので、最初からやり直す必要はありません
  4. Lambda MicroVMs（2026 年の新サービス）：ユーザーやタスクごとに専用の VM を 1 台割り当て、ユーザーや AI が生成したコード（AI コーディングアシスタントなど）を実行します。1 つあたり最長 8 時間です。通常の関数ではなく、別の種類のコンピューティングリソースです
  5. Lambda Managed Instances：非同期呼び出しとイベントソースマッピングは最長 90 分です（公式のクォータページに記載）
  6. 長時間実行するエージェントの場合：通常の関数は 15 分が上限のままです。耐久性のある関数で複数のステップに分ける（合計で最長 1 年）か、MicroVMs を使います（1 つあたり最長 8 時間）
  7. リクエスト数と実行時間（ミリ秒単位）に応じて課金されます。コールドスタートは、プロビジョニングされた同時実行や SnapStart で緩和できます
  8. デフォルトでは Amazon Web Services が管理するネットワークで実行されます。プライベートサブネットのデータベースに接続するには、関数に VPC を設定する必要があります
  9. 同時実行数にはアカウント単位のクォータがあります。予約済み同時実行数を設定すると、特定の関数の同時実行数を確保することも、上限を設けることもできます

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

LV.1 · レベル 1

同時実行クォータの引き上げ

より高い同時実行数の上限を申請し、トラフィックが多くてもスロットリングされないようにします

ゲーム内：「サービスクォータを使い切った」を無効化、パフォーマンス効率の柱 +1 点

運用コスト：通行料を受け取るたびに 15% のリクエスト料金

LV.2 · レベル 2

プロビジョニングされた同時実行

実行環境を事前に準備し、コールドスタートをなくします

ゲーム内：このマスの通行料がさらに +20%

運用コスト：1 周ごとに $10、通行料を受け取るたびに 15% のリクエスト料金

LV.3 · レベル 3

コンテナイメージ + Web Adapter

関数をコンテナイメージ（最大 10 GB）としてパッケージ化し、Lambda Web Adapter を組み合わせると、Express、Flask、Spring Boot などの Web フレームワークがほぼコードを変えずに動きます。常時稼働のサーバーは不要で、リクエスト単位で支払います

ゲーム内：運用コストまたはリクエスト料金が半額

運用コスト：1 周ごとに $10、通行料を受け取るたびに 8% のリクエスト料金

1.標準の Lambda 関数の 1 回の実行時間の上限はどれですか？
正解15 分

2.Lambda 関数に設定できるメモリの上限はどれですか？
正解10,240 MB
CPU はメモリサイズに比例して割り当てられます
3.Lambda や DynamoDB のようなサーバーレスサービスでは、高可用性のためにマルチ AZ を自前で構成する必要がありますか？
正解いいえ、デフォルトで複数の AZ で動作する
サーバーレスはマルチ AZ の高可用性が標準で備わっています。リージョン全体の障害に耐える必要がある場合にだけ、マルチリージョンを自前で構成します
4.Lambda の料金は主に何に基づきますか？
正解リクエスト数と実行時間
実行時間は設定したメモリ量で換算され、リクエストがなければ料金はかかりません。プロビジョニングされた同時実行は別途、時間に応じて課金されます
5.Lambda のコールドスタートとは何ですか？
正解新しい実行環境の初期化に余分にかかる時間
プロビジョニングされた同時実行で、実行環境を事前に準備しておけます
6.GuardDuty が異常を検出したとき、インスタンスを自動で隔離する一般的な方法はどれですか？
正解EventBridge ルールで Lambda をトリガーして対処する
Step Functions をトリガーして複数ステップの対処をオーケストレーションすることもできます。これが「脅威への自動対応」アーキテクチャです
7.ある会社は今後 1 年間、安定したコンピューティング使用量を確約しますが、EC2 のインスタンスファミリーやリージョンを頻繁に変更し、一部のワークロードは Fargate と Lambda で実行しています。最も適した料金モデルはどれですか？CLF-C02
正解Compute Savings Plans
Compute Savings Plans は 1 時間あたりの利用金額を確約するもので、インスタンスファミリー、サイズ、OS、テナンシー、リージョンによる制限がなく、Fargate と Lambda にも適用され、最大 66% 節約できます。単一のリージョンと単一のインスタンスファミリーに限定される EC2 Instance Savings Plans は最大 72% 節約できますが、柔軟性では劣ります。スタンダードリザーブドインスタンスは特定のインスタンス構成に限定されるため、柔軟性が低くなります。　公式ドキュメント ↗
8.ある企業のコンピューティング使用量は安定していますが、EC2 から Fargate と Lambda へ段階的に移行しており、その間に EC2 のインスタンスファミリーやリージョンを変更する可能性もあります。この企業は割引を受けるために、3 年間の安定した使用量をコミットするつもりです。最も適切なオプションはどれですか？SAA-C03
正解Compute Savings Plans
Compute Savings Plans の割引は、インスタンスファミリー、サイズ、OS、リージョンを問わず EC2 の使用量に適用され、Fargate と Lambda にも適用されます。EC2 Instance Savings Plans は、特定のリージョン内の特定のインスタンスファミリーに限定されます。スタンダードリザーブドインスタンスも同様に、インスタンスの属性に制約されます。スポットはコミットメント型の割引ではなく、中断される可能性もあります。　公式ドキュメント ↗
