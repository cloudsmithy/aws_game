CloudFront

ネットワーク系グローバルサービス従量課金グローバルサービス

CDN：ウェブサイト、動画、API を世界中のエッジロケーションにキャッシュし、ユーザーは最寄りの拠点からアクセスするので、オリジンの負荷が軽くなります。Shield Standard が標準で付属し、一般的な DDoS 攻撃を防ぎます。

主な用途

ウェブサイトや静的アセットの高速化、動画配信

使う理由

ユーザーが広い地域に分散していて、静的コンテンツが多いときに最前面に置きます：ユーザーの近くから返すのでオリジンの負荷が小さく、エッジで攻撃をブロックすることもできます

重要ポイント5 件

  1. グローバルな CDN：コンテンツをエッジロケーションにキャッシュし、ユーザーは近くの拠点からアクセスします。動的な API も CloudFront を通して高速化できます
  2. オリジンには S3（OAC で CloudFront だけがプライベートバケットを読み取れるようにする）、ALB、EC2、API Gateway、または任意の HTTP サーバーを使えます
  3. Shield Standard が標準で付いており一般的な DDoS を防げるほか、WAF も関連付けられます
  4. エッジコンピューティング：CloudFront Functions（軽量、レイテンシーが非常に低い）と Lambda@Edge（より高機能）
  5. 署名付き URL や署名付き Cookie でプライベートコンテンツへのアクセスを制御します。コンテンツを更新したら、無効化リクエストを送ってキャッシュを更新できます

LV.2 · レベル 2

オリジンアクセスコントロール

S3 オリジンへのアクセスを CloudFront だけに許可するので、バケットを公開する必要がありません

ゲーム内：「S3 バケットがパブリックに設定された」を無効化

運用コスト：通行料を受け取るたびに 15% のリクエスト料金

LV.3 · レベル 3

オリジンフェイルオーバー

プライマリオリジンがダウンすると、自動でセカンダリオリジンに切り替えます

ゲーム内：リージョン全体の障害に耐える

運用コスト：通行料を受け取るたびに 15% のリクエスト料金

比較と選び方

CloudFront か ELB

ユーザーが世界中にいて静的コンテンツが多いなら、Shield を CloudFront に適用します。1 つのリージョンだけで、動的なリクエストが中心なら ALB に適用します
