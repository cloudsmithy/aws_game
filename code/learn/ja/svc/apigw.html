API Gateway

ネットワーク系サーバーレス従量課金マルチ AZ 標準対応

マネージドな API の入口：REST、HTTP、WebSocket API を作成し、認可、スロットリング、キャッシュを担当します。背後に Lambda などのサービスを接続し、呼び出し回数で課金されます。

主な用途

サーバーレス API、モバイルアプリやミニアプリのバックエンド

使う理由

ゲートウェイを自分で構築する必要はありません：認証・認可、スロットリング、キャッシュ、バージョン管理が最初から用意されていて、後ろに Lambda を直接つなげられます

重要ポイント5 件

  1. API は 3 種類：REST API（最も多機能：使用量プラン、API キー、リクエストの検証、キャッシュ）、HTTP API（より安く高速だが、機能は少なめ）、WebSocket API
  2. 認証・認可：IAM、Cognito ユーザープール、Lambda オーソライザーに加え、HTTP API では JWT を直接検証することもできます
  3. スロットリングと使用量プランで、API の不正な大量呼び出しを防ぎます。REST API ではレスポンスのキャッシュを有効にできます
  4. エンドポイントタイプ：エッジ最適化、リージョン、プライベート（VPC 内からインターフェイスエンドポイント経由でのみアクセス可能）
  5. 統合のタイムアウトはデフォルトで 29 秒です。時間のかかる処理は非同期にしましょう

3 つの主な機能ゲームの 3 段階のアップグレードは、実際のサービスにあるこの 3 つの機能です

LV.1 · レベル 1

使用量プランによるスロットリング

ステージと API キーごとにリクエストレートを制限し、急増したリクエストがすべてバックエンドに届かないようにします。公式にはベストエフォートとされており、DDoS 対策には WAF が必要です

ゲーム内：「API に悪意のある大量リクエスト」を無効化（セキュリティ攻防 DLC）、パフォーマンス効率の柱 +1 点

運用コスト：通行料を受け取るたびに 15% のリクエスト料金

LV.2 · レベル 2

アクセス認証

Cognito ユーザープール、Lambda オーソライザー、または IAM で呼び出し元を検証します。未認証のリクエストや権限のないリクエストはゲートウェイで拒否され、バックエンドには届きません

ゲーム内：「セキュリティ監査に不合格」を無効化

運用コスト：通行料を受け取るたびに 15% のリクエスト料金

LV.3 · レベル 3

キャッシュ

レスポンスをキャッシュしてバックエンドの呼び出しを減らし、応答を速くします。キャッシュは時間単位で課金されます

ゲーム内：このマスの通行料がさらに +20%

運用コスト：1 周ごとに $10、通行料を受け取るたびに 15% のリクエスト料金

練習問題ゲームの問題集と認定試験の練習問題から 3 問：選択肢をクリックして正誤を確認できます

正解 0 / 3、回答済み 0

1.API Gateway でサインイン済みのユーザーだけを通すには、どの方法が最も手軽ですか？
正解API に Cognito ユーザープールのオーソライザーを設定し、サインイン時に取得したトークンをリクエストに付ける
API Gateway の Cognito オーソライザー（HTTP API では JWT オーソライザー）が先にトークンを検証するため、未サインインやトークン期限切れのリクエストはゲートウェイで拒否され、Lambda に検証ロジックを書く必要はありません
2.API Gateway がサポートする API の種類はどれですか？
正解REST、HTTP、WebSocket
HTTP API のほうが安価で軽量です。GraphQL には AppSync を使います
3.WAF はどのサービスの前段に配置できますか？
正解CloudFront、ALB、API Gateway
WAF はレイヤー 7 を担当します。API Gateway で関連付けられるのは REST API だけです。ほかに AppSync や Cognito ユーザープールなどにも関連付けられます
