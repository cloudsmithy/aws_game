キャッシュの自動更新

キャッシュとデータベースが常に一致します：データが変わると、該当するキャッシュがすぐに更新されます

必須 3 つオプション 1 つ通行料は約 $152–$200（出目 7、アップグレードなし）

各サービスの役割4 つのサービス

01DynamoDB必須

データベース · サーバーレス · 従量課金 · 価格 $240
ここでの役割
DynamoDB のデータが変わると Streams が変更を順番に記録
使う理由
アクセスパターンが決まっていて、同時アクセスが非常に多いときに使います：管理するデータベースサーバーがなく、読み書きのレイテンシーはミリ秒単位で安定しています
概要
サーバーレスのキーバリュー型およびドキュメント型データベース：ミリ秒単位で読み書きでき、オンデマンドモードはリクエスト単位で課金、データは自動的に複数の AZ に保存されます。グローバルテーブルを使えば複数のリージョンで同時に読み書きできます。
主な用途
ユーザーセッション、ショッピングカート、ゲームデータ、高い同時実行性が求められるワークロード

02EventBridgeオプション

アプリケーション統合 · サーバーレス · 従量課金 · 価格 $240
ここでの役割
EventBridge Pipes でフィルタリング・転送し、ポーリングを自前で書かずに済む
使う理由
イベントを送る側と処理する側が互いを知る必要がありません：処理する側を追加しても送信側を変更する必要がなく、スケジュールに従って起動することもできます
概要
サーバーレスのイベントバス：Amazon Web Services のサービス、自社のアプリケーション、SaaS から送られるイベントをルールに従って Lambda や Step Functions などに転送し、スケジュールでの起動もできます。
主な用途
イベント駆動型アーキテクチャ、アカウント間のイベント配信、定期実行タスク
EventBridge のサービスノート →

03Lambda必須

コンピューティング · サーバーレス · 従量課金 · 価格 $220
ここでの役割
Lambda が ElastiCache の該当キャッシュを削除または更新
使う理由
コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません
概要
サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。
主な用途
API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク
Lambda のサービスノート →

04ElastiCache必須

データベース · PaaS · 時間課金 · 価格 $300
ここでの役割
Lambda が ElastiCache の該当キャッシュを削除または更新
使う理由
同じデータが繰り返し読まれるときに、インメモリキャッシュの層を置きます：ミリ秒未満で応答でき、データベースの負荷が大きく減ります
概要
マネージドなインメモリキャッシュ：Valkey、Redis OSS、Memcached に対応し、マイクロ秒からミリ秒単位で読み書きできます。データベースの前に置いて、アクセスが集中するデータの読み取りを受け止めます。
主な用途
ホットデータのキャッシュ、セッション、ランキング

ゲーム内での計算方法

必須
3 つ：DynamoDB、Lambda、ElastiCache
オプション
1 つ：EventBridge。なくても完成扱いで、あればまとめて請求
請求方法
そろえると、ほかのプレイヤーがこのアーキテクチャに含まれるあなたのマスのどれに止まっても、アーキテクチャ全体のすべてのサービスの通行料を合計して請求します。「または」のサービスを複数持っていれば、すべて合計に含まれます
金額の目安
アップグレードなし、出目 7 での見積もり：最小構成なら毎回約 $152、すべての部分をそろえると（最適なアーキテクチャ）約 $200。アップグレードすると、さらに大きく増えます

ゲーム内の価格は架空のもので、実際の料金を表すものではありません。$ はゲーム内通貨の単位です。
