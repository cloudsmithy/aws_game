各サービスの役割5 つのサービス

01API Gateway必須

ネットワーク · サーバーレス · 従量課金 · 価格 $220
ここでの役割
API Gateway が注文リクエストを受け付ける
使う理由
ゲートウェイを自分で構築する必要はありません：認証・認可、スロットリング、キャッシュ、バージョン管理が最初から用意されていて、後ろに Lambda を直接つなげられます
概要
マネージドな API の入口：REST、HTTP、WebSocket API を作成し、認可、スロットリング、キャッシュを担当します。背後に Lambda などのサービスを接続し、呼び出し回数で課金されます。
主な用途
サーバーレス API、モバイルアプリやミニアプリのバックエンド

02Step Functions必須

アプリケーション統合 · サーバーレス · 従量課金 · 価格 $260
ここでの役割
Step Functions がステップを順に制御：在庫の引き当て、決済、出荷指示の作成を行い、どこかで失敗したらそれまでの処理を取り消す
使う理由
複数ステップのワークフローのために、ステートマシンを自分で書く必要はありません：各ステップの再試行、タイムアウト、失敗時のロールバックを設定でき、どのステップまで実行したかも確認できます
概要
視覚的なワークフローのオーケストレーション：Lambda、コンテナタスク、各種サービスの API 呼び出しをステートマシンとしてつなぎ、再試行、分岐、並列処理を標準で備えます。人による承認を待つこともできます。
主な用途
注文処理フロー、データ処理パイプライン、AI エージェントのステップのオーケストレーション
Step Functions のサービスノート →

03Lambda必須

コンピューティング · サーバーレス · 従量課金 · 価格 $220
ここでの役割
Lambda が各ステップを実行
使う理由
コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません
概要
サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。
主な用途
API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク
Lambda のサービスノート →

04DynamoDB必須

データベース · サーバーレス · 従量課金 · 価格 $240
ここでの役割
DynamoDB に注文ステータスを記録
使う理由
アクセスパターンが決まっていて、同時アクセスが非常に多いときに使います：管理するデータベースサーバーがなく、読み書きのレイテンシーはミリ秒単位で安定しています
概要
サーバーレスのキーバリュー型およびドキュメント型データベース：ミリ秒単位で読み書きでき、オンデマンドモードはリクエスト単位で課金、データは自動的に複数の AZ に保存されます。グローバルテーブルを使えば複数のリージョンで同時に読み書きできます。
主な用途
ユーザーセッション、ショッピングカート、ゲームデータ、高い同時実行性が求められるワークロード
DynamoDB のサービスノート →

05SQSオプション

アプリケーション統合 · サーバーレス · 従量課金 · 価格 $240
ここでの役割
SQS に出荷タスクを入れ、倉庫システムが自分のペースで取り出す
使う理由
前後の処理速度が違うときに、間にキューを置きます：ピーク時はいったんキューにため、バックエンドは自分のペースで取り出します。失敗したものは再試行もできます
概要
マネージドなメッセージキュー：プロデューサーがメッセージをキューに入れ、コンシューマーが自分のペースで取り出します。標準キューは少なくとも 1 回の配信、FIFO キューは順序を保証します。
主な用途
注文のピークの平準化、システムを疎結合にして互いに影響しないようにする、非同期タスク
