01API Gateway必須

ネットワークグループ · Serverless · 従量課金 · 価格 $220
ここでの役割
API Gateway がリクエストを受け付け
使う理由
ゲートウェイを自分で構築する必要はありません：認証、スロットリング、キャッシュ、バージョン管理が最初から用意されていて、後ろに Lambda を直接つなげられます
概要
マネージドな API の入口：REST、HTTP、WebSocket API を作成し、認可、スロットリング、キャッシュを担当します。背後に Lambda などのサービスを接続し、呼び出し回数で課金されます。
主な用途
サーバーレス API、モバイルアプリやミニプログラムのバックエンド
API Gateway のサービスノート →

02Lambda必須

コンピューティンググループ · Serverless · 従量課金 · 価格 $220
ここでの役割
Lambda が処理：書き込みは RDS または Aurora へ（SQL Server や MySQL などのリレーショナルデータベース、RDS Proxy で接続を再利用）
使う理由
コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません
概要
サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。
主な用途
API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク
Lambda のサービスノート →

03RDS必須いずれか 1 つ

データベースグループ · PaaS · 時間課金 · 価格 $280
ここでの役割
Lambda が処理：書き込みは RDS または Aurora へ（SQL Server や MySQL などのリレーショナルデータベース、RDS Proxy で接続を再利用）
使う理由
リレーショナルデータベースが必要だけれど、自分で運用したくないときに使います：バックアップ、パッチ適用、マルチ AZ のフェイルオーバーはすべてマネージドで、選べるエンジンが最も多いです
概要
マネージドなリレーショナルデータベース：MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2 に対応し、バックアップ、パッチ適用、フェイルオーバーを代行します。マルチ AZ 配置では別の AZ にスタンバイインスタンスを置きます。
主な用途
従来型の業務システム、EC サイトの注文データベース
RDS のサービスノート →

03Aurora必須いずれか 1 つ

データベースグループ · PaaS · 時間課金 · 価格 $280
ここでの役割
Lambda が処理：書き込みは RDS または Aurora へ（SQL Server や MySQL などのリレーショナルデータベース、RDS Proxy で接続を再利用）
使う理由
より高いパフォーマンスと可用性を備えた MySQL や PostgreSQL が必要なときに選びます：ストレージは自動で 3 つの AZ にまたがり、リードレプリカの遅延も小さく抑えられます
概要
Amazon Web Services が独自に開発したクラウドネイティブなリレーショナルデータベースで、MySQL および PostgreSQL と互換性があります：データは 3 つの AZ に 6 つのコピーとして保存され、リードレプリカは最大 15 個。Aurora Serverless v2 は負荷に応じて自動でスケールし、Global Database はリージョンをまたいで使えます。
主な用途
高い同時実行性が求められる基幹業務データベース
Aurora のサービスノート →
どれを選ぶか

Aurora は MySQL と PostgreSQL に互換性があり、パフォーマンスと可用性がより高くなります（ストレージは 3 つの AZ にまたがります）。SQL Server や Oracle が必要な場合や、コストを抑えたい場合は RDS を使います

04DMS必須

データベースグループ · PaaS · 時間課金 · 価格 $340
ここでの役割
DMS がデータベースの変更を継続的に OpenSearch へ同期（CDC、RDS 自体は OpenSearch にデータをプッシュできないので、同期は DMS が担う）
使う理由
RDS と Aurora は、自分では OpenSearch にデータをプッシュできません。DMS なら、アプリケーションのコードを変更せずに、データベースの変更を継続的に同期できます
概要
データベース移行サービス：オンプレミスや他のクラウドのデータベースを Amazon Web Services に移行します。同種（MySQL から RDS for MySQL）でも異種（Oracle から Aurora PostgreSQL）でも移行できます。全量ロードの後もソースデータベースの変更を継続的にキャプチャ（CDC）するので、新旧のデータベースを同期させたまま、切り替え時のダウンタイムを短くできます。レプリケーションインスタンスの時間単位で課金され、従量課金の DMS Serverless もあります。
主な用途
データベースのクラウド移行、業務データベースの変更をデータレイク、検索、データウェアハウスにリアルタイムで同期（CDC）
DMS のサービスノート →

05OpenSearch必須

分析グループ · PaaS · 時間課金 · 価格 $360
ここでの役割
OpenSearch がクエリと全文検索を担当（プライマリに負荷をかけない）
使う理由
全文検索、あいまい検索、ログのリアルタイム検索が必要なときに使います。これらをリレーショナルデータベースで行うと遅いうえ、データベースに負荷がかかります
概要
マネージドな OpenSearch（Elasticsearch から派生したオープンソースプロジェクト）：全文検索、ログ分析、可視化を行い、ベクトルデータベースとしても使えます。
主な用途
サイト内検索、ログ検索、RAG のベクトル検索
