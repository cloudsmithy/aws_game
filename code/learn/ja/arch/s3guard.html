01S3必須

ストレージ · サーバーレス · 従量課金 · 価格 $60
ここでの役割
S3 バケットを誰かがパブリックに設定
使う理由
バケットを誤って公開設定にしてしまうことは、データ漏えいの最もよくある原因の 1 つです。そのため、自動でチェックし、自動でプライベートに戻します
概要
オブジェクトストレージ：ファイルを「オブジェクト」としてバケットに保存し、保存したデータ量とリクエスト数に応じて課金されます。容量を事前に計画する必要はありません。S3 Standard ストレージクラスは、1 つのリージョン内の 3 つ以上の AZ にデータを保存します。
主な用途
ウェブサイトの画像や静的アセット、データレイク、バックアップとアーカイブ、ログ

02Config必須

モニタリング · 従量課金 · 従量課金 · 価格 $150
ここでの役割
Config のマネージドルール（s3-bucket-public-read-prohibited など）がすぐに検出し、自動修復で Systems Manager Automation ドキュメントを実行して、このバケットの「パブリックアクセスのブロック」を有効化
使う理由
リソースの設定がどう変わったかを記録し、コンプライアンスに準拠しているかを自動でチェックします
概要
設定の記録とコンプライアンスチェック：アカウント内の各リソースの設定と変更履歴を継続的に記録し、ルールで準拠しているかをチェックします（たとえば S3 バケットが公開されていないか、EBS ボリュームが暗号化されているか）。準拠していないリソースは自動で修復できます。
主な用途
コンプライアンス監査、誰が設定を壊したかの調査、公開された S3 バケットを自動でプライベートに戻す

03EventBridge必須

アプリケーション統合 · サーバーレス · 従量課金 · 価格 $240
ここでの役割
EventBridge にコンプライアンス状態の変化イベントが送られ、セキュリティチームに転送（メール、チャット）
使う理由
イベントを送る側と処理する側が互いを知る必要がありません：処理する側を追加しても送信側を変更する必要がなく、スケジュールに従って起動することもできます
概要
サーバーレスのイベントバス：Amazon Web Services のサービス、自社のアプリケーション、SaaS から送られるイベントをルールに従って Lambda や Step Functions などに転送し、スケジュールでの起動もできます。
主な用途
イベント駆動型アーキテクチャ、アカウント間のイベント配信、定期実行タスク
