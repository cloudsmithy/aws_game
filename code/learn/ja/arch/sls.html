各サービスの役割7 つのサービス

01CloudFrontオプション

ネットワークグループ · グローバルサービス · 従量課金 · 価格 $400
ここでの役割
CloudFront がフロントエンドのページを配信
使う理由
ユーザーが広い地域に分散していて、静的コンテンツが多いときに最前面に置きます：ユーザーの近くから返すのでオリジンの負荷が小さく、エッジで攻撃をブロックすることもできます
概要
CDN：ウェブサイト、動画、API を世界中のエッジロケーションにキャッシュし、ユーザーは最寄りの拠点からアクセスするので、オリジンの負荷が軽くなります。Shield Standard が標準で付属し、一般的な DDoS 攻撃を防ぎます。
主な用途
ウェブサイトや静的アセットの高速化、動画配信

02S3オプション

ストレージグループ · Serverless · 従量課金 · 価格 $60
ここでの役割
S3 にページを保存
使う理由
容量を計画する必要がなく、保存した分だけ支払います。データの耐久性は 99.999999999%（9 が 11 個）です。保存期間が長くなるにつれてアクセスが減るデータは、より安いストレージクラスへ自動で移すこともできます
概要
オブジェクトストレージ：ファイルを「オブジェクト」としてバケットに保存し、保存したデータ量とリクエスト数に応じて課金されます。容量を事前に計画する必要はありません。S3 Standard ストレージクラスは、1 つのリージョン内の 3 つ以上の AZ にデータを保存します。
主な用途
ウェブサイトの画像や静的アセット、データレイク、バックアップとアーカイブ、ログ
S3 のサービスノート →

03Cognitoオプション

セキュリティグループ · マネージド · 従量課金 · 価格 $80
ここでの役割
Cognito でユーザーがサインインし、API Gateway が先にトークンを検証
使う理由
サインインの仕組みを自分で作る必要はありません：パスワードの保存、MFA、パスワードのリセット、ソーシャルサインインがすべて用意されていて、API Gateway や ALB での認証にもそのまま使えます
概要
アプリやウェブサイトのユーザーサインインを管理：ユーザープールはアカウントを保存してサインアップ、サインイン、MFA を担当し、サインイン後に JWT トークンを発行します。ID プールはサインインしたユーザーを一時的な Amazon Web Services 認証情報に交換するので、アプリから S3 などのサービスに直接アクセスできます。月間アクティブユーザー（MAU）で課金されます。
主な用途
アプリやウェブサイトのサインアップとサインイン、API へのサインイン検証の追加（API Gateway と ALB はどちらも Cognito のトークンを直接検証できます）、モバイルアプリから S3 へのファイルの直接アップロード
Cognito のサービスノート →

04API Gateway必須

ネットワークグループ · Serverless · 従量課金 · 価格 $220
ここでの役割
API Gateway がリクエストを受け付け
使う理由
ゲートウェイを自分で構築する必要はありません：認証、スロットリング、キャッシュ、バージョン管理が最初から用意されていて、後ろに Lambda を直接つなげられます
概要
マネージドな API の入口：REST、HTTP、WebSocket API を作成し、認可、スロットリング、キャッシュを担当します。背後に Lambda などのサービスを接続し、呼び出し回数で課金されます。
主な用途
サーバーレス API、モバイルアプリやミニプログラムのバックエンド
API Gateway のサービスノート →

05Lambda必須

コンピューティンググループ · Serverless · 従量課金 · 価格 $220
ここでの役割
Lambda が処理
使う理由
コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません
概要
サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。
主な用途
API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク

06DynamoDB必須いずれか 1 つ

データベースグループ · Serverless · 従量課金 · 価格 $240
ここでの役割
DynamoDB または Aurora（Serverless v2）がデータを保存
使う理由
アクセスパターンが決まっていて、同時アクセスが非常に多いときに使います：管理するデータベースサーバーがなく、読み書きのレイテンシーはミリ秒単位で安定しています
概要
サーバーレスのキーバリュー型およびドキュメント型データベース：ミリ秒単位で読み書きでき、オンデマンドモードはリクエスト単位で課金、データは自動的に複数の AZ に保存されます。グローバルテーブルを使えば複数のリージョンで同時に読み書きできます。
主な用途
ユーザーセッション、ショッピングカート、ゲームデータ、高い同時実行性が求められるワークロード
DynamoDB のサービスノート →

06Aurora必須いずれか 1 つ

データベースグループ · PaaS · 時間課金 · 価格 $280
ここでの役割
DynamoDB または Aurora（Serverless v2）がデータを保存
使う理由
より高いパフォーマンスと可用性を備えた MySQL や PostgreSQL が必要なときに選びます：ストレージは自動で 3 つの AZ にまたがり、リードレプリカの遅延も小さく抑えられます
概要
Amazon Web Services が独自に開発したクラウドネイティブなリレーショナルデータベースで、MySQL および PostgreSQL と互換性があります：データは 3 つの AZ に 6 つのコピーとして保存され、リードレプリカは最大 15 個。Aurora Serverless v2 は負荷に応じて自動でスケールし、Global Database はリージョンをまたいで使えます。
主な用途
高い同時実行性が求められる基幹業務データベース
Aurora のサービスノート →
どれを選ぶか

キーで読み書きし、同時アクセスが非常に多く、アクセスパターンが決まっているなら DynamoDB を選びます。SQL、トランザクション、複数テーブルの結合が必要なら Aurora を選びます（Serverless v2 は自動でスケールします）

ゲーム内での計算方法

必須
3 つ：API Gateway、Lambda、DynamoDB または Aurora
オプション

請求方法
そろえると、ほかのプレイヤーがこのアーキテクチャのあなたのどのマスに止まっても、アーキテクチャ全体のすべてのサービスの通行料を合計して請求します。「または」のサービスを複数持っていれば、すべて合計に含まれます
金額の目安
アップグレードなし、出目 7 での見積もり：最小構成なら毎回約 $136、すべての部分をそろえると（最適なアーキテクチャ）約 $300。アップグレードすると、さらに大きく増えます
