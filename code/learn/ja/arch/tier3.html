クラシックな 3 層 Web

従来型の Web サイトや企業システムの標準構成：ロードバランサー、アプリケーションサーバー、データベースをそれぞれ 1 層とし、各層を個別にスケールできます

必須 3 つオプション 4 つ通行料は約 $104–$396（出目 7、アップグレードなし）

01Route 53オプション

ネットワークグループ · グローバルサービス · 従量課金 · 価格 $160
ここでの役割
Route 53 がドメインを名前解決
使う理由
ドメインの名前解決とヘルスチェックをまとめて行えます：片方がダウンしたら、自動でもう片方に切り替わります
概要
マネージド DNS：ドメイン名の登録と名前解決を行い、ヘルスチェックに基づいてフェイルオーバーしたり、レイテンシーや地理的位置に基づいてユーザーを異なるリージョンに誘導したりできます。グローバルサービスで、可用性の SLA は 100% です。
主な用途
ドメイン名の名前解決、リージョン間のディザスタリカバリ切り替え
Route 53 のサービスノート →

02CloudFrontオプション

ネットワークグループ · グローバルサービス · 従量課金 · 価格 $400
ここでの役割
CloudFront が静的コンテンツを近くでキャッシュし、エッジで攻撃の一部をブロック
使う理由
ユーザーが広い地域に分散していて、静的コンテンツが多いときに最前面に置きます：ユーザーの近くから返すのでオリジンの負荷が小さく、エッジで攻撃をブロックすることもできます
概要
CDN：ウェブサイト、動画、API を世界中のエッジロケーションにキャッシュし、ユーザーは最寄りの拠点からアクセスするので、オリジンの負荷が軽くなります。Shield Standard が標準で付属し、一般的な DDoS 攻撃を防ぎます。
主な用途
ウェブサイトや静的アセットの高速化、動画配信
CloudFront のサービスノート →

03ELB必須

ネットワークグループ · マネージド · 時間課金 · 価格 $140
ここでの役割
ELB がリクエストを複数の AZ に分散
使う理由
複数のバックエンドの前に統一された入口を置きます：トラフィックを自動で振り分け、故障したインスタンスを避けます。最初から複数の AZ にまたがっています
概要
ロードバランシング：トラフィックを背後の複数の EC2、コンテナ、Lambda に分散し、異常なターゲットを自動的に避けます。ALB は HTTP/HTTPS、NLB は TCP/UDP を処理します。
主な用途
ウェブサイトや API の統一された入口、マルチ AZ の高可用性
ELB のサービスノート →

04Cognitoオプション

セキュリティグループ · マネージド · 従量課金 · 価格 $80
ここでの役割
ALB が未サインインのユーザーを先に Cognito でサインインさせる
使う理由
サインインの仕組みを自分で作る必要はありません：パスワードの保存、MFA、パスワードのリセット、ソーシャルサインインがすべて用意されていて、API Gateway や ALB での認証にもそのまま使えます
概要
アプリやウェブサイトのユーザーサインインを管理：ユーザープールはアカウントを保存してサインアップ、サインイン、MFA を担当し、サインイン後に JWT トークンを発行します。ID プールはサインインしたユーザーを一時的な Amazon Web Services 認証情報に交換するので、アプリから S3 などのサービスに直接アクセスできます。月間アクティブユーザー（MAU）で課金されます。
主な用途
アプリやウェブサイトのサインアップとサインイン、API へのサインイン検証の追加（API Gateway と ALB はどちらも Cognito のトークンを直接検証できます）、モバイルアプリから S3 へのファイルの直接アップロード
Cognito のサービスノート →

05EC2必須いずれか 1 つ

コンピューティンググループ · IaaS · 時間課金 · 価格 $100
ここでの役割
EC2 または ECS がアプリを実行
使う理由
OS を完全に制御したい、特殊なソフトウェアを入れたい、古いアプリケーションを動かしたいときに使います。インスタンスタイプの種類が最も豊富です
概要
クラウド上の仮想サーバー：CPU、メモリ、OS を自分で選び、秒単位で課金されます。オンデマンド、Savings Plans、スポットなどの方法で購入できます。各インスタンスは 1 つの AZ にあるため、高可用性には複数の AZ にそれぞれ数台ずつ配置し、ELB と Auto Scaling を組み合わせます。
主な用途
さまざまなアプリケーションの実行、OS を完全に制御する必要があるケース
EC2 のサービスノート →

05ECS必須いずれか 1 つ

コンテナグループ · コンテナ · 時間課金 · 価格 $180
ここでの役割
EC2 または ECS がアプリを実行
使う理由
コンテナを動かしたいけれど Kubernetes は学びたくない、というときに選びます。Fargate と組み合わせれば、マシンの管理さえ不要です
概要
Amazon Web Services 独自のコンテナオーケストレーションサービス：実行するタスク数を指定すると、スケジューリングと故障したタスクの置き換えを行います。基盤には EC2 も Fargate（サーバー管理が不要）も使えます。
主な用途
マイクロサービス、バッチ処理
ECS のサービスノート →
どれを選ぶか

OS を完全に制御したい、古いアプリケーションを動かしたいなら EC2 を使います。すでにコンテナ化していて手間を減らしたいなら ECS を使います（Fargate と組み合わせればマシンの管理さえ不要です）

06RDS必須いずれか 1 つ

データベースグループ · PaaS · 時間課金 · 価格 $280
ここでの役割
RDS または Aurora がデータを保存
使う理由
リレーショナルデータベースが必要だけれど、自分で運用したくないときに使います：バックアップ、パッチ適用、マルチ AZ のフェイルオーバーはすべてマネージドで、選べるエンジンが最も多いです
概要
マネージドなリレーショナルデータベース：MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2 に対応し、バックアップ、パッチ適用、フェイルオーバーを代行します。マルチ AZ 配置では別の AZ にスタンバイインスタンスを置きます。
主な用途
従来型の業務システム、EC サイトの注文データベース
RDS のサービスノート →

06Aurora必須いずれか 1 つ

データベースグループ · PaaS · 時間課金 · 価格 $280
ここでの役割
RDS または Aurora がデータを保存
使う理由
より高いパフォーマンスと可用性を備えた MySQL や PostgreSQL が必要なときに選びます：ストレージは自動で 3 つの AZ にまたがり、リードレプリカの遅延も小さく抑えられます
概要
Amazon Web Services が独自に開発したクラウドネイティブなリレーショナルデータベースで、MySQL および PostgreSQL と互換性があります：データは 3 つの AZ に 6 つのコピーとして保存され、リードレプリカは最大 15 個。Aurora Serverless v2 は負荷に応じて自動でスケールし、Global Database はリージョンをまたいで使えます。
主な用途
高い同時実行性が求められる基幹業務データベース
Aurora のサービスノート →
どれを選ぶか

Aurora は MySQL と PostgreSQL に互換性があり、パフォーマンスと可用性がより高くなります（ストレージは 3 つの AZ にまたがります）。SQL Server や Oracle が必要な場合や、コストを抑えたい場合は RDS を使います

07OpenSearchオプション

分析グループ · PaaS · 時間課金 · 価格 $360
ここでの役割
OpenSearch にもアプリがデータベースへの書き込みと同時に検索対象の内容を書き込み、サイト内検索はこちらを使うのでデータベースに負荷がかからない
使う理由
サイト内検索にはあいまい一致や関連度順の並べ替えが必要で、SQL の LIKE で実装すると遅いうえ、データベースに負荷がかかります
概要
マネージドな OpenSearch（Elasticsearch から派生したオープンソースプロジェクト）：全文検索、ログ分析、可視化を行い、ベクトルデータベースとしても使えます。
主な用途
サイト内検索、ログ検索、RAG のベクトル検索

ゲーム内での計算方法

必須
3 つ：ELB、EC2 または ECS、RDS または Aurora
オプション
4 つ：Route 53、CloudFront、Cognito、OpenSearch。なくても完成扱いで、あればまとめて請求
請求方法
そろえると、ほかのプレイヤーがこのアーキテクチャのあなたのどのマスに止まっても、アーキテクチャ全体のすべてのサービスの通行料を合計して請求します。「または」のサービスを複数持っていれば、すべて合計に含まれます
金額の目安
アップグレードなし、出目 7 での見積もり：最小構成なら毎回約 $104、すべての部分をそろえると（最適なアーキテクチャ）約 $396。アップグレードすると、さらに大きく増えます

ゲーム内の価格は架空のもので、実際の料金を表すものではありません。$ はゲーム内通貨の単位です。
