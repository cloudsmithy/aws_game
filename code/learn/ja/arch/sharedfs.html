各サービスの役割6 つのサービス

01ELB必須

ネットワーク · マネージド · 時間課金 · 価格 $140
ここでの役割
ELB がリクエストを複数のマシンに振り分ける
使う理由
複数のバックエンドの前に統一された入口を置きます：トラフィックを自動で振り分け、故障したインスタンスを避けます。最初から複数の AZ にまたがっています
概要
ロードバランシング：トラフィックを背後の複数の EC2、コンテナ、Lambda に分散し、異常なターゲットを自動的に避けます。ALB は HTTP/HTTPS、NLB は TCP/UDP を処理します。
主な用途
ウェブサイトや API の統一された入口、マルチ AZ の高可用性
ELB のサービスノート →

02EC2必須いずれか 1 つ

コンピューティング · IaaS · 時間課金 · 価格 $100
ここでの役割
EC2、ECS または EKS 上のアプリケーションがすべて同じ EFS ファイルシステムをマウント
使う理由
OS を完全に制御したい、特殊なソフトウェアを入れたい、古いアプリケーションを動かしたいときに使います。インスタンスタイプの種類が最も豊富です
概要
クラウド上の仮想サーバー：CPU、メモリ、OS を自分で選び、秒単位で課金されます。オンデマンド、Savings Plans、スポットなどの方法で購入できます。各インスタンスは 1 つの AZ にあるため、高可用性には複数の AZ にそれぞれ数台ずつ配置し、ELB と Auto Scaling を組み合わせます。
主な用途
さまざまなアプリケーションの実行、OS を完全に制御する必要があるケース
EC2 のサービスノート →

02ECS必須いずれか 1 つ

コンテナ · コンテナ · 時間課金 · 価格 $180
ここでの役割
EC2、ECS または EKS 上のアプリケーションがすべて同じ EFS ファイルシステムをマウント
使う理由
コンテナを動かしたいけれど Kubernetes は学びたくない、というときに選びます。Fargate と組み合わせれば、マシンの管理さえ不要です
概要
Amazon Web Services 独自のコンテナオーケストレーションサービス：実行するタスク数を指定すると、スケジューリングと故障したタスクの置き換えを行います。基盤には EC2 も Fargate（サーバー管理が不要）も使えます。
主な用途
マイクロサービス、バッチ処理
ECS のサービスノート →

02EKS必須いずれか 1 つ

コンテナ · コンテナ · 時間課金 · 価格 $200
ここでの役割
EC2、ECS または EKS 上のアプリケーションがすべて同じ EFS ファイルシステムをマウント
使う理由
チームがすでに Kubernetes を使っていて、Helm やコミュニティのツールを引き続き使いたいときに選びます
概要
マネージド Kubernetes：コントロールプレーンは Amazon Web Services が複数の AZ で実行し、クラスターごとに時間単位で課金されます。ワーカーノードには EC2、マネージド型ノードグループ、Fargate、Auto Mode を使えます。
主な用途
すでに Kubernetes を使っているチームのクラウド移行、複数環境への統一的なデプロイ
EKS のサービスノート →
どれを選ぶか

OS を完全に制御したいなら EC2、コンテナ化していて手間を減らしたいなら ECS、チームが Kubernetes に慣れているなら EKS を選びます

03EFS必須

ストレージ · サーバーレス · 従量課金 · 価格 $100
ここでの役割
EC2、ECS または EKS 上のアプリケーションがすべて同じ EFS ファイルシステムをマウント
使う理由
複数のマシンで同じファイルを読み書きするとき、NFS サーバーを自分で構築する必要がありません。容量は使った分だけ自動で増えます
概要
マネージドな共有ファイルシステム（NFS）：複数の EC2、コンテナ、Lambda から同じディレクトリを同時にマウントできます。容量は書き込みに応じて自動で増え、使った分だけ課金されます。
主な用途
複数のサーバーで共有するファイル、コンテンツ管理、機械学習のトレーニングデータ
EFS のサービスノート →

04VPCオプション

ネットワーク · マネージド · 無料 · 価格 $140
ここでの役割
VPC の各 AZ のサブネットに EFS マウントターゲットを置く
使う理由
リソースを自分のプライベートネットワークに置き、サブネットとセキュリティグループで誰がアクセスできるかを決めます。データベースをインターネットに公開する必要はありません
概要
クラウド上のプライベートネットワーク：IP アドレス範囲、サブネット、ルートテーブル、セキュリティグループを自分で設定し、どのリソースがインターネットにアクセスできるかを決めます。VPC 自体は無料です。
主な用途
外部向けのロードバランサーはパブリックサブネットに、アプリケーションとデータベースはプライベートサブネットに配置

ゲーム内での計算方法

必須
3 つ：ELB、EC2 または ECS または EKS、EFS
オプション
1 つ：VPC。なくても完成扱いで、あればまとめて請求
請求方法
そろえると、ほかのプレイヤーがこのアーキテクチャに含まれるあなたのマスのどれに止まっても、アーキテクチャ全体のすべてのサービスの通行料を合計して請求します。「または」のサービスを複数持っていれば、すべて合計に含まれます
金額の目安
アップグレードなし、出目 7 での見積もり：最小構成なら毎回約 $68、すべての部分をそろえると（最適なアーキテクチャ）約 $172。アップグレードすると、さらに大きく増えます
