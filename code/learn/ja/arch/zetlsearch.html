各サービスの役割4 つのサービス

01DynamoDB必須

データベース · サーバーレス · 従量課金 · 価格 $240
ここでの役割
DynamoDB が商品と注文を保存
使う理由
アクセスパターンが決まっていて、同時アクセスが非常に多いときに使います：管理するデータベースサーバーがなく、読み書きのレイテンシーはミリ秒単位で安定しています
概要
サーバーレスのキーバリュー型およびドキュメント型データベース：ミリ秒単位で読み書きでき、オンデマンドモードはリクエスト単位で課金、データは自動的に複数の AZ に保存されます。グローバルテーブルを使えば複数のリージョンで同時に読み書きできます。
主な用途
ユーザーセッション、ショッピングカート、ゲームデータ、高い同時実行性が求められるワークロード
DynamoDB のサービスノート →

02OpenSearch必須

分析 · PaaS · 時間課金 · 価格 $360
ここでの役割
OpenSearch には Zero-ETL 統合（OpenSearch Ingestion パイプライン）で変更が自動で同期され、同期コードを自分で書く必要はない
使う理由
全文検索、あいまい検索、ログのリアルタイム検索が必要なときに使います。これらをリレーショナルデータベースで行うと遅いうえ、データベースに負荷がかかります
概要
マネージドな OpenSearch（Elasticsearch から派生したオープンソースプロジェクト）：全文検索、ログ分析、可視化を行い、ベクトルデータベースとしても使えます。
主な用途
サイト内検索、ログ検索、RAG のベクトル検索
OpenSearch のサービスノート →

03Lambda必須

コンピューティング · サーバーレス · 従量課金 · 価格 $220
ここでの役割
Lambda が検索リクエストを受け、OpenSearch で全文検索、あいまい検索、距離による検索を実行
使う理由
コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません
概要
サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。
主な用途
API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク
Lambda のサービスノート →

04API Gatewayオプション

ネットワーク · サーバーレス · 従量課金 · 価格 $220
ここでの役割
API Gateway からリクエストが入る
使う理由
ゲートウェイを自分で構築する必要はありません：認証・認可、スロットリング、キャッシュ、バージョン管理が最初から用意されていて、後ろに Lambda を直接つなげられます
概要
マネージドな API の入口：REST、HTTP、WebSocket API を作成し、認可、スロットリング、キャッシュを担当します。背後に Lambda などのサービスを接続し、呼び出し回数で課金されます。
主な用途
サーバーレス API、モバイルアプリやミニアプリのバックエンド

必須
3 つ：DynamoDB、OpenSearch、Lambda
オプション

請求方法
そろえると、ほかのプレイヤーがこのアーキテクチャに含まれるあなたのマスのどれに止まっても、アーキテクチャ全体のすべてのサービスの通行料を合計して請求します。「または」のサービスを複数持っていれば、すべて合計に含まれます

アップグレードなし、出目 7 での見積もり：最小構成なら毎回約 $164、すべての部分をそろえると（最適なアーキテクチャ）約 $208。アップグレードすると、さらに大きく増えます
