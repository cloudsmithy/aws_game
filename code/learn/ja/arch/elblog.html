01ELB必須

ネットワークグループ · マネージド · 時間課金 · 価格 $140
ここでの役割
ELB が 5 分ごとにアクセスログを S3 に書き込み
使う理由
複数のバックエンドの前に統一された入口を置きます：トラフィックを自動で振り分け、故障したインスタンスを避けます。最初から複数の AZ にまたがっています
概要
ロードバランシング：トラフィックを背後の複数の EC2、コンテナ、Lambda に分散し、異常なターゲットを自動的に避けます。ALB は HTTP/HTTPS、NLB は TCP/UDP を処理します。
主な用途
ウェブサイトや API の統一された入口、マルチ AZ の高可用性
ELB のサービスノート →

02S3必須

ストレージグループ · Serverless · 従量課金 · 価格 $60
ここでの役割
ELB が 5 分ごとにアクセスログを S3 に書き込み
使う理由
容量を計画する必要がなく、保存した分だけ支払います。データの耐久性は 99.999999999%（9 が 11 個）です。保存期間が長くなるにつれてアクセスが減るデータは、より安いストレージクラスへ自動で移すこともできます
概要
オブジェクトストレージ：ファイルを「オブジェクト」としてバケットに保存し、保存したデータ量とリクエスト数に応じて課金されます。容量を事前に計画する必要はありません。S3 Standard ストレージクラスは、1 つのリージョン内の 3 つ以上の AZ にデータを保存します。
主な用途
ウェブサイトの画像や静的アセット、データレイク、バックアップとアーカイブ、ログ
S3 のサービスノート →

03EventBridgeオプション

アプリケーション統合グループ · Serverless · 従量課金 · 価格 $240
ここでの役割
EventBridge に新規ファイルのイベントが先に届いてから振り分け
使う理由
イベントを送る側と処理する側が互いを知る必要がありません：処理する側を追加しても送信側を変更する必要がなく、スケジュールに従って起動することもできます
概要
サーバーレスのイベントバス：Amazon Web Services のサービス、自社のアプリケーション、SaaS から送られるイベントをルールに従って Lambda や Step Functions などに転送し、スケジュールでの起動もできます。
主な用途
イベント駆動型アーキテクチャ、アカウント間のイベント配信、定期実行タスク
EventBridge のサービスノート →

04Lambda必須

コンピューティンググループ · Serverless · 従量課金 · 価格 $220
ここでの役割
Lambda が 1 行ずつ解析
使う理由
コード量が少なく、イベントをきっかけに動く処理を任せられます：サーバーやスケーリングを管理する必要がなく、リクエストがなければ料金はかかりません
概要
サーバーレス関数：コードをアップロードすると、イベントが来たときだけ実行されます。リクエスト数と実行時間（ミリ秒単位）で課金され、リクエストがなければ料金はかかりません。1 回の実行は最長 15 分です。
主な用途
API バックエンド、S3 にアップロードされたファイルの処理、定期実行タスク
Lambda のサービスノート →

05OpenSearch必須

分析グループ · PaaS · 時間課金 · 価格 $360
ここでの役割
OpenSearch に書き込み、Dashboards で 5xx、遅いリクエスト、不審な IP をリアルタイムに検索
使う理由
全文検索、あいまい検索、ログのリアルタイム検索が必要なときに使います。これらをリレーショナルデータベースで行うと遅いうえ、データベースに負荷がかかります
概要
マネージドな OpenSearch（Elasticsearch から派生したオープンソースプロジェクト）：全文検索、ログ分析、可視化を行い、ベクトルデータベースとしても使えます。
主な用途
サイト内検索、ログ検索、RAG のベクトル検索
