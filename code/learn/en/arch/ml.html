What each piece does4 services

01S3RequiredOne of

Storage group · Serverless · By usage · Price $60
Role here
Training data is stored in S3 or EFS
Why use it
You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes
What it is
Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.
Common uses
Website images and static assets, data lakes, backup and archive, logs
S3 service notes →

01EFSRequiredOne of

Storage group · Serverless · By usage · Price $100
Role here
Training data is stored in S3 or EFS
Why use it
When several machines need to read and write the same files, you don't have to run your own NFS server, and capacity grows as you use it
What it is
Managed shared file system (NFS): multiple EC2 instances, containers and Lambda functions can mount the same directory at once; capacity grows as you write and you pay for what you use.
Common uses
Files shared across many servers, content management, machine learning training data
EFS service notes →
How to choose

For large training datasets read as whole files, use S3 (cheaper); when several machines need to share reads and writes like a local disk, use EFS

02ECRRequired

Containers group · Managed · By usage · Price $180
Role here
Your own training image is stored in ECR
Why use it
Images sit right next to where they're deployed: permissions work directly with ECS and EKS, and images are scanned for vulnerabilities when you push them
What it is
Managed container image registry: stores Docker and OCI images and can scan for vulnerabilities; ECS and EKS pull images directly from it.
Common uses
Push images here after a CI/CD build, and pull them at deployment

03SageMaker AIRequired

AI group · PaaS · By the hour · Price $460
Role here
SageMaker AI pulls the image, reads the data, then trains and deploys the model
Why use it
Use it when you need to train, fine-tune or deploy models yourself: training, tuning, deployment and monitoring in one platform
What it is
Machine learning platform: prepare data, train, tune, and deploy models in one place. Includes managed notebook environments, and inference endpoints are billed by instance hours.
Common uses
Training your own models, deploying inference services
