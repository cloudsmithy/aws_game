01API GatewayRequired

Networking group · Serverless · By usage · Price $220
Role here
API Gateway receives requests
Why use it
No need to build your own gateway: authorization, throttling, caching and version management work out of the box, with Lambda connected right behind it
What it is
Managed API front door: create REST, HTTP and WebSocket APIs, with authorization, throttling and caching, connected to Lambda or other services behind it and billed by number of calls.
Common uses
Serverless APIs, backends for mobile apps and mini programs

02LambdaRequired

Compute group · Serverless · By usage · Price $220
Role here
Lambda processes them: writes go to RDS or Aurora (relational databases such as SQL Server and MySQL, with connections pooled through RDS Proxy)
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks

03AuroraRequiredOne of

Database group · PaaS · By the hour · Price $280
Role here
Lambda processes them: writes go to RDS or Aurora (relational databases such as SQL Server and MySQL, with connections pooled through RDS Proxy)
Why use it
Choose it when you need MySQL or PostgreSQL with higher performance and availability: storage spans 3 AZs automatically, and read replicas have low lag
What it is
Amazon Web Services' own cloud-native relational database, compatible with MySQL and PostgreSQL: data is stored as 6 copies across 3 AZs, with up to 15 read replicas; Aurora Serverless v2 scales automatically with load, and Global Database can span Regions.
Common uses
High-concurrency core business databases
Aurora service notes →
How to choose

Aurora is compatible with MySQL and PostgreSQL and has better performance and high availability (storage spans 3 AZs); for SQL Server or Oracle, or to save money, use RDS

04DMSRequired

Database group · PaaS · By the hour · Price $340
Role here
DMS keeps syncing changes in the database to OpenSearch (CDC
Why use it
RDS and Aurora can't push data to OpenSearch on their own; DMS keeps syncing database changes over without any application code changes
What it is
Database migration service: moves databases from your data center or another cloud to Amazon Web Services, either homogeneous (MySQL to RDS for MySQL) or heterogeneous (Oracle to Aurora PostgreSQL). After the full load it keeps capturing changes on the source database (CDC), so old and new stay in sync and cutover downtime is short. Billed by the hour for replication instances; DMS Serverless is billed by usage.
Common uses
Moving databases to the cloud; syncing changes from your business database to a data lake, search, or data warehouse in real time (CDC)
DMS service notes →

05OpenSearchRequired

Analytics group · PaaS · By the hour · Price $360
Role here
OpenSearch handles queries and full-text search (not loading the primary)
Why use it
Use it for full-text search, fuzzy matching and real-time log search, which are slow on a relational database and put load on it
What it is
Managed OpenSearch (the open-source project forked from Elasticsearch): full-text search, log analytics and visualization, and it can also serve as a vector database.
Common uses
Site search, log search, vector search for RAG
