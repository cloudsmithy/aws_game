What each piece does6 services

01ELBRequired

Networking group · Managed · By the hour · Price $140
Role here
ELB spreads requests across multiple machines
Why use it
One entry point in front of multiple backends: it spreads traffic automatically, routes around failed instances, and spans AZs by design
What it is
Load balancing: spreads traffic across multiple EC2 instances, containers or Lambda functions behind it and automatically routes around unhealthy ones; ALB handles HTTP/HTTPS and NLB handles TCP/UDP.
Common uses
A single entry point for websites and APIs, Multi-AZ high availability

02EC2RequiredOne of

Compute group · IaaS · By the hour · Price $100
Role here
Applications on EC2, ECS, or EKS all mount the same EFS file system
Why use it
Use it when you need full control of the operating system, special software or legacy apps; it has the widest range of instance types
What it is
Virtual servers in the cloud: you pick CPU, memory and operating system, billed by the second, and you can buy them On-Demand, with Savings Plans, as Spot and more. Each instance lives in one AZ, so for high availability you place several in multiple AZs, together with ELB and Auto Scaling.
Common uses
Running all kinds of applications, cases that need full control of the operating system
EC2 service notes →

02ECSRequiredOne of

Containers group · Containers · By the hour · Price $180
Role here
Applications on EC2, ECS, or EKS all mount the same EFS file system
Why use it
Choose it when you want to run containers without learning Kubernetes; with Fargate you don't even manage machines
What it is
Amazon Web Services' own container orchestration service: tell it how many tasks to run and it schedules them and replaces failed ones; the underlying compute can be EC2 or Fargate (no servers to manage).
Common uses
Microservices, batch jobs
ECS service notes →

02EKSRequiredOne of

Containers group · Containers · By the hour · Price $200
Role here
Applications on EC2, ECS, or EKS all mount the same EFS file system
Why use it
Choose it when your team already uses Kubernetes and wants to keep using Helm and community tools
What it is
Managed Kubernetes: Amazon Web Services runs the control plane across multiple AZs and each cluster is billed by the hour; worker nodes can use EC2, managed node groups, Fargate or Auto Mode.
Common uses
Teams already using Kubernetes moving to the cloud, unified deployment across environments
EKS service notes →
How to choose

For full control of the operating system, use EC2; for containers with less to manage, use ECS; if your team knows Kubernetes, choose EKS

03EFSRequired

Storage group · Serverless · By usage · Price $100
Role here
Applications on EC2, ECS, or EKS all mount the same EFS file system
Why use it
When several machines need to read and write the same files, you don't have to run your own NFS server, and capacity grows as you use it
What it is
Managed shared file system (NFS): multiple EC2 instances, containers and Lambda functions can mount the same directory at once; capacity grows as you write and you pay for what you use.
Common uses
Files shared across many servers, content management, machine learning training data
EFS service notes →

04VPCOptional

Networking group · Managed · Free · Price $140
Role here
VPC has an EFS mount target in the subnet of every AZ
Why use it
Put resources in your own private network, where subnets and security groups decide who can reach them, so databases don't have to be exposed to the internet
What it is
Your private network in the cloud: you define the CIDR range, subnets, route tables and security groups, and decide which resources can reach the internet. The VPC itself is free.
Common uses
Put the public-facing load balancer in a public subnet, and the application and database in private subnets
