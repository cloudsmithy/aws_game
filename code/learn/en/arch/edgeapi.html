What each piece does4 services

01CloudFrontRequired

Networking group · Global service · By usage · Price $400
Role here
CloudFront takes the request at the edge
Why use it
Put it at the very front when users are spread out and there's a lot of static content: responses come from nearby, the origin carries less load, and attacks can be blocked at the edge
What it is
CDN: caches your website, video and APIs at edge locations around the world so users connect to the nearest one, which takes load off the origin. Comes with Shield Standard against common DDoS attacks.
Common uses
Speeding up websites and static assets, video delivery
CloudFront service notes →

02WAFRequired

Security group · Managed · By usage · Price $400
Role here
WAF filters malicious traffic
Why use it
Blocks SQL injection, XSS, malicious bots and API abuse with rules at the entry point, without changing application code
What it is
Web application firewall: sits in front of CloudFront, ALB, or API Gateway and blocks SQL injection, cross-site scripting, and malicious bots by rule. It can also rate-limit by IP.
Common uses
Defending against common web attacks, preventing API abuse
WAF service notes →

03API GatewayRequired

Networking group · Serverless · By usage · Price $220
Role here
API Gateway handles it
Why use it
No need to build your own gateway: authorization, throttling, caching and version management work out of the box, with Lambda connected right behind it
What it is
Managed API front door: create REST, HTTP and WebSocket APIs, with authorization, throttling and caching, connected to Lambda or other services behind it and billed by number of calls.
Common uses
Serverless APIs, backends for mobile apps and mini programs
API Gateway service notes →

04LambdaOptional

Compute group · Serverless · By usage · Price $220
Role here
Lambda runs the backend logic
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
