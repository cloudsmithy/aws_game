What each piece does3 services

01EventBridgeRequired

Application Integration group · Serverless · By usage · Price $240
Role here
EventBridge receives alarms and Health events
Why use it
Event senders and event handlers don't need to know each other: adding a handler doesn't require changing the sender, and it can also trigger on a schedule
What it is
Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.
Common uses
Event-driven architectures, distributing events across accounts, scheduled tasks
EventBridge service notes →

02AgentCoreRequired

AI group · Serverless · By usage · Price $100
Role here
An AgentCore agent reads logs and checks metrics to find the root cause
Why use it
The runtime isolation, session memory, tool gateway and identity that agents need in production are all managed, so you don't have to build them yourself
What it is
Bedrock AgentCore: a managed platform for taking AI agents to production. Runtime hosts and runs agents (frameworks such as LangGraph, CrewAI and Strands all work), each session runs in its own microVM, and you are billed for the compute actually used; components such as Memory, Gateway, Identity and Observability can be combined as needed.
Common uses
Customer service assistants, operations assistants, AI assistants that can call business APIs
AgentCore service notes →

03LambdaRequired

Compute group · Serverless · By usage · Price $220
Role here
The agent calls Lambda through Gateway to run the fix (restart, scale out, roll back)
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
