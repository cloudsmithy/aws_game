What each piece does4 services

01EBSRequired

Storage group · IaaS · By the hour · Price $120
Role here
EBS snapshots are protected by Snapshot Lock (in compliance mode nobody can delete them until the lock expires, not even the root user)
Why use it
EBS snapshots are stored in S3, and with Snapshot Lock, ransomware can't delete the backups even if it gets access
What it is
Block storage for EC2 (cloud disks): a volume attaches to an instance in the same AZ as a system or data disk, and snapshots can be taken as backups. A volume lives in a single AZ.
Common uses
System disks, data disks for self-managed databases
EBS service notes →

02S3Required

Storage group · Serverless · By usage · Price $60
Role here
Important files are kept in an S3 bucket with Object Lock enabled
Why use it
You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes
What it is
Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.
Common uses
Website images and static assets, data lakes, backup and archive, logs
S3 service notes →

03GuardDutyRequired

Security group · Managed · By usage · Price $380
Role here
GuardDuty Malware Protection scans EBS volumes and files newly uploaded to S3
Why use it
No agents to install: once it's on, it analyzes CloudTrail, VPC Flow Logs and DNS logs to find anomalies such as crypto mining and leaked credentials
What it is
Threat detection: continuously analyzes CloudTrail events, VPC Flow Logs, DNS logs and more to find crypto mining, leaked credentials, and unusual access. It only detects and does not block, so pair it with EventBridge and Lambda for automated response.
Common uses
Account security monitoring, automated response to security events
GuardDuty service notes →

04KMSOptional

Security group · Managed · By usage · Price $400
Role here
KMS customer managed keys encrypt snapshots and objects, with key permissions managed separately
Why use it
You don't have to keep keys yourself: services that store data can use it directly for encryption, and CloudTrail records who used each key
What it is
Managed key management: create and manage encryption keys that S3, EBS, RDS and other services use to encrypt data. Keys never leave KMS in plaintext, and every use is logged in CloudTrail.
Common uses
Encrypting data at rest, controlling who can decrypt data
