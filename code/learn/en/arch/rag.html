What each piece does5 services

01S3Required

Storage group · Serverless · By usage · Price $60
Role here
Documents go in S3
Why use it
You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes
What it is
Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.
Common uses
Website images and static assets, data lakes, backup and archive, logs
S3 service notes →

02LambdaOptional

Compute group · Serverless · By usage · Price $220
Role here
Lambda customizes how documents are split and cleaned
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
Lambda service notes →

03OpenSearchRequiredOne of

Analytics group · PaaS · By the hour · Price $360
Role here
Bedrock Knowledge Bases splits documents into chunks, computes vectors, and stores them in OpenSearch or Aurora PostgreSQL (pgvector)
Why use it
Use it for full-text search, fuzzy matching and real-time log search, which are slow on a relational database and put load on it
What it is
Managed OpenSearch (the open-source project forked from Elasticsearch): full-text search, log analytics and visualization, and it can also serve as a vector database.
Common uses
Site search, log search, vector search for RAG
OpenSearch service notes →

03AuroraRequiredOne of

Database group · PaaS · By the hour · Price $280
Role here
Bedrock Knowledge Bases splits documents into chunks, computes vectors, and stores them in OpenSearch or Aurora PostgreSQL (pgvector)
Why use it
Choose it when you need MySQL or PostgreSQL with higher performance and availability: storage spans 3 AZs automatically, and read replicas have low lag
What it is
Amazon Web Services' own cloud-native relational database, compatible with MySQL and PostgreSQL: data is stored as 6 copies across 3 AZs, with up to 15 read replicas; Aurora Serverless v2 scales automatically with load, and Global Database can span Regions.
Common uses
High-concurrency core business databases
Aurora service notes →
How to choose

For many vectors and hybrid search that combines keywords and vectors, choose OpenSearch; if you already use PostgreSQL and the data volume is small, choose Aurora (pgvector)

04BedrockRequired

AI group · Billed per token · Per token · Price $500
Role here
Bedrock Knowledge Bases splits documents into chunks, computes vectors, and stores them in OpenSearch or Aurora PostgreSQL (pgvector); Bedrock retrieves relevant passages and generates an answer with its sources
Why use it
Choose it when you want to use ready-made large models directly: one API for models from many providers, no GPUs to manage, and you pay per token
What it is
Call foundation models from multiple companies (Anthropic Claude, Amazon Nova, Meta Llama, Mistral, and more) through an API, billed per input and output token. Also includes Knowledge Bases, Agents, and Guardrails. Your data is not used to train models.
Common uses
Chatbots, content generation, AI agents
