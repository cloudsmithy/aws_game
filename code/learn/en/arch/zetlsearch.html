What each piece does4 services

01DynamoDBRequired

Database group · Serverless · By usage · Price $240
Role here
DynamoDB stores products and orders
Why use it
Use it when access patterns are fixed and concurrency is very high: there are no database servers to manage, and read and write latency stays steady at the millisecond level
What it is
Serverless key-value and document database: millisecond reads and writes, on-demand mode billed per request, data automatically stored across multiple AZs; global tables allow reads and writes in multiple Regions at once.
Common uses
User sessions, shopping carts, game data, high-concurrency workloads
DynamoDB service notes →

02OpenSearchRequired

Analytics group · PaaS · By the hour · Price $360
Role here
A Zero-ETL integration (OpenSearch Ingestion pipeline) syncs changes into OpenSearch automatically, so you write no sync code
Why use it
Use it for full-text search, fuzzy matching and real-time log search, which are slow on a relational database and put load on it
What it is
Managed OpenSearch (the open-source project forked from Elasticsearch): full-text search, log analytics and visualization, and it can also serve as a vector database.
Common uses
Site search, log search, vector search for RAG
OpenSearch service notes →

03LambdaRequired

Compute group · Serverless · By usage · Price $220
Role here
Lambda takes search requests and runs full-text, fuzzy, and distance-based searches in OpenSearch
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
Lambda service notes →

04API GatewayOptional

Networking group · Serverless · By usage · Price $220
Role here
Requests come in from API Gateway
Why use it
No need to build your own gateway: authorization, throttling, caching and version management work out of the box, with Lambda connected right behind it
What it is
Managed API front door: create REST, HTTP and WebSocket APIs, with authorization, throttling and caching, connected to Lambda or other services behind it and billed by number of calls.
Common uses
Serverless APIs, backends for mobile and web apps
