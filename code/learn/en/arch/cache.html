What each piece does8 services

01CognitoOptional

Security group · Managed · By usage · Price $80
Role here
ALB first sends signed-out users to Cognito to sign in
Why use it
You don't have to build sign-in yourself: password storage, MFA, password recovery and social sign-in are ready to use, and API Gateway and ALB can use it directly for authentication
What it is
User sign-in for your apps and websites: a user pool stores accounts and handles sign-up, sign-in and MFA, and issues JWT tokens after sign-in; an identity pool exchanges a signed-in user's identity for temporary Amazon Web Services credentials so the app can access services such as S3 directly. Billed by monthly active users (MAU).
Common uses
Sign-up and sign-in for apps and websites, adding sign-in checks to APIs (API Gateway and ALB both accept Cognito tokens directly), mobile apps uploading files straight to S3

02ELBRequired

Networking group · Managed · By the hour · Price $140
Role here
ELB distributes traffic
Why use it
One entry point in front of multiple backends: it spreads traffic automatically, routes around failed instances, and spans AZs by design
What it is
Load balancing: spreads traffic across multiple EC2 instances, containers or Lambda functions behind it and automatically routes around unhealthy ones; ALB handles HTTP/HTTPS and NLB handles TCP/UDP.
Common uses
A single entry point for websites and APIs, Multi-AZ high availability

03EC2RequiredOne of

Compute group · IaaS · By the hour · Price $100
Role here
EC2 or ECS runs the app
Why use it
Use it when you need full control of the operating system, special software or legacy apps; it has the widest range of instance types
What it is
Virtual servers in the cloud: you pick CPU, memory and operating system, billed by the second, and you can buy them On-Demand, with Savings Plans, as Spot and more. Each instance lives in one AZ, so for high availability you place several in multiple AZs, together with ELB and Auto Scaling.
Common uses
Running all kinds of applications, cases that need full control of the operating system
EC2 service notes →

03ECSRequiredOne of

Containers group · Containers · By the hour · Price $180
Role here
EC2 or ECS runs the app
Why use it
Choose it when you want to run containers without learning Kubernetes; with Fargate you don't even manage machines
What it is
Amazon Web Services' own container orchestration service: tell it how many tasks to run and it schedules them and replaces failed ones; the underlying compute can be EC2 or Fargate (no servers to manage).
Common uses
Microservices, batch jobs
ECS service notes →
How to choose

For full control of the operating system or legacy apps, use EC2; if you're already containerized and want less to manage, use ECS (with Fargate you don't even manage machines)

04ElastiCacheRequired

Database group · PaaS · By the hour · Price $300
Role here
The app checks ElastiCache for hot data first, and on a miss queries RDS, Aurora, or DynamoDB and writes the result back to the cache
Why use it
When the same data is read over and over, add an in-memory cache layer: sub-millisecond responses and much less load on the database
What it is
Managed in-memory cache: Valkey, Redis OSS and Memcached, with reads and writes in microseconds to milliseconds, placed in front of the database to absorb hot reads.
Common uses
Caching hot data, sessions, leaderboards

05RDSRequiredOne of

Database group · PaaS · By the hour · Price $280
Role here
The app checks ElastiCache for hot data first, and on a miss queries RDS, Aurora, or DynamoDB and writes the result back to the cache
Why use it
Use it when you need a relational database but don't want to run it yourself: backups, patching and Multi-AZ failover are managed, and it offers the widest choice of engines
What it is
Managed relational database: supports MySQL, PostgreSQL, MariaDB, Oracle, SQL Server and Db2, and handles backups, patching and failover for you. A Multi-AZ deployment keeps a standby instance in another AZ.
Common uses
Traditional business systems, e-commerce order databases

05AuroraRequiredOne of

Database group · PaaS · By the hour · Price $280
Role here
The app checks ElastiCache for hot data first, and on a miss queries RDS, Aurora, or DynamoDB and writes the result back to the cache
Why use it
Choose it when you need MySQL or PostgreSQL with higher performance and availability: storage spans 3 AZs automatically, and read replicas have low lag
What it is
Amazon Web Services' own cloud-native relational database, compatible with MySQL and PostgreSQL: data is stored as 6 copies across 3 AZs, with up to 15 read replicas; Aurora Serverless v2 scales automatically with load, and Global Database can span Regions.
Common uses
High-concurrency core business databases
Aurora service notes →

05DynamoDBRequiredOne of

Database group · Serverless · By usage · Price $240
Role here
The app checks ElastiCache for hot data first, and on a miss queries RDS, Aurora, or DynamoDB and writes the result back to the cache
Why use it
Use it when access patterns are fixed and concurrency is very high: there are no database servers to manage, and read and write latency stays steady at the millisecond level
What it is
Serverless key-value and document database: millisecond reads and writes, on-demand mode billed per request, data automatically stored across multiple AZs; global tables allow reads and writes in multiple Regions at once.
Common uses
User sessions, shopping carts, game data, high-concurrency workloads
DynamoDB service notes →
How to choose

For key-based reads and writes at very high concurrency, choose DynamoDB; for SQL and transactions, choose Aurora (better performance and high availability) or RDS (more engines, lower cost)
