What each piece does4 services

01GuardDutyRequired

Security group · Managed · By usage · Price $380
Role here
GuardDuty finds an anomaly
Why use it
No agents to install: once it's on, it analyzes CloudTrail, VPC Flow Logs and DNS logs to find anomalies such as crypto mining and leaked credentials
What it is
Threat detection: continuously analyzes CloudTrail events, VPC Flow Logs, DNS logs and more to find crypto mining, leaked credentials, and unusual access. It only detects and does not block, so pair it with EventBridge and Lambda for automated response.
Common uses
Account security monitoring, automated response to security events
GuardDuty service notes →

02EventBridgeRequired

Application Integration group · Serverless · By usage · Price $240
Role here
EventBridge routes it
Why use it
Event senders and event handlers don't need to know each other: adding a handler doesn't require changing the sender, and it can also trigger on a schedule
What it is
Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.
Common uses
Event-driven architectures, distributing events across accounts, scheduled tasks
EventBridge service notes →

03Step FunctionsRequired

Application Integration group · Serverless · By usage · Price $260
Role here
Step Functions handles it automatically by playbook
Why use it
No need to write your own state machine for multi-step processes: retries, timeouts and rollback on failure can be configured for each step, and you can see which step a run has reached
What it is
Visual workflow orchestration: chains Lambda, container tasks and API calls to many services into a state machine, with built-in retries, branching and parallelism, and can pause to wait for human approval.
Common uses
Order processing flows, data processing pipelines, orchestrating the steps of AI agents
Step Functions service notes →

04LambdaOptional

Compute group · Serverless · By usage · Price $220
Role here
Lambda performs actions such as isolating the instance and revoking keys
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
