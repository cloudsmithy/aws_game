What each piece does5 services

01S3Required

Storage group · Serverless · By usage · Price $60
Role here
A file is uploaded to S3
Why use it
You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes
What it is
Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.
Common uses
Website images and static assets, data lakes, backup and archive, logs
S3 service notes →

02EventBridgeOptional

Application Integration group · Serverless · By usage · Price $240
Role here
The event goes to EventBridge first, which filters and forwards it by rule
Why use it
Event senders and event handlers don't need to know each other: adding a handler doesn't require changing the sender, and it can also trigger on a schedule
What it is
Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.
Common uses
Event-driven architectures, distributing events across accounts, scheduled tasks
EventBridge service notes →

03SQSRequired

Application Integration group · Serverless · By usage · Price $240
Role here
SQS queues it
Why use it
Put a queue between two stages that process at different speeds: peaks wait in the queue, the backend pulls at its own pace, and failed messages can be retried
What it is
Managed message queue: producers put messages in the queue and consumers take them at their own pace. Standard queues deliver at least once; FIFO queues guarantee order.
Common uses
Smoothing order spikes, decoupling systems so they don't drag each other down, asynchronous tasks
SQS service notes →

04LambdaRequired

Compute group · Serverless · By usage · Price $220
Role here
Lambda pulls messages in batches and processes them, retrying failures
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
Lambda service notes →

05DynamoDBOptional

Database group · Serverless · By usage · Price $240
Role here
The results are recorded in DynamoDB
Why use it
Use it when access patterns are fixed and concurrency is very high: there are no database servers to manage, and read and write latency stays steady at the millisecond level
What it is
Serverless key-value and document database: millisecond reads and writes, on-demand mode billed per request, data automatically stored across multiple AZs; global tables allow reads and writes in multiple Regions at once.
Common uses
User sessions, shopping carts, game data, high-concurrency workloads
