What each piece does4 services

01Route 53Required

Networking group · Global service · By usage · Price $160
Role here
Route 53 resolves the domain
Why use it
DNS resolution and health checks together: if one side goes down, traffic switches to the other automatically
What it is
Managed DNS: registers and resolves domain names, can fail over based on health checks, and routes users to different Regions by latency or geolocation. A global service with a 100% availability SLA.
Common uses
Domain name resolution, cross-Region disaster recovery failover
Route 53 service notes →

02CloudFrontRequired

Networking group · Global service · By usage · Price $400
Role here
CloudFront caches globally
Why use it
Put it at the very front when users are spread out and there's a lot of static content: responses come from nearby, the origin carries less load, and attacks can be blocked at the edge
What it is
CDN: caches your website, video and APIs at edge locations around the world so users connect to the nearest one, which takes load off the origin. Comes with Shield Standard against common DDoS attacks.
Common uses
Speeding up websites and static assets, video delivery
CloudFront service notes →

03WAFOptional

Security group · Managed · By usage · Price $400
Role here
WAF blocks malicious requests
Why use it
Blocks SQL injection, XSS, malicious bots and API abuse with rules at the entry point, without changing application code
What it is
Web application firewall: sits in front of CloudFront, ALB, or API Gateway and blocks SQL injection, cross-site scripting, and malicious bots by rule. It can also rate-limit by IP.
Common uses
Defending against common web attacks, preventing API abuse
WAF service notes →

04S3Required

Storage group · Serverless · By usage · Price $60
Role here
S3 stores the web files
Why use it
You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes
What it is
Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.
Common uses
Website images and static assets, data lakes, backup and archive, logs
