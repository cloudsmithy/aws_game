What each piece does4 services

01S3Required

Storage group · Serverless · By usage · Price $60
Role here
An image is uploaded to S3
Why use it
You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes
What it is
Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.
Common uses
Website images and static assets, data lakes, backup and archive, logs
S3 service notes →

02EventBridgeOptional

Application Integration group · Serverless · By usage · Price $240
Role here
EventBridge first receives the S3 event and filters it by rule (images only, one folder only) before routing
Why use it
Event senders and event handlers don't need to know each other: adding a handler doesn't require changing the sender, and it can also trigger on a schedule
What it is
Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.
Common uses
Event-driven architectures, distributing events across accounts, scheduled tasks
EventBridge service notes →

03LambdaRequired

Compute group · Serverless · By usage · Price $220
Role here
Lambda generates the thumbnail and writes it back to S3
Why use it
Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost
What it is
Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.
Common uses
API backends, processing files uploaded to S3, scheduled tasks
Lambda service notes →

04CloudFrontRequired

Networking group · Global service · By usage · Price $400
Role here
CloudFront serves images from S3 close to users
Why use it
Put it at the very front when users are spread out and there's a lot of static content: responses come from nearby, the origin carries less load, and attacks can be blocked at the edge
What it is
CDN: caches your website, video and APIs at edge locations around the world so users connect to the nearest one, which takes load off the origin. Comes with Shield Standard against common DDoS attacks.
Common uses
Speeding up websites and static assets, video delivery
