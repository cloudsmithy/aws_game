What each piece does6 services

01ECRRequired

Containers group · Managed · By usage · Price $180
Role here
An image is pushed to ECR and Inspector scans it for vulnerabilities right away
Why use it
Images sit right next to where they're deployed: permissions work directly with ECS and EKS, and images are scanned for vulnerabilities when you push them
What it is
Managed container image registry: stores Docker and OCI images and can scan for vulnerabilities; ECS and EKS pull images directly from it.
Common uses
Push images here after a CI/CD build, and pull them at deployment
ECR service notes →

02InspectorRequired

Security group · Managed · By usage · Price $380
Role here
Inspector findings are sent to EventBridge, which automatically notifies the owner and opens a ticket
Why use it
Finds vulnerabilities in EC2, container images and Lambda automatically, so when a new CVE comes out, you don't have to wait for someone to run a scan
What it is
Automated vulnerability scanning: continuously scans EC2 instances, container images in ECR, and Lambda functions for software vulnerabilities and unintended network exposure, and scores them by risk.
Common uses
Patch management, compliance checks
Inspector service notes →

03ECSRequiredOne of

Containers group · Containers · By the hour · Price $180
Role here
Only images with no critical vulnerabilities are deployed to ECS, EKS, or EC2
Why use it
Choose it when you want to run containers without learning Kubernetes; with Fargate you don't even manage machines
What it is
Amazon Web Services' own container orchestration service: tell it how many tasks to run and it schedules them and replaces failed ones; the underlying compute can be EC2 or Fargate (no servers to manage).
Common uses
Microservices, batch jobs
ECS service notes →

03EKSRequiredOne of

Containers group · Containers · By the hour · Price $200
Role here
Only images with no critical vulnerabilities are deployed to ECS, EKS, or EC2
Why use it
Choose it when your team already uses Kubernetes and wants to keep using Helm and community tools
What it is
Managed Kubernetes: Amazon Web Services runs the control plane across multiple AZs and each cluster is billed by the hour; worker nodes can use EC2, managed node groups, Fargate or Auto Mode.
Common uses
Teams already using Kubernetes moving to the cloud, unified deployment across environments
EKS service notes →

03EC2RequiredOne of

Compute group · IaaS · By the hour · Price $100
Role here
Only images with no critical vulnerabilities are deployed to ECS, EKS, or EC2
Why use it
Use it when you need full control of the operating system, special software or legacy apps; it has the widest range of instance types
What it is
Virtual servers in the cloud: you pick CPU, memory and operating system, billed by the second, and you can buy them On-Demand, with Savings Plans, as Spot and more. Each instance lives in one AZ, so for high availability you place several in multiple AZs, together with ELB and Auto Scaling.
Common uses
Running all kinds of applications, cases that need full control of the operating system
EC2 service notes →
How to choose

For full control of the operating system, use EC2; for containers with less to manage, use ECS; if your team knows Kubernetes, choose EKS

04EventBridgeOptional

Application Integration group · Serverless · By usage · Price $240
Role here
Inspector findings are sent to EventBridge, which automatically notifies the owner and opens a ticket
Why use it
Event senders and event handlers don't need to know each other: adding a handler doesn't require changing the sender, and it can also trigger on a schedule
What it is
Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.
Common uses
Event-driven architectures, distributing events across accounts, scheduled tasks
