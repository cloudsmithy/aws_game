DMS

Database groupPaaSBy the hourMulti-AZ is on you

Database migration service: moves databases from your data center or another cloud to Amazon Web Services, either homogeneous (MySQL to RDS for MySQL) or heterogeneous (Oracle to Aurora PostgreSQL). After the full load it keeps capturing changes on the source database (CDC), so old and new stay in sync and cutover downtime is short. Billed by the hour for replication instances; DMS Serverless is billed by usage.

Common uses

Moving databases to the cloud; syncing changes from your business database to a data lake, search, or data warehouse in real time (CDC)

Why use it

No code changes on the source database: it does a full load first, then keeps capturing changes (CDC), so migration cutover downtime is short; day to day it can also sync changes in real time to search, a data lake or a data warehouse

Key concepts5 points

  1. Database migration service: a full load first, then ongoing replication of changes (CDC), while the source database keeps serving traffic during the migration
  2. Homogeneous migrations (MySQL to RDS for MySQL) move over directly; heterogeneous migrations (Oracle to Aurora PostgreSQL) first use Schema Conversion to convert the schema and stored procedures
  3. The replication instance runs in your VPC; you can also use DMS Serverless, which scales automatically with usage
  4. Targets aren't only databases: they can also be S3, Kinesis, OpenSearch, or Redshift, for syncing data lakes, search, and data warehouses
  5. Data validation checks whether the data in the source and target databases matches

Three key featuresThe game's three upgrade levels are these three real-world features

LV.1 · Level 1

Multi-AZ replication instance

The replication instance keeps a synchronous standby in another AZ; if the AZ of the primary fails, it switches over automatically and migration and ongoing replication continue

In the game: Survives an AZ power outage and single points of failure

Running cost: $20 per lap

LV.2 · Level 2

DMS Serverless

No need to pick a replication instance size; it scales automatically by the capacity units (DCU) actually used and is billed by usage

In the game: Running cost or request fees halved

Running cost: $15 per lap

LV.3 · Level 3

Schema Conversion

Automatically converts the schema, stored procedures, and functions from Oracle and SQL Server to work with Aurora PostgreSQL and MySQL, so changing database engines doesn't need manual rewriting

In the game: Rent on this square +20%

Running cost: $20 per lap

1.When migrating a database with DMS, what should you turn on to keep the old and new databases in sync until cutover?
AnswerContinuous replication with CDC after the full load completes
After the full load finishes, DMS keeps capturing changes (CDC) from the source database and applies them to the new database, so cutover needs only a very short downtime
2.When migrating Oracle to Aurora PostgreSQL, what do you use to convert the table schema and stored procedures?
AnswerDMS Schema Conversion (formerly SCT)
For a heterogeneous migration, first convert the table schema and code objects with DMS Schema Conversion or SCT, then move the data with a DMS replication task
