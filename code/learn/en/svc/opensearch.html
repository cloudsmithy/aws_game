OpenSearch

Analytics groupPaaSBy the hourMulti-AZ is on you

Managed OpenSearch (the open-source project forked from Elasticsearch): full-text search, log analytics and visualization, and it can also serve as a vector database.

Common uses

Site search, log search, vector search for RAG

Why use it

Use it for full-text search, fuzzy matching and real-time log search, which are slow on a relational database and put load on it

Key concepts5 points

  1. Managed OpenSearch (an open source project forked from Elasticsearch 7.10): full-text search and log analytics, with OpenSearch Dashboards for visualization
  2. Two forms: managed domains (you choose the node types) and OpenSearch Serverless (collections that scale automatically)
  3. The vector engine does k-NN vector search and is often used as the vector store for RAG
  4. For production, a Multi-AZ deployment with dedicated cluster manager nodes is recommended; keep cold data in UltraWarm or cold storage to save money
  5. OpenSearch Ingestion is a managed data pipeline that can bring in data from S3, DynamoDB (Zero-ETL), and more

Three key featuresThe game's three upgrade levels are these three real-world features

Compare and choose

OpenSearch or Redshift

For full-text search and real-time log search, choose OpenSearch; for large-scale SQL analytics and reports, choose Redshift

Aurora or OpenSearch

For many vectors and hybrid search that combines keywords and vectors, choose OpenSearch; if you already use PostgreSQL and the data volume is small, choose Aurora (pgvector)

OpenSearch or Redshift or S3

For cheap long-term storage and offline analysis, use an S3 data lake; for SQL reports in seconds, load the data into Redshift; for real-time search, load it into OpenSearch
