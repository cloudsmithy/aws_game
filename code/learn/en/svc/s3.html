S3

Storage groupServerlessBy usageMulti-AZ built in

Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.

Common uses

Website images and static assets, data lakes, backup and archive, logs

Why use it

You don't need to plan capacity, you pay for what you store, and durability is 11 nines; data that gets colder over time can move automatically to cheaper storage classes

Key concepts6 points

  1. Object storage: data is stored and retrieved by “bucket + key”; it isn't a file system or a disk attached to a machine
  2. Storage classes from hot to cold: S3 Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, Glacier Deep Archive; the colder, the cheaper, but retrieval is slower or costs extra
  3. Since December 2020, reads and writes are strongly consistent: read right after a write and you get the new data
  4. New buckets have Block Public Access on and ACLs disabled by default, and new objects are encrypted with SSE-S3 by default
  5. Versioning, lifecycle rules and Object Lock (write once, read many) work together to protect against accidental deletion and ransomware
  6. Event notifications can trigger Lambda directly, or be sent to SQS, SNS or EventBridge

Three key featuresThe game's three upgrade levels are these three real-world features

LV.1 · Level 1

Versioning

Keeps every version of each object, so accidental deletes and edits can be recovered

In the game: Immune to accidental data deletion

Running cost: 15% request fees each time rent is received, plus $5 per lap

LV.2 · Level 2

Intelligent-Tiering

Automatically moves data to cheaper storage tiers based on access frequency

In the game: Running cost or request fees halved

Running cost: 8% request fees each time rent is received, plus $5 per lap

LV.3 · Level 3

Automatic thumbnail generation

As soon as an image is uploaded, an S3 event notification triggers Lambda to generate a thumbnail and write it back to another bucket or prefix

In the game: Rent on this square +20%

Running cost: 8% request fees each time rent is received, plus $5 per lap

Compare and choose

EFS or S3

For large training datasets read as whole files, use S3 (cheaper); when several machines need to share reads and writes like a local disk, use EFS

OpenSearch or Redshift or S3

For cheap long-term storage and offline analysis, use an S3 data lake; for SQL reports in seconds, load the data into Redshift; for real-time search, load it into OpenSearch

Correct 0 / 8, answered 0

1.How can instances in a private subnet access S3 without going through a NAT gateway and without paying data processing fees?
AnswerCreate an S3 gateway endpoint
Gateway endpoints for S3 and DynamoDB are free
2.For archive data in S3 that is rarely accessed but must be kept for years, which storage class is cheapest?
AnswerS3 Glacier Deep Archive
Standard retrieval within 12 hours and bulk within 48 hours, much slower than Flexible Retrieval; minimum storage duration 180 days
3.Do services like S3 and EFS need you to set up Multi-AZ yourself?
AnswerNo, they store data across multiple AZs by default
S3 Standard stores data in at least 3 AZs; single-zone classes such as S3 One Zone-IA and EFS One Zone are exceptions
4.What is the designed durability of S3 Standard storage?
Answer99.999999999% (11 nines)
Durability is 11 nines; availability is a different matter
5.What is the maximum size of a single S3 object?
Answer50 TB
Raised from 5 TB to 50 TB in December 2025; a single PUT is at most 5 GB, and larger objects need multipart upload
6.Since April 2023, what is the default state of newly created S3 buckets?
AnswerBlock Public Access on, ACLs disabled
To make a bucket public, you must explicitly turn off Block Public Access yourself
7.What is characteristic of S3 Intelligent-Tiering?
AnswerIt automatically moves data between storage tiers based on access frequency, with no retrieval fees
Suited to data with unpredictable access patterns, with a small per-object monitoring fee
8.What is the cheapest way to query data on S3 with Athena?
AnswerUse a columnar format such as Parquet and partition the data
Athena charges by data scanned, so the less you scan, the cheaper it is
