Cognito

Security groupManagedBy usageMulti-AZ built in

User sign-in for your apps and websites: a user pool stores accounts and handles sign-up, sign-in and MFA, and issues JWT tokens after sign-in; an identity pool exchanges signed-in users for temporary Amazon Web Services credentials so the app can access services such as S3 directly. Billed by monthly active users (MAU).

Common uses

Sign-up and sign-in for apps and websites, adding sign-in checks to APIs (API Gateway and ALB both accept Cognito tokens directly), mobile apps uploading files straight to S3

Why use it

You don't have to build sign-in yourself: password storage, MFA, password recovery and social sign-in are ready to use, and API Gateway and ALB can use it directly for authentication

Key concepts5 points

  1. User pools: a user directory plus sign-in, with sign-up, passwords, MFA, social sign-in, and enterprise SAML and OIDC sign-in all built in; JWT tokens are issued after sign-in
  2. Identity pools: exchange a signed-in identity for temporary IAM credentials, so the app can call services such as S3 and DynamoDB directly
  3. API Gateway can validate tokens with a Cognito authorizer; ALB listener rules can authenticate users through Cognito directly
  4. Managed Login provides a ready-made sign-in page with customizable branding
  5. Billed by monthly active users (MAU)

Three key featuresThe game's three upgrade levels are these three real-world features

LV.1 · Level 1

MFA

Asks for a second check at sign-in on top of the password (SMS, email code, or an authenticator app), so a leaked password isn't enough to get in

In the game: Immune to “user accounts hit by credential stuffing” (a password alone can't log in); Immune to “failed a security audit”

Running cost: 15% request fees each time rent is received

LV.2 · Level 2

Social and enterprise sign-in

Connects social accounts such as Google and Apple, plus company SAML and OIDC identity providers, so users don't need yet another password and more people sign in

In the game: Rent on this square +20%

Running cost: 15% request fees each time rent is received

LV.3 · Level 3

Identity pools (federated identities)

Exchanges the identity from a user pool or social sign-in for temporary Amazon Web Services credentials, scoped by role, so the app calls services like S3 and DynamoDB directly without going through your own server

In the game: Running cost or request fees halved

Running cost: 8% request fees each time rent is received

1.What is the difference between Cognito user pools and identity pools?
AnswerA user pool handles sign-up and sign-in and issues tokens; an identity pool exchanges signed-in users for temporary Amazon Web Services credentials
A user pool is a user directory that handles sign-up, sign-in, and MFA and issues JWTs after sign-in; an identity pool exchanges the identity from a user pool or social sign-in for temporary credentials, used to access services such as S3 directly
2.What is the easiest way to let API Gateway admit only signed-in users?
AnswerConfigure a Cognito user pool authorizer on the API, and have requests carry the token obtained at sign-in
The API Gateway Cognito authorizer (a JWT authorizer for HTTP APIs) validates the token first, so requests that are not signed in or have an expired token are rejected at the gateway, and no validation logic is needed in Lambda
3.Someone is using passwords leaked elsewhere to attack your app with credential stuffing. Which Cognito feature fits best?
AnswerThreat protection: detects use of leaked passwords and unusual sign-ins, and blocks them or requires an extra MFA step based on risk
Threat protection (formerly called advanced security features, part of the Plus feature plan) checks for compromised credentials, and automatically blocks unusual sign-ins or asks for another verification based on the risk level
