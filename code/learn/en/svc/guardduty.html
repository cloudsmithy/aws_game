GuardDuty

Security groupManagedBy usageMulti-AZ built in

Threat detection: continuously analyzes CloudTrail events, VPC Flow Logs, DNS logs and more to find crypto mining, leaked credentials, and unusual access. It only detects and does not block, so pair it with EventBridge and Lambda for automated response.

Common uses

Account security monitoring, automated response to security events

Why use it

No agents to install: once it's on, it analyzes CloudTrail, VPC Flow Logs and DNS logs to find anomalies such as crypto mining and leaked credentials

Key concepts5 points

  1. Threat detection: analyzes CloudTrail management events, VPC Flow Logs, and DNS logs, with no agent to install
  2. Protections you can turn on: S3, EKS audit logs, Runtime Monitoring, Malware Protection, RDS login activity, and Lambda network activity
  3. Findings are graded by severity and can be sent to EventBridge for automated response
  4. For multiple accounts, a delegated administrator account manages them centrally
  5. Uses machine learning and threat intelligence to spot behavior such as crypto mining, leaked credentials, and unusual API calls

1.What data does GuardDuty mainly analyze?
AnswerCloudTrail, VPC Flow Logs, DNS logs, and more
Basic detection just needs to be turned on, with no collectors to deploy; runtime monitoring needs an agent, which can be managed automatically
2.After GuardDuty finds an anomaly, what is a common way to isolate the instance automatically?
AnswerAn EventBridge rule triggers a Lambda function to handle it
It can also trigger Step Functions to orchestrate a multi-step response; this is the “Automated Threat Response” architecture
