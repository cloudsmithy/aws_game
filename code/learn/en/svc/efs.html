SERVICEStorage group · Serverless

EFS

Storage groupServerlessBy usageMulti-AZ built in

Managed shared file system (NFS): multiple EC2 instances, containers and Lambda functions can mount the same directory at once; capacity grows as you write and you pay for what you use.

Common uses

Files shared across many servers, content management, machine learning training data

Why use it

When several machines need to read and write the same files, you don't have to run your own NFS server, and capacity grows as you use it

Key concepts5 points

  1. A managed NFS file system that EC2, ECS, EKS and Lambda can all mount, so multiple machines can read and write the same files at the same time
  2. Regional file systems store data across multiple AZs, with one mount target in each AZ; there are also cheaper One Zone file systems that live in a single AZ
  3. Storage classes are Standard, Infrequent Access and Archive; lifecycle management moves rarely used files to colder storage automatically
  4. Throughput modes: Elastic (scales automatically with actual usage), Provisioned and Bursting
  5. You pay for the storage you actually use, with no capacity to provision in advance; for Windows file shares, use FSx for Windows File Server

Compare and choose

EFS or S3

For large training datasets read as whole files, use S3 (cheaper); when several machines need to share reads and writes like a local disk, use EFS

1.What is the biggest difference between EFS and EBS?
AnswerEFS can be mounted by multiple instances at once, while an EBS volume is generally attached to only one
EBS has Multi-Attach, but only for some volume types and within the same AZ
2.What type of storage is EFS?
AnswerA shared file system that multiple instances can mount at the same time
EFS uses the NFS protocol and scales automatically with usage
3.Do services like S3 and EFS need you to set up Multi-AZ yourself?
AnswerNo, they store data across multiple AZs by default
S3 Standard stores data in at least 3 AZs; single-zone classes such as S3 One Zone-IA and EFS One Zone are exceptions
4.Multiple EC2 instances spread across multiple Availability Zones in the same Region need to access the same shared file system over NFS at the same time. Which service should they choose?CLF-C02
AnswerAmazon Elastic File System (Amazon EFS)
EFS supports concurrent access from multiple NFS clients, and compute instances in multiple Availability Zones of the same Region can all access it, which suits shared data. An EBS snapshot is a point-in-time backup of a volume and cannot be mounted directly as a shared file system. Official docs ↗
5.A content management system runs on a Linux EC2 Auto Scaling group spanning three Availability Zones. All instances must read and write the same set of files at the same time, and storage capacity must grow and shrink automatically as files are added and removed. Which storage should be chosen?SAA-C03
AnswerAn Amazon EFS Regional file system, with a mount target created in each Availability Zone
EFS is a managed shared file system based on NFS. A Regional file system stores data redundantly across multiple Availability Zones, can be accessed concurrently by a large number of instances, and scales capacity automatically as files are added and removed. Separate EBS volumes are not shared with each other, and sync scripts are complex and error-prone; FSx for Windows is for SMB and Windows workloads; instance store is temporary storage.
