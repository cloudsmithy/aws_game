CloudTrail

Monitoring groupBy usageBy usageWildcard service

Records API calls in your account: who did what, when, and from where. The console shows the last 90 days of management events by default; create a trail to store them in S3 long term.

Common uses

Security auditing, finding out who deleted a resource

Why use it

Records who called which API and when, so you can trace what happened after an incident

Key concepts5 points

  1. Records API calls in your account: who did what, when, and from where, for auditing and troubleshooting
  2. Event history shows the last 90 days of management events by default; to keep them long term, create a trail that delivers them to S3
  3. Data events (S3 object reads and writes, Lambda invocations, and more) must be turned on separately and are charged separately
  4. Log file integrity validation proves that logs haven't been altered; an organization trail covers all accounts at once
  5. CloudTrail Lake lets you query events with SQL

1.In a multi-account environment, what do you use to enforce that “no one can turn off CloudTrail”?
AnswerOrganizations service control policies (SCPs)
SCPs are the backstop at the organization level, and even account administrators can't bypass them
2.What does CloudTrail record?
AnswerAPI calls in your account

3.What data does GuardDuty mainly analyze?
AnswerCloudTrail, VPC Flow Logs, DNS logs, and more
Basic detection just needs to be turned on, with no collectors to deploy; runtime monitoring needs an agent, which can be managed automatically
4.A financial company requires sensitive data in S3 to be encrypted at rest, and requires that it can decide which IAM principals may use the encryption key, manage key rotation itself, and audit key usage through CloudTrail. Which approach meets all the requirements?SAA-C03
AnswerUse SSE-KMS with a customer managed KMS key, and control access through the key policy
The key policy of a customer managed key is managed by the customer, who can enable automatic or on-demand rotation, and key usage is logged to CloudTrail. SSE-S3 doesn't let you control key permissions separately; neither the properties nor the key policy of an Amazon Web Services managed key can be modified; a hard-coded key is both insecure and impossible to audit centrally. 5.An EC2 instance was terminated last night, and the team wants to find out which user or role called the API, and when. Which service's records should they check?CLF-C02
AnswerCloudTrail
CloudTrail records actions taken by users, roles, or Amazon Web Services services as events, covering the console, CLI, SDK, and API calls, which makes it suitable for auditing “who did what.” CloudWatch metrics reflect resource performance data and do not record who made an API call.
