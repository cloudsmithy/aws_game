Storage group

3 services

Files, objects and disks: where data lives and how it's backed up

S3Storage · Serverless

Object storage: files are stored as “objects” in buckets and billed by the amount of data stored and the number of requests, with no capacity planning. The Standard storage class stores data across at least 3 AZs in one Region.

Concepts 6Questions 8Architectures 16
EFSStorage · Serverless

Managed shared file system (NFS): multiple EC2 instances, containers and Lambda functions can mount the same directory at once; capacity grows as you write and you pay for what you use.

Concepts 5Questions 5Architectures 2
EBSStorage · IaaS

Block storage for EC2 (cloud disks): a volume attaches to an instance in the same AZ as a system or data disk, and snapshots can be taken as backups. A volume lives in a single AZ.

Compute group

2 services

Where code runs: virtual machines, or functions that run on events

LambdaCompute · Serverless

Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.

Concepts 9Questions 8Architectures 26
EC2Compute · IaaS

Virtual servers in the cloud: you pick CPU, memory and operating system, billed by the second, and you can buy them On-Demand, with Savings Plans, as Spot and more. Each instance lives in one AZ, so for high availability you place several in multiple AZs, together with ELB and Auto Scaling.

Networking group

5 services

How traffic gets in and where it goes: private networks, load balancing, domains, CDN, API entry points

VPCNetworking · Managed

Your private network in the cloud: you define the CIDR range, subnets, route tables and security groups, and decide which resources can reach the internet. The VPC itself is free.

Concepts 5Questions 7Architectures 2
CloudFrontNetworking · Global service

CDN: caches your website, video and APIs at edge locations around the world so users connect to the nearest one, which takes load off the origin. Comes with Shield Standard against common DDoS attacks.

Concepts 5Questions 8Architectures 9
ELBNetworking · Managed

Load balancing: spreads traffic across multiple EC2 instances, containers or Lambda functions behind it and automatically routes around unhealthy ones; ALB handles HTTP/HTTPS and NLB handles TCP/UDP.

Concepts 5Questions 7Architectures 9
API GatewayNetworking · Serverless

Managed API front door: create REST, HTTP and WebSocket APIs, with authorization, throttling and caching, connected to Lambda or other services behind it and billed by number of calls.

Concepts 5Questions 3Architectures 8
Route 53Networking · Global service

Managed DNS: registers and resolves domain names, can fail over based on health checks, and routes users to different Regions by latency or geolocation. A global service with a 100% availability SLA.

Containers group

Package apps as container images, then deploy and orchestrate them in a uniform way

ECRContainers · Managed

Managed container image registry: stores Docker and OCI images and can scan for vulnerabilities; ECS and EKS pull images directly from it.

ECSContainers · Containers

Amazon Web Services' own container orchestration service: tell it how many tasks to run and it schedules them and replaces failed ones; the underlying compute can be EC2 or Fargate (no servers to manage).

EKSContainers · Containers

Managed Kubernetes: Amazon Web Services runs the control plane across multiple AZs and each cluster is billed by the hour; worker nodes can use EC2, managed node groups, Fargate or Auto Mode.

Application Integration group

3 services

Pass messages, send events and orchestrate workflows between services, decoupling producers from consumers

SQSApplication Integration · Serverless

Managed message queue: producers put messages in the queue and consumers take them at their own pace. Standard queues deliver at least once; FIFO queues guarantee order.

Concepts 5Questions 7Architectures 4
EventBridgeApplication Integration · Serverless

Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.

Concepts 5Questions 4Architectures 14
Step FunctionsApplication Integration · Serverless

Visual workflow orchestration: chains Lambda, container tasks and API calls to many services into a state machine, with built-in retries, branching and parallelism, and can pause to wait for human approval.

Database group

5 services

Store business data: relational databases, key-value databases, caches, plus DMS for moving databases

RDSDatabase · PaaS

Managed relational database: supports MySQL, PostgreSQL, MariaDB, Oracle, SQL Server and Db2, and handles backups, patching and failover for you. A Multi-AZ deployment keeps a standby instance in another AZ.

Concepts 5Questions 8Architectures 7
AuroraDatabase · PaaS

Amazon Web Services' own cloud-native relational database, compatible with MySQL and PostgreSQL: data is stored as 6 copies across 3 AZs, with up to 15 read replicas; Aurora Serverless v2 scales automatically with load, and Global Database can span Regions.

Concepts 5Questions 6Architectures 10
DMSDatabase · PaaS

Database migration service: moves databases from your data center or another cloud to Amazon Web Services, either homogeneous (MySQL to RDS for MySQL) or heterogeneous (Oracle to Aurora PostgreSQL). After the full load it keeps capturing changes on the source database (CDC), so old and new stay in sync and cutover downtime is short. Billed by the hour for replication instances; DMS Serverless is billed by usage.

Concepts 5Questions 2Architectures 3
DynamoDBDatabase · Serverless

Serverless key-value and document database: millisecond reads and writes, on-demand mode billed per request, data automatically stored across multiple AZs; global tables allow reads and writes in multiple Regions at once.

Concepts 5Questions 7Architectures 12
ElastiCacheDatabase · PaaS

Managed in-memory cache: Valkey, Redis OSS and Memcached, with reads and writes in microseconds to milliseconds, placed in front of the database to absorb hot reads.

Analytics group

5 services

Process and query data: real-time streams, ETL, SQL queries, data warehouses, search

KinesisAnalytics · Managed

Real-time data streaming: Kinesis Data Streams absorbs large numbers of events per second and lets multiple applications read at once; Data Firehose can deliver data straight into S3, Redshift and OpenSearch.

Concepts 5Questions 5Architectures 4
RedshiftAnalytics · PaaS

Cloud data warehouse: columnar storage and massively parallel processing, analyzing huge amounts of data with SQL; available as provisioned clusters or Redshift Serverless.

Concepts 5Questions 4Architectures 4
GlueAnalytics · Serverless

Serverless data integration (ETL) service: crawls data sources to build a data catalog, cleans and transforms data with Spark jobs, and is billed by run time.

AthenaAnalytics · Serverless

Serverless interactive query: query data in S3 directly with SQL, with no cluster to build, billed by the amount of data scanned. Storing data in columnar formats and partitioning by date means far less is scanned, which saves money.

Concepts 5Questions 3Architectures 3
OpenSearchAnalytics · PaaS

Managed OpenSearch (the open-source project forked from Elasticsearch): full-text search, log analytics and visualization, and it can also serve as a vector database.

Security group

6 services

Identity, encryption and protection: sign-in, keys, threat detection, vulnerability scanning, firewalls, DDoS protection

GuardDutySecurity · Managed

Threat detection: continuously analyzes CloudTrail events, VPC Flow Logs, DNS logs and more to find crypto mining, leaked credentials, and unusual access. It only detects and does not block, so pair it with EventBridge and Lambda for automated response.

Concepts 5Questions 3Architectures 3
InspectorSecurity · Managed

Automated vulnerability scanning: continuously scans EC2 instances, container images in ECR, and Lambda functions for software vulnerabilities and unintended network exposure, and scores them by risk.

Concepts 5Questions 2Architectures 2
WAFSecurity · Managed

Web application firewall: sits in front of CloudFront, ALB, or API Gateway and blocks SQL injection, cross-site scripting, and malicious bots by rule. It can also rate-limit by IP.

Concepts 5Questions 3Architectures 5
CognitoSecurity · Managed

User sign-in for your apps and websites: a user pool stores accounts and handles sign-up, sign-in and MFA, and issues JWT tokens after sign-in; an identity pool exchanges a signed-in user's identity for temporary Amazon Web Services credentials so the app can access services such as S3 directly. Billed by monthly active users (MAU).

Concepts 5Questions 3Architectures 10
KMSSecurity · Managed

Managed key management: create and manage encryption keys that S3, EBS, RDS and other services use to encrypt data. Keys never leave KMS in plaintext, and every use is logged in CloudTrail.

Concepts 5Questions 5Architectures 2
Shield AdvancedSecurity · Global service

DDoS protection: Shield Standard is included free on every account and blocks common network-layer attacks. Shield Advanced is a paid subscription that adds application-layer protection, Shield Response Team (SRT) support, and credits for scaling costs during an attack.

AI group

3 services

Models and agents: call large models, train your own models, host agents

AgentCoreAI · Serverless

Bedrock AgentCore: a managed platform for taking AI agents to production. Runtime hosts and runs agents (frameworks such as LangGraph, CrewAI and Strands all work), each session runs in its own microVM, and you are billed for the compute actually used; components such as Memory, Gateway, Identity and Observability can be combined as needed.

SageMaker AIAI · PaaS

Machine learning platform: prepare data, train, tune, and deploy models in one place. Includes managed notebook environments, and inference endpoints are billed by instance hours.

Call foundation models from multiple companies (Anthropic Claude, Amazon Nova, Meta Llama, Mistral, and more) through an API, billed per input and output token. Also includes Knowledge Bases, Agents, and Guardrails. Your data is not used to train models.

Monitoring and observability: collects metrics, logs, and events, sets alarms, and builds dashboards. Alarms can notify people or trigger Auto Scaling.

Configuration recording and compliance checks: continuously records the configuration and change history of every resource in your account, and checks compliance with rules (for example, whether an S3 bucket is public or an EBS volume is encrypted). Noncompliant resources can be remediated automatically.
