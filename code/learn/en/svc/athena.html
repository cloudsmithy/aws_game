Athena

Analytics groupServerlessBy usageMulti-AZ built in

Serverless interactive query: query data in S3 directly with SQL, with no cluster to build, billed by the amount of data scanned. Storing data in columnar formats and partitioning by date means far less is scanned, which saves money.

Common uses

Log analysis, ad hoc data lake queries

Why use it

The easiest way to query data in S3 now and then: no database to set up, no servers to manage, and you pay for the data scanned

Key concepts5 points

  1. Query data in S3 directly with standard SQL, with no cluster to set up, billed by data scanned
  2. Table schemas are stored in the Glue Data Catalog; supports CSV, JSON, Parquet, ORC, Apache Iceberg, and other formats
  3. Save money and run faster: convert to a columnar format such as Parquet, compress, and partition by date so less data is scanned
  4. Federated queries can also reach other data sources such as DynamoDB and RDS
  5. Commonly used to analyze ALB, CloudFront, and CloudTrail logs

Three key featuresThe game's three upgrade levels are these three real-world features

LV.1 · Level 1

Partition projection

Computes partition locations directly from rules without looking them up in the Data Catalog; combined with partitioning, only the needed data is scanned, so less scanning costs less

In the game: Running cost or request fees halved

Running cost: 8% request fees each time rent is received

LV.2 · Level 2

Query result reuse

Reuses the previous result for identical queries

In the game: Rent on this square +20%

Running cost: 8% request fees each time rent is received

LV.3 · Level 3

Federated queries

One SQL query reads multiple data sources at once, such as S3, databases, and logs

In the game: Higher rent

Running cost: 8% request fees each time rent is received

1.What is the cheapest way to query data on S3 with Athena?
AnswerUse a columnar format such as Parquet and partition the data
Athena charges by data scanned, so the less you scan, the cheaper it is
2.In default (on-demand) mode, what is Athena billed on?
AnswerThe amount of data scanned by each query
Columnar formats and partitioning can greatly reduce the amount scanned
3.A company writes several TB of JSON clickstream logs to S3 every day through Amazon Data Firehose, and analysts query them with Amazon Athena. Most queries involve only the last few days and a few fields, but the cost is high. What is the most effective way to reduce query costs?SAA-C03
AnswerUse a Glue job to convert the data to the Apache Parquet columnar format and partition it by date
Athena bills by the amount of data scanned: a columnar format makes queries read only the columns they need, and partitioning by date makes queries scan only the relevant partitions, and both greatly reduce the amount scanned. Changing the storage class adds retrieval fees and does not reduce the amount scanned; a self-managed database adds always-on costs and operational work; cross-Region replication only adds storage and transfer costs.
