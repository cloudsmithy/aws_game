API Gateway

Networking groupServerlessBy usageMulti-AZ built in

Managed API front door: create REST, HTTP and WebSocket APIs, with authorization, throttling and caching, connected to Lambda or other services behind it and billed by number of calls.

Common uses

Serverless APIs, backends for mobile and web apps

Why use it

No need to build your own gateway: authorization, throttling, caching and version management work out of the box, with Lambda connected right behind it

Key concepts5 points

  1. Three API types: REST APIs (the most features: usage plans, API keys, request validation, caching), HTTP APIs (cheaper and faster, with fewer features), and WebSocket APIs
  2. Authorization: IAM, Cognito user pools, Lambda authorizers; HTTP APIs can also validate JWTs directly
  3. Throttling and usage plans protect against abuse; REST APIs can turn on response caching
  4. Endpoint types: edge-optimized, Regional, and private (accessible only from a VPC through an interface endpoint)
  5. The integration timeout is 29 seconds by default; move long-running work to asynchronous processing

Three key featuresThe game's three upgrade levels are these three real-world features

LV.1 · Level 1

Usage plan throttling

Limits request rates by stage and API key so bursts don't all hit the backend; officially this is best-effort, and DDoS protection needs WAF

In the game: Immune to “API flooded with malicious requests” (Security Showdown DLC); Performance Efficiency pillar +1 point

Running cost: 15% request fees each time rent is received

LV.2 · Level 2

Access authentication

Validates callers with a Cognito user pool, a Lambda authorizer, or IAM: unauthenticated or unauthorized requests are blocked at the gateway and never reach the backend

In the game: Immune to “Failed security audit”

Running cost: 15% request fees each time rent is received

LV.3 · Level 3

Caching

Caches responses to call the backend less and respond faster; the cache is billed by the hour

In the game: Rent on this square +20%

Running cost: 15% request fees each time rent is received, plus $10 per lap

Correct 0 / 3, answered 0

1.What is the easiest way to let API Gateway admit only signed-in users?
AnswerConfigure a Cognito user pool authorizer on the API, and have requests carry the token obtained at sign-in
The API Gateway Cognito authorizer (a JWT authorizer for HTTP APIs) validates the token first, so requests that are not signed in or have an expired token are rejected at the gateway, and no validation logic is needed in Lambda
2.Which types of APIs does API Gateway support?
AnswerREST, HTTP, WebSocket
HTTP APIs are cheaper and lighter; GraphQL needs AppSync
3.Which services can WAF be placed in front of?
AnswerCloudFront, ALB, API Gateway
WAF works at layer 7; on API Gateway it can only be attached to REST APIs, and it can also be attached to AppSync, Cognito user pools, and more
