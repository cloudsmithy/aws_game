SERVICEContainers group · Containers

EKS

Containers groupContainersBy the hourMulti-AZ is on you

Managed Kubernetes: Amazon Web Services runs the control plane across multiple AZs and each cluster is billed by the hour; worker nodes can use EC2, managed node groups, Fargate or Auto Mode.

Common uses

Teams already using Kubernetes moving to the cloud, unified deployment across environments

Why use it

Choose it when your team already uses Kubernetes and wants to keep using Helm and community tools

Key concepts5 points

  1. A managed Kubernetes control plane (running across multiple AZs) that is compatible with upstream Kubernetes, so kubectl and Helm work as usual
  2. Worker nodes: managed node groups, self-managed nodes, Fargate, or EKS Auto Mode, which manages the nodes too
  3. Each cluster is charged an hourly control plane fee; nodes are billed separately
  4. Pods access cloud services through IAM roles (EKS Pod Identity or IRSA)
  5. Suits teams that already use Kubernetes and want to stay consistent with their other environments

Three key featuresThe game's three upgrade levels are these three real-world features

LV.1 · Level 1

Multi-AZ

Worker nodes are spread across multiple AZs

In the game: Survives an AZ power outage and single points of failure

Running cost: $20 per lap

LV.2 · Level 2

Karpenter auto scaling

Quickly launches the most suitable nodes on demand

In the game: Survives traffic surges

Running cost: $30 per lap

LV.3 · Level 3

EKS Auto Mode

Amazon Web Services manages the nodes: automatic patching, a fresh batch of nodes at least every 21 days, no SSH on nodes; vulnerabilities in the image still need ECR enhanced scanning

In the game: This square is immune to “Internet-exposed instance hit by SSH brute force” (other instances can still be hit)

Running cost: $40 per lap

Compare and choose

ECS or EKS

ECS is Amazon Web Services' own orchestrator and is simple to get started with; if your team knows Kubernetes and needs to stay consistent with other environments, choose EKS

EC2 or ECS or EKS

For full control of the operating system, use EC2; for containers with less to manage, use ECS; if your team knows Kubernetes, choose EKS
