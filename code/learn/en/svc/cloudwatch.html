CloudWatch

Monitoring groupBy usageBy usageWildcard service

Monitoring and observability: collects metrics, logs, and events, sets alarms, and builds dashboards. Alarms can notify people or trigger Auto Scaling.

Common uses

Watching CPU, error rate, and latency, and alerting automatically when something breaks

Why use it

Metrics, logs and alarms are all here, so you know the moment something goes wrong

Key concepts5 points

  1. Metrics: services report them automatically, and you can also publish custom metrics; alarms notify you when a threshold is crossed or trigger actions such as Auto Scaling
  2. Logs: collects application and service logs in one place, and Logs Insights analyzes them with a query language
  3. Dashboards bring it all together in one view; Synthetics uses scripts to simulate user visits and catch failures early
  4. Container Insights, Lambda Insights, and Application Signals show application health
  5. Billed by number of metrics, log volume, number of alarms, and more
