Lambda

Compute groupServerlessBy usageMulti-AZ built in

Serverless functions: upload code and it runs only when an event arrives, billed by number of requests and run time (in milliseconds), with no charge when there are no requests; a single run can last up to 15 minutes.

Common uses

API backends, processing files uploaded to S3, scheduled tasks

Why use it

Give it small, event-triggered jobs: no servers or scaling to manage, and no requests means no cost

Key concepts9 points

  1. Event-driven functions: S3, SQS, DynamoDB Streams, EventBridge, API Gateway, and more can trigger them
  2. A regular function runs for up to 15 minutes per invocation; memory ranges from 128 MB to 10 GB, and CPU is allocated in proportion to memory
  3. Durable functions (launched in December 2025 for multi-step applications and AI workflows): your code records progress with steps and waits, you aren't charged while it's paused, and a whole execution can last up to 1 year; a single invocation is still capped at 15 minutes, and after a timeout it resumes from the last completed step instead of starting over
  4. Lambda MicroVMs (a new service in 2026): gives each user or task its own VM for running user- or AI-generated code (such as an AI coding assistant), each for up to 8 hours; it is a separate kind of compute resource, not a regular function
  5. Lambda Managed Instances: asynchronous invocations and event source mappings can run for up to 90 minutes (per the official quotas page)
  6. For long-running agents: a regular function still gets only 15 minutes; you can split the work into steps with durable functions (up to 1 year in total) or use MicroVMs (up to 8 hours each)
  7. Billed by number of requests and duration (in milliseconds); cold starts can be reduced with provisioned concurrency or SnapStart
  8. By default, functions run in a network managed by Amazon Web Services; to reach a database in a private subnet, you need to connect the function to the VPC
  9. Concurrency has an account-level quota; reserved concurrency can both guarantee and cap a function's concurrency

Correct 0 / 8, answered 0

1.How long can a single execution of a standard Lambda function run at most?
Answer15 minutes
For longer tasks, consider Step Functions, ECS, or Batch
2.How much memory can a Lambda function be configured with at most?
Answer10,240 MB
CPU is allocated in proportion to memory size
3.For Serverless services like Lambda and DynamoDB, do you need to set up Multi-AZ yourself for high availability?
AnswerNo, they run across multiple AZs by default
Serverless has Multi-AZ high availability built in; you only need multi-Region yourself to survive a whole Region having problems
4.What is Lambda mainly billed on?
AnswerNumber of requests and run duration
Duration is converted by the configured memory, and with no requests you pay nothing; provisioned concurrency is billed separately by duration
5.What is a Lambda cold start?
AnswerThe extra time spent initializing a new execution environment
Provisioned concurrency can prepare execution environments in advance
6.After GuardDuty finds an anomaly, what is a common way to isolate the instance automatically?
AnswerAn EventBridge rule triggers a Lambda function to handle it
It can also trigger Step Functions to orchestrate a multi-step response; this is the “Automated threat response” architecture
7.A company commits to a steady level of compute usage for the next 1 year, but will often change EC2 instance families and Regions, and some workloads run on Fargate and Lambda. Which pricing model is the best fit?CLF-C02
AnswerCompute Savings Plans
Compute Savings Plans commit to an hourly spend amount, are not restricted by instance family, size, operating system, tenancy, or Region, and also apply to Fargate and Lambda, saving up to 66%. EC2 Instance Savings Plans, tied to a single Region and a single instance family, save up to 72%, but are less flexible. Standard Reserved Instances are tied to a specific instance configuration and are inflexible. Official docs ↗
8.A company's compute usage is steady, but it is gradually migrating from EC2 to Fargate and Lambda, and may also change EC2 instance families and Regions in the meantime. The company is willing to commit to steady usage for 3 years to get a discount. Which option fits best?SAA-C03
AnswerCompute Savings Plans
The discount of Compute Savings Plans applies to EC2 usage of any instance family, size, operating system, and Region, and also applies to Fargate and Lambda. EC2 Instance Savings Plans are tied to a specific instance family in a Region; Standard Reserved Instances are likewise limited by instance attributes; Spot is not a commitment-based discount and can be interrupted.
