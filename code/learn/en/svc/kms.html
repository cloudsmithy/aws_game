KMS

Security groupManagedBy usageMulti-AZ built inWildcard service

Managed key management: create and manage encryption keys that S3, EBS, RDS and other services use to encrypt data. Keys never leave KMS in plaintext, and every use is logged in CloudTrail.

Common uses

Encrypting data at rest, controlling who can decrypt data

Why use it

You don't have to keep keys yourself: services that store data can use it directly for encryption, and CloudTrail records who used each key

Key concepts5 points

  1. Managed encryption keys: most services that store data, such as S3, EBS, RDS, and DynamoDB, integrate with it directly
  2. Envelope encryption: the KMS key encrypts only the data key, and the data key then encrypts the bulk data
  3. Keys are either Amazon Web Services managed keys or customer managed keys; for customer managed keys you can write your own key policy, turn on automatic rotation, and disable the key
  4. Every use of a key is recorded in CloudTrail, so you can audit who decrypted what and when
  5. Key material never leaves FIPS 140-validated hardware security modules (HSMs)

1.What is KMS used for?
AnswerCreating and managing encryption keys
Many services rely on KMS keys for encryption at rest; store passwords in Secrets Manager and certificates in ACM
2.How long can the automatic rotation period of a KMS customer managed key be set to?
Answer90 to 2,560 days, default 1 year
Old data can still be decrypted after rotation
3.A development team needs to create and manage keys for encrypting data, and wants those keys protected by validated hardware security modules. Which service should they use?CLF-C02
AnswerKey Management Service (KMS)
KMS is used to create and control keys for encryption and signing, and KMS keys are protected by hardware security modules validated under FIPS 140-3. Secrets Manager stores secrets such as passwords, ACM manages TLS certificates, and IAM manages identities and permissions; none of them create encryption keys. Official docs ↗
4.The compliance team requires that a custom model obtained by fine-tuning in Amazon Bedrock must be encrypted with a key that the company itself manages and controls. What should be done?AIF-C01
AnswerEncrypt the custom model with a KMS customer managed key
By default, Bedrock encrypts custom models with an Amazon Web Services owned key, and you can instead choose to encrypt with a customer managed key that you manage in KMS and control access to through the key policy. IAM access keys are used for authentication and are not data encryption keys. Official docs ↗
5.A financial company requires sensitive data in S3 to be encrypted at rest, and requires that it can decide which IAM principals may use the encryption key, manage key rotation itself, and audit key usage through CloudTrail. Which approach meets all the requirements?SAA-C03
AnswerUse SSE-KMS with a customer managed KMS key, and control access through the key policy
The key policy of a customer managed key is managed by the customer, who can enable automatic or on-demand rotation, and key usage is logged to CloudTrail. SSE-S3 doesn't let you control key permissions separately; neither the properties nor the key policy of an Amazon Web Services managed key can be modified; a hard-coded key is both insecure and impossible to audit centrally.
