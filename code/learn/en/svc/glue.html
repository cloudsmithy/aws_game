Service notes/Analytics group/Glue

SERVICEAnalytics group · Serverless

Glue

Analytics groupServerlessBy usageMulti-AZ built in

Serverless data integration (ETL) service: crawls data sources to build a data catalog, cleans and transforms data with Spark jobs, and is billed by run time.

Common uses

Loading a data lake, preparing data for Athena and Redshift

Why use it

Clean data, convert formats and build a data catalog without running your own cluster, and pay for run time

Key concepts5 points

  1. Serverless data integration (ETL) service: cleans and transforms data with Spark or Python jobs
  2. The Glue Data Catalog stores table schemas (metadata) in one place, and Athena, Redshift Spectrum, and EMR all use it
  3. Crawlers automatically scan data sources such as S3, infer table schemas, and write them to the Data Catalog
  4. Glue Studio lets you build jobs visually; Glue DataBrew cleans data through a visual interface
  5. Billed by the run time of DPUs (data processing units)

2.What does a Glue crawler do?
AnswerScans data sources, infers the table schema, and writes it to the Data Catalog
After that, Athena and Redshift Spectrum can query it directly
3.A company writes several TB of JSON clickstream logs to S3 every day through Amazon Data Firehose, and analysts query them with Amazon Athena. Most queries involve only the last few days and a few fields, but the cost is high. What is the most effective way to reduce query costs?SAA-C03
AnswerUse a Glue job to convert the data to the Apache Parquet columnar format and partition it by date
Athena bills by the amount of data scanned: a columnar format makes queries read only the columns they need, and partitioning by date makes queries scan only the relevant partitions, and both greatly reduce the amount scanned. Changing the storage class adds retrieval fees and does not reduce the amount scanned; a self-managed database adds always-on costs and operational work; cross-Region replication only adds storage and transfer costs.
