SERVICEDatabase group · PaaS

RDS

Database groupPaaSBy the hourMulti-AZ is on you

Managed relational database: supports MySQL, PostgreSQL, MariaDB, Oracle, SQL Server and Db2, and handles backups, patching and failover for you. A Multi-AZ deployment keeps a standby instance in another AZ.

Common uses

Traditional business systems, e-commerce order databases

Why use it

Use it when you need a relational database but don't want to run it yourself: backups, patching and Multi-AZ failover are managed, and it offers the widest choice of engines

Key concepts5 points

  1. Managed relational database, with MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, and Db2 engines
  2. Multi-AZ deployment: data is replicated synchronously to a standby instance in another AZ, with automatic failover if the primary has a problem (the standby doesn't serve read requests in normal operation)
  3. Read replicas: asynchronous replication that offloads read traffic; replicas can be placed in other Regions
  4. Automated backups with point-in-time recovery, retained for up to 35 days; manual snapshots can be kept long term
  5. RDS Proxy reuses database connections, which suits callers like Lambda that open many short-lived connections

Three key featuresThe game's three upgrade levels are these three real-world features

Compare and choose

Aurora or RDS

Aurora is compatible with MySQL and PostgreSQL and has better performance and high availability (storage spans 3 AZs); for SQL Server or Oracle, or to save money, use RDS

Aurora or DynamoDB or RDS

For key-based reads and writes at very high concurrency, choose DynamoDB; for SQL and transactions, choose Aurora (better performance and high availability) or RDS (more engines, lower cost)

4.A company's production database runs on Amazon RDS for MySQL around the clock, and neither the instance type nor the Region will change over the next 3 years. How can the database cost be reduced?SAA-C03
AnswerPurchase a 3-year RDS Reserved DB Instance for the database
RDS Reserved DB Instances trade a 1-year or 3-year term for a significant discount compared with On-Demand pricing, and suit instances that run steadily for the long term. Running a production database on Spot risks interruptions and is heavier to operate; a production database that runs around the clock cannot be shut down at night; RDS storage cannot use S3 storage classes. 5.What is the main benefit of enabling a Multi-AZ DB instance deployment with one standby instance for Amazon RDS?CLF-C02
AnswerThe standby instance is in another Availability Zone and takes over automatically on failure
A Multi-AZ deployment with one standby instance provides failover support, but the standby does not serve read traffic. To scale read performance, consider other options such as read replicas. Official docs ↗
6.An application uses Amazon RDS for MySQL, and the database password is currently hard-coded in a config file. The company requires credentials to be stored centrally and rotated automatically on a schedule, with as little custom code as possible. Which approach should it use?SAA-C03
AnswerStore the credentials in Secrets Manager with automatic rotation enabled, and have the application read them through the API at runtime
Secrets Manager stores credentials centrally and has built-in automatic rotation (managed rotation or a Lambda rotation function), and the application reads the latest value when needed. The Parameter Store approach requires you to write your own rotation script; KMS key rotation only replaces the encryption key material and does not change the database password. Official docs ↗
7.An e-commerce company's order database runs on a single Amazon RDS for PostgreSQL instance. The company requires automatic failover if an Availability Zone fails, with as little loss of committed data as possible, and does not need extra read scaling. How should it be changed?SAA-C03
AnswerConvert the DB instance to a Multi-AZ deployment
A Multi-AZ deployment maintains a synchronously replicated standby instance in another Availability Zone and fails over automatically if the primary fails. Read replicas replicate asynchronously, must be promoted manually, and may lose the latest data; hourly snapshots have an RPO of up to an hour, and recovery also needs manual work. Official docs ↗
8.A news website's Amazon RDS database has constantly high CPU because the same popular queries run over and over, and the query results barely change for several minutes. How can read performance be improved with as few changes to the database as possible?SAA-C03
AnswerCache the results of popular queries with ElastiCache
ElastiCache provides a managed in-memory cache, and caching the results of repeated popular queries significantly reduces database load and read latency. The standby instance of a Multi-AZ DB instance deployment does not serve reads; the reader instances of a Multi-AZ DB cluster can share reads, but you must migrate to a new cluster, and popular queries still run in full every time; st1 is HDD and is not suited to random database I/O; switching to a T-series instance only changes how CPU is billed and bursts, and the load from repeated popular queries remains.
