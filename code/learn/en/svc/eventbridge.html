EventBridge

Application Integration groupServerlessBy usageMulti-AZ built in

Serverless event bus: routes events from Amazon Web Services services, your own applications and SaaS to Lambda, Step Functions and others by rule, and can also trigger on a schedule.

Common uses

Event-driven architectures, distributing events across accounts, scheduled tasks

Why use it

Event senders and event handlers don't need to know each other: adding a handler doesn't require changing the sender, and it can also trigger on a schedule

Key concepts5 points

  1. Serverless event bus: takes in events from Amazon Web Services services, your own applications, and SaaS partners
  2. Rules filter events by content (event patterns) and route them to targets such as Lambda, SQS, and Step Functions
  3. EventBridge Scheduler: triggers on a schedule by cron expression or fixed rate, and can call many services' APIs directly without writing a Lambda function
  4. Pipes: point-to-point connections from sources such as SQS, Kinesis, and DynamoDB Streams to a target, with optional filtering and transformation in between
  5. Events can be archived and replayed later; the Schema Registry discovers event structures automatically

1.What is EventBridge mainly used for?
AnswerReceiving events and routing them to targets by rules
It can take events from Amazon Web Services services, SaaS, and your own applications
2.What are EventBridge Global Endpoints used for?
AnswerWhen the primary Region fails, events switch to a backup Region
Works with Route 53 health checks for automatic failover
3.After GuardDuty finds an anomaly, what is a common way to isolate the instance automatically?
AnswerAn EventBridge rule triggers a Lambda function to handle it
It can also trigger Step Functions to orchestrate a multi-step response; this is the “Automated threat response” architecture
4.Several microservices at a company publish order status change events. The requirement is to route events to different targets (such as Lambda and Step Functions) based on event content (for example, a status field equal to CANCELLED), without changing publisher code when adding consumers, and with as little routing code as possible. Which service should it use?SAA-C03
AnswerAn Amazon EventBridge event bus, with a rule that has an event pattern for each type of consumer
EventBridge rules use event patterns to match events by content and route them to targets, and adding a consumer only requires adding a rule. Hard-coded routing in the publisher creates coupling; Kinesis requires each consumer to read and filter on its own; a self-built broker has high operational overhead. Official docs ↗
