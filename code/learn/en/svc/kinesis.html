Kinesis

Analytics groupManagedBy the hourMulti-AZ built in

Real-time data streaming: Kinesis Data Streams absorbs large numbers of events per second and lets multiple applications read at once; Data Firehose can deliver data straight into S3, Redshift and OpenSearch.

Common uses

Real-time analysis of clickstreams and logs, live dashboards, IoT data

Why use it

Use it when records keep streaming in and must be processed in real time: it handles traffic bursts, and multiple consumers can read at the same time

Key concepts5 points

  1. Kinesis Data Streams: real-time data streams that scale by shards or in on-demand mode; data is retained for 24 hours by default and up to 365 days
  2. Multiple consumers can read the same stream at the same time; enhanced fan-out gives each consumer its own dedicated read throughput
  3. Amazon Data Firehose (formerly Kinesis Data Firehose) continuously delivers data to S3, Redshift, OpenSearch, and more without writing code
  4. Records with the same partition key go to the same shard, which keeps them in order
  5. Common downstream options: Lambda for real-time processing, or Managed Service for Apache Flink for stream processing

1.How long does Kinesis Data Streams retain data by default?
Answer24 hours
24 hours by default, extendable up to 365 days
2.What is the write limit of a single Kinesis Data Streams shard?
Answer1 MB or 1,000 records per second
2 MB per second is the read limit; if throughput isn't enough, add shards or use on-demand mode
3.Do you pay for Kinesis Data Streams when it sits empty with no data?
AnswerYes, billed by the hour or with an account minimum
Provisioned mode is billed per shard-hour and on-demand Standard mode per stream-hour, even when the stream is idle. If the account has On-demand Advantage enabled, there is no per-stream hourly charge, but the on-demand streams in this Region together are billed for at least 25 MiB per second of writes and 25 MiB per second of reads. So it does not count as Serverless in the sense of "no cost when nobody uses it"
4.What is Kinesis Data Firehose (now called Amazon Data Firehose) mainly used for?
AnswerAutomatically delivering streaming data to destinations such as S3
Destinations include S3, Redshift, and OpenSearch; no consumer code to write, and it batches writes automatically
5.An e-commerce website needs to collect clickstream data in real time. Several applications, such as real-time recommendations and fraud detection, must each read the same data independently and in order, and must be able to reprocess it within the retention period after a processing error. Which service should be used as the data ingestion layer?SAA-C03
AnswerAmazon Kinesis Data Streams
Kinesis Data Streams stores records in order by sequence number within each shard, lets multiple consumers read independently, and can replay data within the retention period. SQS standard queues do not guarantee ordering, and messages cannot be replayed after they are consumed and deleted; SNS does not retain messages after pushing them; relational databases scale poorly for high-velocity clickstreams.
