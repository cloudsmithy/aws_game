服务知识点/分析组/Kinesis

SERVICE分析组 · 托管服务

Kinesis

分析组托管服务按小时自带跨 AZ 高可用

实时数据流：Kinesis Data Streams 接住每秒大量的事件，多个程序同时读；Data Firehose 能把数据直接送进 S3、Redshift、OpenSearch。

常见用法

点击流和日志实时分析、实时大屏、IoT 数据

为什么用它

数据一条条持续进来、要实时处理时用它：扛得住突发流量，多个消费者能同时读

核心知识点5 条

  1. Kinesis Data Streams：实时数据流，按分片或按需模式扩展；数据默认保留 24 小时，最长 365 天
  2. 多个消费者能同时读同一条流；增强扇出给每个消费者独享的读取吞吐
  3. Amazon Data Firehose（原 Kinesis Data Firehose）不用写代码，就能把数据持续投递到 S3、Redshift、OpenSearch 等
  4. 同一个分区键的记录落在同一个分片里，保持顺序
  5. 常见下游：Lambda 实时处理，或者 Managed Service for Apache Flink 做流计算

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

按需模式

不用自己管分片数，按流量自动扩缩（按数据流小时和数据量计费）

游戏里：性能效率支柱 +1 分

运行费：每圈 $10

LV.2 · 第 2 级

增强扇出

每个消费者独享读取吞吐，互不抢

游戏里：这块过路费再 +20%

运行费：每圈 $20

LV.3 · 第 3 级

数据转换

Data Firehose 投递前调用 Lambda 清洗、转换每条记录，或者按 Glue 数据目录里的表结构转成 Parquet 再写进 S3：存得更省，下游用 Athena 查时扫的数据也少

游戏里：运行费或请求费减半

运行费：每圈 $15

练一练5 道，来自游戏题库和认证练习题：点一个选项看对不对

答对 0 / 5，已答 0

1.Kinesis Data Streams 默认保留数据多久？
答案24 小时
默认 24 小时，可以延长到 365 天
2.Kinesis Data Streams 单个分片的写入上限是？
答案每秒 1 MB 或 1000 条
每秒 2 MB 是读取上限；吞吐不够就加分片，或用按需模式
3.Kinesis Data Streams 空着没数据时要付钱吗？
答案要，按小时或账户保底收费
预置模式按分片小时、按需标准模式按数据流小时收费，空着也照算；账户开了 On-demand Advantage 就不收每条流的小时费，但这个 Region 的按需流合计每秒至少按写入、读取各 25 MiB 收费。所以它不算「没人用就不花钱」的 Serverless
4.Kinesis Data Firehose（现名 Amazon Data Firehose）主要用来？
答案把流数据自动投递到 S3 等目的地
目的地有 S3、Redshift、OpenSearch 等；不用写消费者代码，自动攒批写入
5.某电商网站需要实时采集点击流数据，实时推荐和欺诈检测等多个应用要各自独立、按顺序读取同一份数据，并在处理出错后能在保留期内重新处理。应使用哪项服务作为数据接入层？SAA-C03
答案Amazon Kinesis Data Streams
Kinesis Data Streams 在每个分片内按序列号有序保存记录，多个消费者可独立读取，并可在保留期内重放数据。SQS 标准队列不保证顺序，消息消费删除后不能重放；SNS 推送后不保留消息；关系数据库承接高速点击流的扩展性差。　官方文档 ↗
