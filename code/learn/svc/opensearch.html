OpenSearch

分析组PaaS按小时要自己做多 AZ

托管的 OpenSearch（从 Elasticsearch 分出来的开源项目）：全文搜索、日志分析和可视化，也能当向量数据库用。

常见用法

站内搜索、日志检索、RAG 的向量检索

为什么用它

要全文搜索、模糊匹配、日志实时检索时用它，这些用关系库做又慢又压库

核心知识点5 条

  1. 托管的 OpenSearch（从 Elasticsearch 7.10 分出来的开源项目）：全文检索、日志分析，配 OpenSearch Dashboards 做可视化
  2. 两种形态：托管域（自己选节点规格）和 OpenSearch Serverless（集合，自动扩缩）
  3. 向量引擎能做 k-NN 向量检索，常拿来当 RAG 的向量库
  4. 生产环境建议多 AZ 部署加专用主节点；冷数据放 UltraWarm 或冷存储省钱
  5. OpenSearch Ingestion 是托管的数据管道，能从 S3、DynamoDB（Zero-ETL）等导数据进来

和谁比、怎么选

OpenSearch 还是 Redshift

要全文检索、日志实时搜索，选 OpenSearch；要大规模 SQL 分析和报表，选 Redshift

Aurora 还是 OpenSearch

向量多、要关键词加向量的混合检索，选 OpenSearch；已经在用 PostgreSQL、数据量不大，选 Aurora（pgvector）

OpenSearch 还是 Redshift 还是 S3

便宜地长期存、离线分析，放 S3 数据湖；要秒级 SQL 报表，进 Redshift；要实时检索，进 OpenSearch
