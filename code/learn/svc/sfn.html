可视化的工作流编排：把 Lambda、容器任务和各种服务的 API 调用串成状态机，自带重试、分支、并行，还能停下来等人工审批。

常见用法

为什么用它

多步骤的流程不用自己写状态机：每一步的重试、超时、失败回滚都能配，执行到哪一步看得见

核心知识点5 条

  1. 可视化的工作流编排：用状态机描述步骤、分支、并行、等待
  2. 两种工作流：标准（最长跑一年，恰好执行一次，适合长流程）和快速（最长 5 分钟，吞吐高，按次数和时长计费）
  3. 每一步都能配重试、超时、捕获错误转去补偿逻辑
  4. 能直接调用很多服务的 API（SDK 集成），不用都经过 Lambda
  5. 执行历史可视化，每一步的输入输出都看得到，排查方便

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

适合 5 分钟内跑完的高频短流程：按执行次数和运行时长（按内存折算）计费，不按状态转换数计，步骤多、跑得快时更便宜

3.某公司的多个微服务会发布订单状态变更事件。要求按事件内容（例如 status 字段为 CANCELLED）把事件路由到不同目标（如 Lambda、Step Functions），新增消费者时不修改发布方代码，并尽量少写路由代码。应使用哪项服务？SAA-C03
答案Amazon EventBridge 事件总线，为每类消费者创建带事件模式的规则
EventBridge 规则用事件模式按内容匹配事件并路由到目标，新增消费者只需增加规则。发布方硬编码路由会造成耦合；Kinesis 需要各消费者自行读取和过滤；自建代理运维开销大。　官方文档 ↗
