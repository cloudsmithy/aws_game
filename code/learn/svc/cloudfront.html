SERVICE网络组 · 全局服务

CloudFront

网络组全局服务按用量全局服务

CDN：把网站、视频和 API 缓存到全球各地的边缘站点，用户就近访问，减轻源站压力；自带 Shield Standard 挡常见的 DDoS。

常见用法

网站和静态资源加速、视频分发

为什么用它

用户分布广、静态内容多时放在最前面：就近返回，源站压力小，还能在边缘挡攻击

核心知识点5 条

  1. 全球 CDN：内容缓存在边缘站点，用户就近访问；动态 API 也能走它加速
  2. 源站可以是 S3（用 OAC 只让 CloudFront 读私有桶）、ALB、EC2、API Gateway 或任何 HTTP 服务器
  3. 自带 Shield Standard 挡常见 DDoS，还能挂 WAF
  4. 边缘计算：CloudFront Functions（轻量、延迟极低）和 Lambda@Edge（功能更强）
  5. 签名 URL、签名 Cookie 控制私有内容；改了内容可以发失效请求刷新缓存

和谁比、怎么选

CloudFront 还是 ELB

全球用户、静态内容多，Shield 挂在 CloudFront 上；只在一个区域、动态请求为主，挂在 ALB 上

1.CloudFront 的源访问控制（OAC）解决什么问题？
答案只让 CloudFront 读 S3 桶，桶不用公开
比旧的源访问身份（OAI）支持更多功能
2.CloudFront 是什么？
答案CDN，把内容缓存到离用户近的边缘节点
还能和 WAF、Shield 一起挡攻击
3.CloudFront 缓存命中率低，常见原因是？
答案缓存键里带了多余的请求头或查询参数
用缓存策略只保留必要的键
4.WAF 可以挂在哪些服务前面？
答案CloudFront、ALB、API Gateway
WAF 管第 7 层；API Gateway 只能挂 REST API，另外还能挂 AppSync、Cognito 用户池等
5.全球用户访问静态资源慢，第一选择通常是？
答案CloudFront
边缘节点就近缓存，回源走骨干网
6.某公司用 Amazon CloudFront 分发存放在 S3 存储桶中的静态网站资源，要求用户只能通过 CloudFront 访问，不能直接通过 S3 对象 URL 访问。应该怎么做？SAA-C03
答案配置源访问控制（OAC），存储桶策略只允许该分发读取
OAC 让 CloudFront 以签名请求访问 S3，配合只允许该分发的存储桶策略即可阻止直连。公开读取会让对象可被直接访问；Transfer Acceleration 用于加速传输；版本控制和 MFA Delete 用于防止误删，不控制读取路径。　官方文档 ↗
7.一家视频网站的用户遍布全球，希望把图片、JS 和视频等内容缓存在离用户最近的位置以降低延迟。应使用哪项服务？CLF-C02
答案Amazon CloudFront
CloudFront 通过全球的边缘站点分发内容，请求会被路由到延迟最低的边缘站点。Direct Connect 是专用网络连接，不负责内容缓存。　官方文档 ↗
8.一家在线教育公司的源站部署在美国东部区域，其封面图片和 JS/CSS 等静态文件被亚洲和欧洲学员频繁访问，加载很慢。如何以最少的改动提升全球访问性能？SAA-C03
答案使用 Amazon CloudFront，在边缘站点缓存静态内容
CloudFront 通过全球边缘站点缓存内容，并把请求路由到延迟最低的边缘站点。多区域自建服务器运维成本高；改存储类只影响费用，不影响延迟；加大源站实例无法缩短跨洲的网络距离。　官方文档 ↗
