SERVICE分析组 · Serverless

Glue

分析组Serverless按用量自带跨 AZ 高可用

Serverless 的数据集成（ETL）服务：爬取数据源建数据目录，用 Spark 作业清洗、转换数据，按运行时长收费。

常见用法

数据湖入湖、给 Athena 和 Redshift 准备数据

为什么用它

清洗数据、转格式、建数据目录不用自己搭集群，按运行时间付费

核心知识点5 条

  1. Serverless 的数据集成（ETL）服务：用 Spark 或 Python 作业清洗、转换数据
  2. Glue 数据目录集中存表结构（元数据），Athena、Redshift Spectrum、EMR 都用它
  3. 爬网程序（Crawler）自动扫描 S3 等数据源，推断表结构、写进数据目录
  4. Glue Studio 可视化编排作业；Glue DataBrew 用界面做数据清洗
  5. 按 DPU（数据处理单元）的运行时长计费

三个关键功能游戏里的三级升级，就是现实里的这三个功能

答案扫描数据源，推断表结构写进数据目录
之后 Athena、Redshift Spectrum 就能直接查
3.某公司每天通过 Amazon Data Firehose 把数 TB 的 JSON 点击日志写入 S3，分析师用 Amazon Athena 查询。大多数查询只涉及最近几天和少数几个字段，但费用很高。如何最有效地降低查询成本？SAA-C03
答案用 Glue 作业把数据转换为 Apache Parquet 列式格式，并按日期分区
Athena 按扫描的数据量计费：列式格式让查询只读取需要的列，按日期分区让查询只扫描相关分区，两者都能大幅减少扫描量。改存储类会增加取回费用且不减少扫描量；自建数据库增加常驻成本和运维；跨区域复制只会增加存储和传输费用。　官方文档 ↗
