CloudTrail

监控组按用量按用量万能服务

记录账户里的 API 调用：谁在什么时间、从哪里、做了什么操作。控制台默认能查最近 90 天的管理事件；建跟踪可以长期存进 S3。

常见用法

安全审计、查清楚是谁删了资源

为什么用它

记录谁在什么时候调了哪个 API，出事能追溯

核心知识点5 条

  1. 记录账户里的 API 调用：谁、什么时候、从哪里、做了什么，用于审计和排查
  2. 事件历史默认能查 90 天的管理事件；要长期留就建跟踪（Trail）投递到 S3
  3. 数据事件（S3 对象读写、Lambda 调用等）要单独开、单独收费
  4. 日志文件完整性验证能证明日志没被改过；组织级跟踪一次覆盖所有账户
  5. CloudTrail Lake 能用 SQL 查事件

1.多账户环境下统一限制「谁都不能关 CloudTrail」，用什么？
答案Organizations 的服务控制策略（SCP）
SCP 在组织层面兜底，账户管理员也绕不过
2.CloudTrail 记录的是什么？
答案账户里的 API 调用
谁在什么时候调了什么 API
3.GuardDuty 主要分析哪些数据？
答案CloudTrail、VPC 流日志、DNS 日志等
基础检测开启即可，不用自己部署采集；运行时监控要装代理，可以自动管理
4.一家金融公司要求 S3 中的敏感数据静态加密，并且必须能自行决定哪些 IAM 主体可以使用加密密钥、自行管理密钥轮换，并通过 CloudTrail 审计密钥使用。哪种方案满足全部要求？SAA-C03
答案使用 SSE-KMS 并采用客户托管的 KMS 密钥，通过密钥策略控制访问
客户托管密钥的密钥策略由客户管理，可自行开启自动或按需轮换，密钥使用会记录到 CloudTrail。SSE-S3 无法单独控制密钥权限；亚马逊云科技托管密钥的属性和密钥策略都不能修改；硬编码密钥既不安全也无法集中审计。　官方文档 ↗
5.一台 EC2 实例昨晚被人终止了，团队想查清是哪个用户或角色在什么时间调用了 API。应查看哪项服务的记录？CLF-C02
答案CloudTrail
CloudTrail 把用户、角色或亚马逊云科技服务执行的操作记录为事件，涵盖控制台、CLI、SDK 和 API 调用，适合审计「谁做了什么」。CloudWatch 指标反映的是资源性能数据，不记录谁发起了 API 调用。　官方文档 ↗
