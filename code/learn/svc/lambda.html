服务知识点/计算组/Lambda

SERVICE计算组 · Serverless

Lambda

计算组Serverless按用量自带跨 AZ 高可用

无服务器函数：上传代码，有事件来才运行，按请求次数和运行时长（毫秒）收费，没请求不收钱；单次最长运行 15 分钟。

常见用法

API 后端、处理 S3 上传的文件、定时任务

为什么用它

代码不多、按事件触发的活交给它：不用管服务器和扩容，没请求就不花钱

核心知识点9 条

  1. 事件驱动的函数：S3、SQS、DynamoDB Streams、EventBridge、API Gateway 等都能触发
  2. 普通函数单次最长运行 15 分钟；内存 128 MB 到 10 GB，CPU 按内存比例给
  3. 持久函数（durable functions，2025 年 12 月发布，面向多步骤应用和 AI 工作流）：代码里用步骤（steps）和等待（waits）记录进度，暂停期间不收费，整个执行最长 1 年；单次调用还是 15 分钟上限，超时后从上一个完成的步骤接着跑，不用从头开始
  4. Lambda MicroVMs（2026 年的新服务）：给每个用户或任务一台独立的 VM，用来跑用户或 AI 生成的代码（比如 AI 编程助手），每个最长 8 小时；它是单独的一种计算资源，不是普通函数
  5. Lambda Managed Instances：异步调用和事件源映射最长 90 分钟（官方配额页写的）
  6. 要跑很久的智能体：普通函数还是只有 15 分钟；可以用持久函数拆成多个步骤（总共最长 1 年），或者用 MicroVMs（单个最长 8 小时）
  7. 按请求次数和运行时长（毫秒）计费；冷启动可以用预置并发或 SnapStart 缓解
  8. 默认跑在亚马逊云科技管的网络里；要连私有子网里的数据库，得给函数配置 VPC
  9. 并发有账户级配额；预留并发能给某个函数保证、也能限制它的并发

提前准备好执行环境，消除冷启动

用容器镜像打包函数（最大 10 GB），配上 Lambda Web Adapter，Express、Flask、Spring Boot 这些 Web 框架基本不用改代码就能跑；不用常开的服务器，按请求付钱

答对 0 / 8，已答 0

1.标准 Lambda 函数单次执行最长能跑多久？
答案15 分钟
更长的任务考虑 Step Functions、ECS 或 Batch
2.Lambda 函数最多能配置多少内存？
答案10,240 MB
CPU 按内存大小成比例分配
3.Lambda、DynamoDB 这类 Serverless 服务，高可用要自己做多 AZ 吗？
答案不用，默认就在多个 AZ 里运行
Serverless 自带跨 AZ 高可用；要扛整个 Region 出问题，才需要自己做多区域
4.Lambda 主要按什么收费？
答案请求次数和运行时长
时长按配置的内存折算，没有请求就不花钱；预置并发另外按时长收费
5.Lambda 冷启动是什么？
答案新执行环境初始化多花的时间
预置并发可以提前准备好执行环境
6.GuardDuty 发现异常后，想自动隔离实例，常见做法是？
答案EventBridge 规则触发 Lambda 处置
也可以触发 Step Functions 编排多步处置，这就是「威胁自动响应」架构
7.公司承诺未来 1 年保持稳定的计算用量，但会经常更换 EC2 实例族和区域，还有部分负载运行在 Fargate 和 Lambda 上。哪种定价模式最合适？CLF-C02
答案Compute Savings Plans
Compute Savings Plans 承诺每小时的消费金额，不受实例族、大小、操作系统、租期和区域限制，并且适用于 Fargate 和 Lambda，最高可省 66%；绑定单一区域、单一实例族的 EC2 Instance Savings Plans 最高可省 72%，但灵活性不如它。标准预留实例绑定特定实例配置，灵活性差。　官方文档 ↗
8.某公司的计算用量稳定，但正逐步从 EC2 迁移到 Fargate 和 Lambda，期间还可能更换 EC2 实例系列和区域。公司愿意承诺 3 年的稳定用量以获得折扣。哪个选项最合适？SAA-C03
答案Compute Savings Plans
Compute Savings Plans 的折扣适用于任意实例系列、大小、操作系统和区域的 EC2 用量，也适用于 Fargate 和 Lambda。EC2 Instance Savings Plans 绑定某个区域内的特定实例系列；标准预留实例同样受实例属性限制；Spot 不是承诺型折扣，而且可能被中断。　官方文档 ↗
