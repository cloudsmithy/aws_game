每一块干什么4 块服务

01GuardDuty必须

安全组 · 托管服务 · 按用量 · 售价 $380
在这里
GuardDuty 发现异常
为什么用它
不用装代理，开了就分析 CloudTrail、VPC 流日志和 DNS 日志，发现挖矿、凭证泄露这类异常
它是什么
威胁检测：持续分析 CloudTrail 事件、VPC 流日志和 DNS 日志等，发现挖矿、凭证泄露、异常访问。它只负责发现、不负责拦截，要配合 EventBridge 和 Lambda 自动处置。
常见用法
账户安全监控、自动响应安全事件
GuardDuty 的知识点 →

02EventBridge必须

应用集成组 · Serverless · 按用量 · 售价 $240
在这里
EventBridge 路由
为什么用它
发事件的和处理事件的互不认识：多加一个处理方不用改发送方，还能按时间表触发
它是什么
Serverless 事件总线：把亚马逊云科技服务、自己的应用和 SaaS 发出的事件按规则转给 Lambda、Step Functions 等，也能定时触发。
常见用法
事件驱动架构、跨账户分发事件、定时任务
EventBridge 的知识点 →

03Step Functions必须

应用集成组 · Serverless · 按用量 · 售价 $260
在这里
Step Functions 按剧本自动处置
为什么用它
多步骤的流程不用自己写状态机：每一步的重试、超时、失败回滚都能配，执行到哪一步看得见
它是什么
可视化的工作流编排：把 Lambda、容器任务和各种服务的 API 调用串成状态机，自带重试、分支、并行，还能停下来等人工审批。
常见用法
订单处理流程、数据处理流水线、编排 AI Agent 的步骤
Step Functions 的知识点 →

04Lambda可选

计算组 · Serverless · 按用量 · 售价 $220
在这里
Lambda 执行隔离实例、吊销密钥这些动作
为什么用它
代码不多、按事件触发的活交给它：不用管服务器和扩容，没请求就不花钱
它是什么
无服务器函数：上传代码，有事件来才运行，按请求次数和运行时长（毫秒）收费，没请求不收钱；单次最长运行 15 分钟。
常见用法
API 后端、处理 S3 上传的文件、定时任务
