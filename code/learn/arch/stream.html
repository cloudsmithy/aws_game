每一块干什么4 块服务

01Kinesis必须

分析组 · 托管服务 · 按小时 · 售价 $300
在这里
Kinesis 收数据流
为什么用它
数据一条条持续进来、要实时处理时用它：扛得住突发流量，多个消费者能同时读
它是什么
实时数据流：Kinesis Data Streams 接住每秒大量的事件，多个程序同时读；Data Firehose 能把数据直接送进 S3、Redshift、OpenSearch。
常见用法
点击流和日志实时分析、实时大屏、IoT 数据
Kinesis 的知识点 →

02Lambda必须

计算组 · Serverless · 按用量 · 售价 $220
在这里
Lambda 处理后写进 OpenSearch 检索
为什么用它
代码不多、按事件触发的活交给它：不用管服务器和扩容，没请求就不花钱
它是什么
无服务器函数：上传代码，有事件来才运行，按请求次数和运行时长（毫秒）收费，没请求不收钱；单次最长运行 15 分钟。
常见用法
API 后端、处理 S3 上传的文件、定时任务
Lambda 的知识点 →

03OpenSearch必须几选一

分析组 · PaaS · 按小时 · 售价 $360
在这里
Lambda 处理后写进 OpenSearch 检索
为什么用它
要全文搜索、模糊匹配、日志实时检索时用它，这些用关系库做又慢又压库
它是什么
托管的 OpenSearch（从 Elasticsearch 分出来的开源项目）：全文搜索、日志分析和可视化，也能当向量数据库用。
常见用法
站内搜索、日志检索、RAG 的向量检索
OpenSearch 的知识点 →

03Redshift必须几选一

分析组 · PaaS · 按小时 · 售价 $340
在这里
Redshift 也能直接从 Kinesis 流式摄取
为什么用它
数据量大、报表和复杂 SQL 多时用它：列式存储加大规模并行，几十亿行也查得动
它是什么
云数据仓库：列式存储、大规模并行处理，用 SQL 分析海量数据；有预置集群和 Redshift Serverless 两种用法。
常见用法
BI 报表、经营分析
