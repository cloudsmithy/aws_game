每一块干什么4 块服务

01DMS必须

数据库组 · PaaS · 按小时 · 售价 $340
在这里
DMS 把机房的数据库全量搬到 RDS 或 Aurora（换引擎的先用 Schema Conversion 转表结构和存储过程）
为什么用它
源库不用改代码：先全量复制，再持续抓变更（CDC），迁移割接停机短；平时也能把改动实时同步到搜索、数据湖或数仓
它是什么
数据库迁移服务：把机房或别的云上的数据库搬到亚马逊云科技，同构（MySQL 到 RDS for MySQL）、异构（Oracle 到 Aurora PostgreSQL）都行；全量搬完以后还能持续抓源库的变更（CDC），新旧库一直对得上，割接时停机很短。按复制实例的小时计费，也有按用量的 DMS Serverless。
常见用法
数据库上云、把业务库的改动实时同步到数据湖、搜索或数仓（CDC）

02RDS必须几选一

数据库组 · PaaS · 按小时 · 售价 $280
在这里
DMS 把机房的数据库全量搬到 RDS 或 Aurora（换引擎的先用 Schema Conversion 转表结构和存储过程）
为什么用它
要关系库又不想自己运维时用它：备份、补丁、多 AZ 故障切换都托管，引擎选择最多
它是什么
托管的关系数据库：支持 MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2，帮你做备份、打补丁和故障切换。多 AZ 部署会在另一个 AZ 放一台备用实例。
常见用法
传统业务系统、电商订单库

02Aurora必须几选一

数据库组 · PaaS · 按小时 · 售价 $280
在这里
DMS 把机房的数据库全量搬到 RDS 或 Aurora（换引擎的先用 Schema Conversion 转表结构和存储过程）
为什么用它
要更高性能和可用性的 MySQL、PostgreSQL 时选它：存储自动跨 3 个 AZ，只读副本延迟低
它是什么
亚马逊云科技自研的云原生关系数据库，兼容 MySQL 和 PostgreSQL：数据在 3 个 AZ 里存 6 份，最多 15 个只读副本；Aurora Serverless v2 按负载自动伸缩，Global Database 能跨区域。
常见用法
高并发的核心业务数据库
Aurora 的知识点 →
这一环怎么选

Aurora 兼容 MySQL 和 PostgreSQL，性能和高可用更好（存储跨 3 个 AZ）；要 SQL Server、Oracle，或者想省钱，用 RDS

03EC2必须

计算组 · IaaS · 按小时 · 售价 $100
在这里
割接那一刻应用切到云上的 EC2 连新库
为什么用它
要完全掌控操作系统、装特殊软件、跑老应用时用它，机型最全
它是什么
云上的虚拟服务器：自己选 CPU、内存和操作系统，按秒计费，可以用按需、Savings Plans、Spot 等方式买。每台实例在一个 AZ 里，要高可用得在多个 AZ 各放几台，配合 ELB 和 Auto Scaling。
常见用法
跑各种应用、需要完全控制操作系统的场景
