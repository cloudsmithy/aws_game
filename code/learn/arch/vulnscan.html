每一块干什么6 块服务

01ECR必须

容器组 · 托管服务 · 按用量 · 售价 $180
在这里
镜像推进 ECR
为什么用它
镜像就放在部署的地方旁边：和 ECS、EKS 权限打通，推送时顺手扫漏洞
它是什么
托管的容器镜像仓库：存放 Docker / OCI 镜像，可以扫描漏洞，ECS、EKS 直接从这里拉镜像。
常见用法
CI/CD 构建完镜像推上去，部署时拉下来
ECR 的知识点 →

02Inspector必须

安全组 · 托管服务 · 按用量 · 售价 $380
在这里
Inspector 马上扫一遍漏洞；Inspector 的发现发到 EventBridge
为什么用它
自动发现 EC2、容器镜像和 Lambda 里的漏洞，新 CVE 出来不用等人去扫
它是什么
自动漏洞扫描：持续扫描 EC2、ECR 里的容器镜像和 Lambda 函数，找出软件漏洞和不该暴露的网络端口，按风险打分。
常见用法
补丁管理、合规检查
Inspector 的知识点 →

03ECS必须几选一

容器组 · 容器 · 按小时 · 售价 $180
在这里
没有高危漏洞的镜像才部署到 ECS、EKS 或 EC2
为什么用它
想跑容器又不想学 Kubernetes 时选它，配 Fargate 连机器都不用管
它是什么
亚马逊云科技自己的容器编排服务：告诉它要跑几个任务，它负责调度、替换坏掉的；底层可以用 EC2，也可以用 Fargate（不用管服务器）。
常见用法
微服务、批处理任务
ECS 的知识点 →

03EKS必须几选一

容器组 · 容器 · 按小时 · 售价 $200
在这里
没有高危漏洞的镜像才部署到 ECS、EKS 或 EC2
为什么用它
团队已经在用 Kubernetes，要沿用 Helm 和社区工具时选它
它是什么
托管的 Kubernetes：控制平面由亚马逊云科技在多个 AZ 里运行，每个集群按小时收费；工作节点可以用 EC2、托管节点组、Fargate 或 Auto Mode。
常见用法
已经在用 Kubernetes 的团队上云、多环境统一部署
EKS 的知识点 →

03EC2必须几选一

计算组 · IaaS · 按小时 · 售价 $100
在这里
没有高危漏洞的镜像才部署到 ECS、EKS 或 EC2
为什么用它
要完全掌控操作系统、装特殊软件、跑老应用时用它，机型最全
它是什么
云上的虚拟服务器：自己选 CPU、内存和操作系统，按秒计费，可以用按需、Savings Plans、Spot 等方式买。每台实例在一个 AZ 里，要高可用得在多个 AZ 各放几台，配合 ELB 和 Auto Scaling。
常见用法
跑各种应用、需要完全控制操作系统的场景
EC2 的知识点 →
这一环怎么选

要完全掌控操作系统用 EC2；容器化了想省心用 ECS；团队熟 Kubernetes 选 EKS

04EventBridge可选

应用集成组 · Serverless · 按用量 · 售价 $240
在这里
Inspector 的发现发到 EventBridge
为什么用它
发事件的和处理事件的互不认识：多加一个处理方不用改发送方，还能按时间表触发
它是什么
Serverless 事件总线：把亚马逊云科技服务、自己的应用和 SaaS 发出的事件按规则转给 Lambda、Step Functions 等，也能定时触发。
常见用法
事件驱动架构、跨账户分发事件、定时任务
