每一块干什么6 块服务

01ELB必须

网络组 · 托管服务 · 按小时 · 售价 $140
在这里
ELB 把请求分到多台机器
为什么用它
多台后端前面放一个统一入口：自动分流量、绕开坏掉的实例，天生跨 AZ
它是什么
负载均衡：把流量分给后面多台 EC2、容器或 Lambda，自动绕开不健康的；ALB 处理 HTTP/HTTPS，NLB 处理 TCP/UDP。
常见用法
网站和 API 的统一入口、多 AZ 高可用
ELB 的知识点 →

02EC2必须几选一

计算组 · IaaS · 按小时 · 售价 $100
在这里
EC2、ECS 或 EKS 上的应用都挂同一个 EFS 文件系统
为什么用它
要完全掌控操作系统、装特殊软件、跑老应用时用它，机型最全
它是什么
云上的虚拟服务器：自己选 CPU、内存和操作系统，按秒计费，可以用按需、Savings Plans、Spot 等方式买。每台实例在一个 AZ 里，要高可用得在多个 AZ 各放几台，配合 ELB 和 Auto Scaling。
常见用法
跑各种应用、需要完全控制操作系统的场景
EC2 的知识点 →

02ECS必须几选一

容器组 · 容器 · 按小时 · 售价 $180
在这里
EC2、ECS 或 EKS 上的应用都挂同一个 EFS 文件系统
为什么用它
想跑容器又不想学 Kubernetes 时选它，配 Fargate 连机器都不用管
它是什么
亚马逊云科技自己的容器编排服务：告诉它要跑几个任务，它负责调度、替换坏掉的；底层可以用 EC2，也可以用 Fargate（不用管服务器）。
常见用法
微服务、批处理任务
ECS 的知识点 →

02EKS必须几选一

容器组 · 容器 · 按小时 · 售价 $200
在这里
EC2、ECS 或 EKS 上的应用都挂同一个 EFS 文件系统
为什么用它
团队已经在用 Kubernetes，要沿用 Helm 和社区工具时选它
它是什么
托管的 Kubernetes：控制平面由亚马逊云科技在多个 AZ 里运行，每个集群按小时收费；工作节点可以用 EC2、托管节点组、Fargate 或 Auto Mode。
常见用法
已经在用 Kubernetes 的团队上云、多环境统一部署
EKS 的知识点 →
这一环怎么选

要完全掌控操作系统用 EC2；容器化了想省心用 ECS；团队熟 Kubernetes 选 EKS

03EFS必须

存储组 · Serverless · 按用量 · 售价 $100
在这里
EC2、ECS 或 EKS 上的应用都挂同一个 EFS 文件系统
为什么用它
多台机器要读写同一批文件时，不用自己搭 NFS 服务器，容量随用随长
它是什么
托管的共享文件系统（NFS）：多台 EC2、容器、Lambda 能同时挂载同一个目录，容量随写随涨，按用了多少收费。
常见用法
多台服务器共用的文件、内容管理、机器学习训练数据
EFS 的知识点 →

04VPC可选

网络组 · 托管服务 · 免费 · 售价 $140
在这里
VPC 每个 AZ 的子网里都有 EFS 挂载点
为什么用它
把资源放进自己的私有网络，子网和安全组决定谁能访问，数据库不用暴露在公网上
它是什么
你在云上的私有网络：自己划网段、子网、路由表和安全组，决定哪些资源能访问公网。VPC 本身不收费。
常见用法
把对外的负载均衡放公有子网，应用和数据库放私有子网
