每一块干什么5 块服务

01Aurora必须几选一

数据库组 · PaaS · 按小时 · 售价 $280
在这里
Aurora、RDS for MySQL 或 DynamoDB 里的业务数据
为什么用它
要更高性能和可用性的 MySQL、PostgreSQL 时选它：存储自动跨 3 个 AZ，只读副本延迟低
它是什么
亚马逊云科技自研的云原生关系数据库，兼容 MySQL 和 PostgreSQL：数据在 3 个 AZ 里存 6 份，最多 15 个只读副本；Aurora Serverless v2 按负载自动伸缩，Global Database 能跨区域。
常见用法
高并发的核心业务数据库

01RDS必须几选一

数据库组 · PaaS · 按小时 · 售价 $280
在这里
Aurora、RDS for MySQL 或 DynamoDB 里的业务数据
为什么用它
要关系库又不想自己运维时用它：备份、补丁、多 AZ 故障切换都托管，引擎选择最多
它是什么
托管的关系数据库：支持 MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Db2，帮你做备份、打补丁和故障切换。多 AZ 部署会在另一个 AZ 放一台备用实例。
常见用法
传统业务系统、电商订单库
RDS 的知识点 →

01DynamoDB必须几选一

数据库组 · Serverless · 按用量 · 售价 $240
在这里
Aurora、RDS for MySQL 或 DynamoDB 里的业务数据
为什么用它
访问方式固定、并发特别高时用它：没有数据库服务器要管，读写延迟稳定在毫秒级
它是什么
Serverless 的键值和文档数据库：毫秒级读写，按需模式按请求收费，数据自动存在多个 AZ；全局表可以多区域同时读写。
常见用法
用户会话、购物车、游戏数据、高并发场景
DynamoDB 的知识点 →
这一环怎么选

按键读写、超高并发选 DynamoDB；要 SQL 和事务选 Aurora（性能、高可用更好）或 RDS（引擎更多、更便宜）

02Redshift必须

分析组 · PaaS · 按小时 · 售价 $340
在这里
Redshift 里直接跑报表
为什么用它
数据量大、报表和复杂 SQL 多时用它：列式存储加大规模并行，几十亿行也查得动
它是什么
云数据仓库：列式存储、大规模并行处理，用 SQL 分析海量数据；有预置集群和 Redshift Serverless 两种用法。
常见用法
BI 报表、经营分析
