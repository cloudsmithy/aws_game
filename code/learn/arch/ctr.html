每一块干什么4 块服务

01ECR必须

容器组 · 托管服务 · 按用量 · 售价 $180
在这里
镜像放 ECR
为什么用它
镜像就放在部署的地方旁边：和 ECS、EKS 权限打通，推送时顺手扫漏洞
它是什么
托管的容器镜像仓库：存放 Docker / OCI 镜像，可以扫描漏洞，ECS、EKS 直接从这里拉镜像。
常见用法
CI/CD 构建完镜像推上去，部署时拉下来
ECR 的知识点 →

02ECS必须几选一

容器组 · 容器 · 按小时 · 售价 $180
在这里
ECS 或 EKS 拉镜像跑起来
为什么用它
想跑容器又不想学 Kubernetes 时选它，配 Fargate 连机器都不用管
它是什么
亚马逊云科技自己的容器编排服务：告诉它要跑几个任务，它负责调度、替换坏掉的；底层可以用 EC2，也可以用 Fargate（不用管服务器）。
常见用法
微服务、批处理任务
ECS 的知识点 →

02EKS必须几选一

容器组 · 容器 · 按小时 · 售价 $200
在这里
ECS 或 EKS 拉镜像跑起来
为什么用它
团队已经在用 Kubernetes，要沿用 Helm 和社区工具时选它
它是什么
托管的 Kubernetes：控制平面由亚马逊云科技在多个 AZ 里运行，每个集群按小时收费；工作节点可以用 EC2、托管节点组、Fargate 或 Auto Mode。
常见用法
已经在用 Kubernetes 的团队上云、多环境统一部署
EKS 的知识点 →
这一环怎么选

ECS 是亚马逊云科技自家的编排，简单好上手；团队熟 Kubernetes、要和别的环境保持一致，选 EKS

03ELB必须

网络组 · 托管服务 · 按小时 · 售价 $140
在这里
ELB 把外面的请求分给这些容器
为什么用它
多台后端前面放一个统一入口：自动分流量、绕开坏掉的实例，天生跨 AZ
它是什么
负载均衡：把流量分给后面多台 EC2、容器或 Lambda，自动绕开不健康的；ALB 处理 HTTP/HTTPS，NLB 处理 TCP/UDP。
常见用法
网站和 API 的统一入口、多 AZ 高可用
