服务知识点/安全组/WAF

SERVICE安全组 · 托管服务

WAF

安全组托管服务按用量自带跨 AZ 高可用

Web 应用防火墙：挂在 CloudFront、ALB、API Gateway 前面，按规则拦 SQL 注入、跨站脚本和恶意机器人，还能按 IP 限速。

常见用法

防常见 Web 攻击、防刷接口

为什么用它

在入口按规则拦 SQL 注入、XSS、恶意爬虫和刷接口，不用改应用代码

核心知识点5 条

  1. Web 应用防火墙：挂在 CloudFront、ALB、API Gateway、AppSync、Cognito 用户池等前面
  2. Web ACL 里配规则：IP 名单、地理位置、限速（基于速率）、托管规则组（常见漏洞、已知坏输入、SQL 注入等）
  3. Bot Control 识别和管理爬虫；欺诈控制防撞库、防恶意注册
  4. 按 Web ACL、规则数和请求数计费
  5. 新规则可以先用计数（Count）模式观察，确认不误伤再改成阻止

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

托管规则

一键启用常见攻击防护规则，满足合规要求

游戏里：免疫「安全审计没过」

LV.2 · 第 2 级

限速规则

单个 IP 请求太多就拦截

游戏里：免疫「接口被恶意刷爆」（安全攻防 DLC）

LV.3 · 第 3 级

Bot Control

识别爬虫、扫描器、状态监控、搜索引擎这类机器人流量，可以只计数观察、限速或拦截；用目标检查级别还能质询不报身份的机器人

1.WAF 可以挂在哪些服务前面？
答案CloudFront、ALB、API Gateway
WAF 管第 7 层；API Gateway 只能挂 REST API，另外还能挂 AppSync、Cognito 用户池等
2.WAF 的托管规则组是什么？
答案亚马逊云科技或合作伙伴维护的现成规则
比如常见漏洞防护、已知恶意 IP 列表
3.一个面向公众的网站部署在 Application Load Balancer 之后。最近发现个别 IP 地址在短时间内发送大量 HTTP 请求刷接口。如何以最少的运维工作量自动限制这些 IP？SAA-C03
答案为 ALB 关联 WAF Web ACL，并添加基于速率的规则
WAF 基于速率的规则按 IP 等维度统计请求，超过阈值时自动限流，无需人工维护名单。安全组只支持允许规则；NLB 工作在第 4 层，识别不了 HTTP 层的滥用；人工分析流日志再改网络 ACL 反应慢且运维开销大。　官方文档 ↗
