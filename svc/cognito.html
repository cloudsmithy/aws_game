服务知识点/安全组/Cognito

SERVICE安全组 · 托管服务

Cognito

安全组托管服务按用量自带跨 AZ 高可用

给你的 App 和网站管用户登录：用户池存账号，负责注册、登录、MFA，登录后发 JWT 令牌；身份池把登录的用户换成临时的亚马逊云科技凭证，App 可以直接访问 S3 这类服务。按月活跃用户（MAU）计费。

常见用法

App 和网站的注册登录、给 API 加登录校验（API Gateway、ALB 都能直接认 Cognito 的令牌）、手机 App 直传文件到 S3

为什么用它

登录这件事不用自己写：密码存储、MFA、找回密码、社交登录都是现成的，还能直接给 API Gateway 和 ALB 做鉴权

核心知识点5 条

  1. 用户池：用户目录加登录，注册、密码、MFA、社交登录、企业 SAML 和 OIDC 登录都现成，登录后签发 JWT 令牌
  2. 身份池：把登录身份换成一份临时的 IAM 凭证，App 直接调 S3、DynamoDB 这类服务
  3. API Gateway 能用 Cognito 授权方验令牌；ALB 的监听器规则能直接接 Cognito 做登录
  4. 托管登录页（Managed Login）给现成的登录界面，能换品牌样式
  5. 按月活跃用户（MAU）计费

三个关键功能游戏里的三级升级，就是现实里的这三个功能

LV.1 · 第 1 级

MFA 多因素认证

登录时除了密码再验一次（短信、邮件验证码或身份验证器应用），密码泄露了也登不进去

游戏里：免疫「用户账号被撞库」（光有密码登不进去）；免疫「安全审计没过」

LV.2 · 第 2 级

社交与企业登录

接入 Google、Apple 这类社交账号和公司的 SAML、OIDC 身份提供商，用户不用再记一套密码，来登录的人更多

游戏里：这块过路费再 +20%

LV.3 · 第 3 级

身份池（联合身份）

把用户池或社交账号登录后的身份换成临时的亚马逊云科技凭证，权限按角色限定，App 直接调用 S3、DynamoDB 这些服务，不用自己的服务器转一道

游戏里：运行费或请求费减半

1.Cognito 用户池和身份池的区别是？
答案用户池管注册登录、发令牌；身份池把登录的用户换成临时的亚马逊云科技凭证
用户池是用户目录，负责注册、登录、MFA，登录后签发 JWT；身份池把用户池或社交账号登录后的身份换成临时凭证，用来直接访问 S3 这类服务
2.想让 API Gateway 只放行登录过的用户，最省事的做法是？
答案给 API 配 Cognito 用户池授权方，请求带上登录拿到的令牌
API Gateway 的 Cognito 授权方（HTTP API 用 JWT 授权方）先验令牌，没登录或令牌过期的请求在网关就被挡回去，Lambda 里不用写验证逻辑
3.有人拿别处泄露的密码来你的 App 撞库，Cognito 里哪个功能最对口？
答案威胁防护：发现在用泄露的密码、异常登录，按风险拦下或要求补一次 MFA
威胁防护（以前叫高级安全功能，在 Plus 功能套餐里）会检查泄露的凭证，异常登录按风险等级自动拦截或要求再验一次
